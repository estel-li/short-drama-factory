# 首帧功能

## 创作决策

字段 `use_previous_last_frame` 是严格 JSON 布尔值，默认 `false`。`first_frame_reason` 是 AI 的启用理由，默认空字符串。四种内置分镜 Skill 与自建分镜 Skill 都收到程序的统一首帧契约。

同一场景、同一连续段，且下一镜头需要从上一镜头结束状态继续时可以启用。人物相同或风格一致不足以启用；第一镜、时间跳跃、换场、蒙太奇、正反打和需要全新起始构图的镜头应关闭。

场景优先比较稳定 `scene_id`，其次比较非空 `scene`，缺失名称时可比较非空 `continuity_group`。两镜均有连续组且组不同，视为不连续。AI 每批最多生成六镜，下一批通过 `previous_shots` 参考上一批末镜。

## 渲染依赖

启用镜头以当前列表的紧邻前镜为源，不按曾经的镜头编号查找。前镜视频必须完成，属于当前项目且能完整解码。程序从头解码至 EOF，保存最后一个显示帧为原尺寸 PNG，记录源视频 SHA256、源镜头身份、帧序号、PTS 和图片 SHA256。

保存位置为项目 `assets/first_frame_*.png`；来源索引为 `assets/first_frames.json`，渲染状态中的 `first_frame` 同时记录来源。提取图会显示在分镜表。

新镜头强制 I2VA，只有自动首帧参与生成；手工模式与素材绑定保留，关闭后恢复使用。文字阶段无需真实首帧存在：使用明确的待生成来源描述，生成时再解析实际视频。提示词使用官方 0 秒对齐行；原本的 Ref2VA 图片编号与多段格式不会误用到 I2VA。

## 编辑、恢复与锁定

- 修改首帧开关、剧情或前镜动作后，相关提示词和生成缓存按实际输入更新。
- 前镜视频改变或前镜身份改变时，依赖镜头缓存失效；连续依赖会顺序更新。
- 恢复原任务时，已完成的前镜视频可复用；校验完整的末帧 PNG 可复用；不会为无变化的首帧再请求文字模型。
- 迁移包保存项目内首帧 PNG、分镜、状态和素材来源。若不携带视频，需先重新生成前镜，再提取首帧。
- 锁定的依赖镜头遇到上游改动会报错要求解锁。未启用本功能的镜头保留原锁定行为。
- 删除或排序后若启用镜头成为第一镜、或跨场景接续，保存与渲染校验都会拒绝，不会悄悄降级为文生。

## 最小示例

```json
{
  "title": "拿起茶杯",
  "characters": [],
  "shots": [
    {
      "scene": "书房",
      "continuity_group": "study_continuous",
      "summary": "手指刚触碰杯柄",
      "duration": 4,
      "use_previous_last_frame": false
    },
    {
      "scene": "书房",
      "continuity_group": "study_continuous",
      "summary": "从触碰杯柄的状态接着提起杯子",
      "duration": 4,
      "use_previous_last_frame": true,
      "first_frame_reason": "相同机位与连续动作，需要保留末态"
    }
  ]
}
```

使用“已有分镜 JSON”导入后执行提示词和视频阶段。首帧约束用于改善视觉接续，并不承诺语音、表演或所有物体状态完全一致；最终仍需播放检查。
