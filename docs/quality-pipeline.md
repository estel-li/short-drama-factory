# 出片质量流程（2.4）

## 从生成到验收

流程是：对白预算与角色预检 → 试生成一个待生成镜头 → 生成原镜头 → CPU 人声检测 → 同步剪辑音画 → 对齐字幕与注释 → 生成审核图 → 保存版本。

H3 的采样、参考素材与实际末帧接续继续由原有 ComfyUI 流程执行。后期不调用文字 API 或 GPU，不改变原镜头；旧成片和配方保留。

## 对白驱动的镜长

默认预算：`0.40 秒起手 + 台词字数 / 5.6 + 0.30 秒句间 + 0.55 秒收尾`。新分镜可连续安排至多三句、两位说话人的短对白；生成时长夹在 4～8 秒，开放长镜头后上限为 15 秒。

“按对白预算拟合”会调整新分镜时长。手动指定镜长优先；“保持时长分配”仍检查对白是否能说完。该预算针对中文字符，标点与空白不计数，其他语言或数字口语可调整目标语速。H3 的 `17k+5` 帧对齐仍会使实际视频略长。

完整剧本可使用明确的台词格式：

```text
[小王] 我已经看过这张告示了。
[小林] 那我们再确认一下。
[小王] 好，先别着急。
```

在完整剧本输入、按总时长分配、对白拟合模式下，程序按这些原句装镜，分批生成机位、调度与动作，并逐句核对说话人、字词和顺序。目标总时长是规划目标，台词完整性所需的长度可覆盖它。单句太长时会要求按语义拆句，程序不会偷偷删词。普通散文剧本交给文字模型理解，不能提供同等的逐句原稿保证。

## 人物、素材与台词的一致性

- 人物外观描述接近时显示预警，建议同时区分脸型/年龄、主色和配饰，而不只依赖发长。
- 身份图片需要关联真实角色。未出场角色的身份参考会阻止提示词编译；场景和道具参考可不关联角色。
- 新生成的每句台词使用一个 `<d>[语言] 原句</d>`，与 `dialogue` 的字词、顺序和数量严格一致。
- 改人物设定只清理相关镜头的旧提示词；不相关镜头继续使用缓存。修改台词需要更新提示词并重生成，使用上一实际末帧的接续镜头也必须更新。
- 后期入口检查当前剧本与原片生成记录；不能用改字幕来代替重配音。旧版引号对白仅在生成记录匹配且原句完全一致时兼容后期。

在单镜编辑器验看完成镜头后，可以“保存为已验收样板”。样板绑定实际 H3 模式、出场人物以及 Ref2VA 的图片/音视频摘要。选用样板时必须匹配这些条件，不能借用另一个三图基准；新对白仍按当前分镜编写。旧版缺少模式记录的镜头不能直接保存新样板。

## 人声与 RMS 的职责

Silero VAD 6.2.1 使用 CPU、16kHz 单声道与独立的每镜状态。约 2.3MB 模型首次需要时从固定官方提交下载，核对大小和 SHA256；不使用 ComfyUI 显存。

RMS 采用相对底噪阈值，保留较严与放松阈值两套能量活动区间。环境声铺满全片时，能量活动不等于人声。自动剪辑依赖 VAD 的较宽保护区间，不直接用 RMS 切人声。

报告的“人声占比”和“字 / 检测人声秒”是检测估计。VAD 不是 ASR，不能证明模型每个字都说对，也不能代替试听。检测不到人声、没有对白或勾选“保留本镜全部表演与留白”时，不自动压缩该镜头。

## 三档剪辑

| 预设 | 起手 | 收尾 | 句间停顿 | 最多移除原镜长 |
| --- | ---: | ---: | ---: | ---: |
| 原始 | 保留 | 保留 | 保留 | 0% |
| 保守 | 0.40s | 0.55s | 0.35s | 35% |
| 紧凑 | 0.25s | 0.40s | 0.22s | 55% |

裁剪以 24fps 帧边界同步处理视频和音频，切口做短音频淡入淡出。I2VA 接续需要的实际首帧、前镜末帧会保留。压缩计划验证覆盖检测到的人声保护区间；跳切是否自然仍需查看对照图和播放。

## 字幕、注释和遮罩

字幕先定位检测到的人声，再按台词字数分配句内时长；报告会区分 `vad_weighted`、`manual` 和近似对齐。精确时间可在分镜 JSON 标注，与 `dialogue` 数量一致：

```json
"dialogue_timings": [{"start": 2.93, "end": 4.08}]
```

这是原镜头时间轴，后期自动映射到剪辑后的时间轴。标注不会触发 H3 重渲。

成片注释使用最终成片时间，例如：

```json
[{"start": 0.5, "end": 1.8, "text": "说明：请核对这项信息。"}]
```

ASS 的 PlayRes 等于实际输出像素，注释使用居中定位、半透明底板和更高层级。程序按对白一行/多行在时间边界调整注释位置。注释不能重叠或超过本版本长度；更换剪辑强度后应核对时间。

文字遮罩按源镜头标定，多边形坐标基于规范化后的未剪镜头、取值 0～1。各机位分别设置 `shot_uid`，关键帧的顶点数量保持一致；`protect` 是独立的前景保护轨迹：

```json
[{
  "shot_uid": "s1",
  "start": 0, "end": 4,
  "color": "#EAE5DC",
  "keyframes": [{"time": 0, "points": [[0.6,0.2],[0.9,0.2],[0.9,0.5],[0.6,0.5]]}],
  "protect": []
}]
```

程序逐帧插值生成灰度视频并 alphamerge，不对整镜取遮罩交集。前景保护来自标注轨迹，**不是自动人像分割**；人物移动、镜头运动和画幅缩放后都需要用审核图确认残字与误遮挡。遮罩和注释放在 CPU 后期，源片保持完整。

## 审核、版本与重建

每版保存镜头起中末总览、切口前后对照、默认 0.75s 带时间标记的审核帧。审核图帮助读取硬字幕与发现短句遗漏，**不是 OCR 自动誊录**。短句可能仍需 0.25s 更密采样或逐帧播放。

`source_cache/` 按内容摘要保存原片快照；`edits/<版本>/` 保存冻结剧本、检测结果、裁剪区间、字幕、配方、审核图与成片。根目录成片只在完整验收后更新。烧字幕明确读取本次候选文件，不读取上一版根目录成片。

工作台可播放各版本并从冻结原片重建，也可使用：

```powershell
.\.venv\Scripts\python.exe tools/rebuild_edit.py --project "项目绝对路径" --recipe "edits/版本号/recipe.json"
```

重建不调用文字 API、不使用 GPU。原片或配方被改动会失败；编码器版本改变可能改变二进制码流，程序仍校验帧数、音频、画幅和时间戳。

## 验证边界

本项目使用已有 H3 样片与受控音视频验证字幕提前、音画同步、源片不变、模板隔离、动态遮罩、旧文件混用和冻结版本重建；验证不代表对所有题材、音效和语种的质量保证。相应回归检查见 `tests/test_finishing.py`、`tests/test_masking.py` 与 `tests/test_quality_contracts.py`。
