# 2.2 首帧功能验证

验证环境：Windows、RTX 5060 Ti 16GB、配置中的 DeepSeek Flash、H3 W4A8、0.4MP / 4 步。以下为发布前实际执行结果，未随仓库提交私人配置或生成视频。

## 自动化检查

37 项离线单元/集成测试通过，并在独立整理的发布源码目录再次通过。覆盖原有配置、素材、项目编辑、重试、分集、迁移和缓存，以及新增首帧功能。

首帧专项检查包括：严格布尔值与默认关闭、第一镜与换场拒绝、跨批次衔接、锁定保留、B 帧视频末帧准确提取、损坏图片修复、提示词先规划后渲染、恢复不重新调用 LLM、旧提示词输入兼容、相邻顺序、上游视频变更失效和远程上传。

## 真实生成

用自编两镜短剧“同一杯热茶”验证完整链路：

1. 真实文字模型判断第一镜关闭、第二镜开启首帧功能，并输出连续动作的理由。
2. 本机 ComfyUI 顺序生成第一镜；自动提取其第 106 号帧（从 0 计数），保存 480×832 原尺寸 PNG。
3. PNG 与第一镜完整解码得到的实际末帧逐像素相等。
4. 第二镜实际图使用 `MiniMaxH3ImageToVideo` 的 `first_frame` 输入，未绑定尾帧。
5. 两镜各 107 帧，成片 214 帧、约 8.9167 秒，有音频且时间戳递增。
6. 再次通过同一任务编排续跑，没有调用文字模型，也没有向 ComfyUI 新提交生成任务，复用原视频。

## 浏览器

工作台健康接口报告 2.2.0、ComfyUI 连接正常。分镜表中第一镜开关关闭且禁用，第二镜选中、显示 I2VA 和 AI 理由，并显示实际末帧预览。关闭第二镜开关后原模式控件可编辑，重新开启后由自动首帧接管。控制台未出现错误。

这些检查证明数据流、绑定、缓存和界面按契约工作；最终动作与画面质量仍取决于模型输出，需播放审看。
