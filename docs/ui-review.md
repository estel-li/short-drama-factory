# 2.3 代码审查与 UI 验证

## 审查范围

围绕创建故事 → 分镜编辑 → 保存与继续 → 视频播放，以及模型配置、Skill、分集、迁移和任务记录检查前端与 API。生成模型、ComfyUI 采样图和原有首帧算法保持原实现。

## 已修复的问题

| 问题 | 用户影响 | 修复 |
| --- | --- | --- |
| 草稿共用一个 dirty 标记 | 保存设置可能丢掉分镜编辑 | 独立草稿与各自编辑版本，逐分区保存 |
| 轮询替换相同编辑对象 | 输入事件写到旧对象，内容未进入待保存数据 | 无变化时保留引用，运行状态单独刷新 |
| 异步保存清空后续输入 | 保存中的新修改被旧响应覆盖 | 比较编辑版本，保留并提示继续保存 |
| 普通按钮没有 type | 预设等操作可能误提交创建表单 | 默认 button，仅创建入口使用 submit |
| 超宽分镜表与长项目列表 | 窄屏难读，项目堆叠把编辑区推到屏外 | 单镜编辑、可滚动项目库、分区工作台 |
| 排队与错误状态依赖旧项目状态 | 刚排队的任务仍可重复操作 | 后端返回权威 busy，中文任务状态与操作保护 |
| 大纲/设置修改后保留 complete | 过期成片仍显示已完成 | 归档旧产物，更新阶段与待生成状态 |
| 无关时长字段参与校验 | 固定数量或手动时长被隐藏字段阻塞 | 只校验当前分配规则的目标参数 |
| 启动后的异步导航覆盖用户选择 | 用户刚选项目又跳回配置页 | 保留用户已经作出的导航选择 |
| 配置保存重建所有表单 | 其他提供商、环境草稿丢失 | 独立配置草稿，保存后恢复未提交内容 |
| Skill 保存后选项未刷新 | 新规则无法直接用于新故事 | 刷新阶段选项，同时保留故事与设置 |
| 原始 JSON 应用缺少完整校验 | 不合法数据可能破坏编辑器 | 只读服务端校验，失败保留原文 |
| 配置刷新覆写未生成项目标题 | 项目库出现难辨认的目录编号 | 根据剧集计划或原输入恢复可读名称 |
| 错误提示过快消失或包含内部细节 | 难以定位问题，可能回显私有输入 | 错误保留至关闭；结构错误中文化且不回显输入 |

## 验证方法

离线测试覆盖已有生成、编辑、缓存、首帧、分集、安装及迁移，并增加 UI/API 契约与原生 JavaScript 回归测试。43 项后端测试、9 项前端测试全部通过。CI 使用 Windows、Python 3.13 和 Node.js 22。

浏览器实测覆盖：

- 分镜与设置跨分区编辑、保存并从 API 读取确认。
- 项目切换时取消保留草稿，以及明确放弃后切换。
- 错误 JSON 保留、修正后校验与应用。
- 手动时长的草稿创建，不调用模型。
- 手动两集草稿、选择数量与空选择禁止批量提交。
- 复制 Skill、保存，并立即在阶段设置中找到新规则。
- 保存一个提供商时保留另一提供商与环境的未保存输入。
- 桌面和 390px 窄屏布局、键盘焦点、首帧状态与成片媒体加载。

媒体播放验证复用此前真实 H3 生成的两镜样片。此次 UI 验证没有额外调用文字 API 或重新消耗 GPU 生成该样片。演示数据、测试连接和私人配置不随源码发布。

## 保留的范围

字幕仍为对白字数近似对齐；模型对人物与动作的表现需要播放审看。从零安装仍面向 Windows x64 + NVIDIA。Node.js 仅用于开发测试，工作台没有新增前端运行依赖。
