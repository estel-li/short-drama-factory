# H3 专用高级工作流 · 3.3.0

本轮在 3.2.0 基础上增加五类媒体工作流。开发分支 `estel/h3-advanced-3-3`；3.2.0 已先提交并推送为 `bae81cf`。五类均完成 RTX 5060 Ti 16GB 实机生成、完整解码和画面检查；本机运行实例已更新至 3.3.0。

| 方案 | 提供什么 | 生成什么 | 独立参数 |
| --- | --- | --- | --- |
| 音频驱动数字人 | 驱动原声，可加人物首帧 | 由真实音轨条件驱动的画面，保留输入声音 | 步数、尺寸、音频起点 |
| 锁画面拟音 | 工作流源视频 | 保留源画面，重新生成描述的声音 | 步数、尺寸、源片起点 |
| 中段关键帧导演 | 中段引导图，可加首帧／尾帧 | 在中间时间点受图像引导的视频 | 步数、尺寸、引导位置 |
| 多帧音画接续 | 工作流源视频 | 延续末尾动作和音景的新片段 | 步数、尺寸、画面／声音上下文长度 |
| 视频轮廓控制 | 工作流源视频 | 跟随源片结构与动作的新风格视频 | 步数、尺寸、Canny 阈值、强度及采样区间 |

在项目设置的“视频工作流 / 质量”选择，再点“准备所选工作流”。在单镜素材区绑定对应的“工作流源视频”“驱动原声”或“中段引导图”。缺失资源先显示清单和下载确认，进度支持暂停续传。五类默认原生 12 步、0.4MP，不叠加旧 Turbo；可自定义后另存方案。

源音轨不足目标时长时尾部补静音；源视频帧数不足时报错。视频按项目画幅居中缩放，上传时统一为 24fps。精确口型、多人复杂镜头和长链音质需要逐片检查。

4 秒请求按 H3 规则对齐为 107 帧，实际约 4.46 秒；拟音和轮廓源片也需要覆盖这段时长。多帧接续使用 T2VA 或 Ref2VA，不叠加独立首尾帧，以免覆盖接续开场或在裁切中丢失尾帧目标。

## 技术与来源

- [ComfyUI 原生 H3 节点](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_minimax_h3.py)：关键帧引导、音画潜空间和 Fun ControlNet 应用。
- [MiniMax 官方社区索引](https://github.com/MiniMax-AI/awesome-minimax-h3-integration)：核对高级方向、架构与模型配对。
- [H3 Motion Context](https://github.com/NikoDemon80/ComfyUI-H3-Motion-Context)：接续调研时 1276 stars，固定 `518c083`；独立下载并保留 GPL-3.0 源码和许可，不修改原 ComfyUI。
- [H3 Fun Control](https://github.com/wyzborrero/ComfyUI-H3-FunControl)：参考控制分支、稀疏补丁顺序与曲线 AdaLN 的实测资料；实际使用原生节点。
- [Kijai 转换权重](https://huggingface.co/Kijai/MiniMax-H3-experimental)：固定 pruned INT8 ConvRot 控制权重，约 2.14GiB，匹配已有 pruned H3 主干。原始全宽 AdaLN 权重不能替代。
- [H3 Guide](https://github.com/ethanfel/ComfyUI-MiniMax-H3-Guide)、[Audio T8](https://github.com/T8mars/comfyui-minimax-h3-audio-T8)、[LanPaint](https://github.com/scraed/LanPaint) 和本机数字人工作流用于调研媒体锁定、音频用途及局部修复；未将整个大型插件集合装入稳定环境。

音频驱动将编码原声放入主 AV 潜空间并锁住音频蒙版；拟音采用相反锁定方式。分阶段缓存保存并恢复蒙版，不能换回空潜空间。拟音直接使用源帧，驱动成片直接使用原声，避免保留内容发生不必要的 VAE 往返。

接续额外生成上下文、移除重复头部并按目标帧数裁切音画。中段关键帧是时间点图像条件；轮廓控制是模型补丁，不是普通视频参考或仅换提示词。

固定 revision、大小与 SHA256 见 `manifests/video-workflows.json`。操作接口见 [AI 高级工作流说明](../agent-skills/short-drama-factory/references/h3-advanced.md)。

## 实机记录（2026-10-20）

硬件为 Thunderbolt 4 显卡坞连接的 RTX 5060 Ti 16GB、32GB 内存；使用现有 W4A8 主干、NVFP4 文本编码器和 ComfyUI 0.36.0。五类默认 0.4MP、原生 12 步；下面是节点执行时间，不含首次校验、进程启动、排队与应用后期。

| 工作流 | 编码 / 采样 / 解码 | 核对结果 |
| --- | --- | --- |
| 音频驱动数字人 | 26.244 / 97.725 / 23.100 秒 | 原声潜空间锁定，画面生成与合片成功 |
| 锁画面拟音 | 29.686 / 91.577 / 3.539 秒 | 画面潜空间锁定，采用源帧合片，声音重新生成 |
| 中段关键帧导演 | 10.125 / 104.080 / 23.051 秒 | 首帧开始、片中到达打开红书的引导构图 |
| 多帧音画接续 | 16.437 / 164.669 / 30.836 秒 | 接上源片末尾状态，去掉重复上下文后仍交付 107 帧 |
| 视频轮廓控制 | 23.514 / 140.270 / 23.458 秒 | 实际工作台将书店人物转换为二维动漫，并跟随开书动作；确认图中使用 Fun ControlNet 补丁 |

前四类在隔离验证引擎通过完整应用 Runner 生成。轮廓控制还通过实际工作台 API；原声驱动与拟音也通过实际 API 再次验收。原声额外使用单声道、22050Hz 输入，验证双声道转换及音频 VAE 采样率适配。全部生成采用手写分镜，没有调用付费文字 API。

音频驱动采样前后音频潜空间最大差异约 `1.19e-7`；拟音的视频潜空间最大差异约 `4.77e-7`，均在浮点误差内，锁定蒙版正确恢复。拟音源帧与重编码成片的 RGB PSNR 约 42.86dB；这里保留的是源帧内容，输出 H.264 仍有正常编码损失。新声音 PCM 摘要与原音轨不同。

实际工作台的轮廓项目为 `20261020_203540_494672`，原声驱动为 `20261020_203911_674dab`，拟音为 `20261020_204142_2650ca`。精确请求、图、prompt_id、计时、输出摘要、完整解码及抽帧图保存在本机忽略目录 `logs/h3-advanced-33/`；大型模型和测试产物不进入源码仓库。

## 本轮发现并修复的问题

- 外部手写分镜没有 `compiled_mode` 时，旧代码可能忽略显式 Ref2VA 或首帧绑定。现在按有效模式／真实绑定选择图；新增媒体方案在渲染前校验输入。旧 3.2 两份参考意图样片的过强验收表述已在历史记录更正。
- 含 `LoadVideo` 预览的解码图，旧结果读取可能先取到输入 MP4。现在只读取 SaveVideo 节点 16 的产物；缺少真实产物时报错。用已完成的拟音缓存重取真正输出，采样 prompt_id 保持不变，没有重复采样。
- 真正 Ref2VA 回归项目 `20261020_204158_a4a6b1` 已完成，直接核对实际采样图确认为 Ref 主干和 PDD Ref 配对头。

样片覆盖短镜头、单人物、单源素材；不把音轨技术检查当作逐字人工试听，不保证所有提示词的精确口型或长链人物一致性。
