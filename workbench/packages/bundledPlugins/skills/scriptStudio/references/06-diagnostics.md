## 十六、常见问题与处理

### 1. 用户只有 04 分镜，没有资产库

先反推临时素材映射：

```text
临时 @图片1 = 当前场景参考图（待用户提供）
临时 @Image2 = 主角参考图（待用户提供）
```

同时提醒：没有参考图时可用文生视频，但角色一致性下降。

### 2. 用户只有资产库，没有分镜

先建议回到 04 生成分镜，再适配 Seedance。  
如果用户要快速输出，则按剧本直接生成“简化 Seedance prompt”，并标注未经过 04 分镜拆解。

### 3. 用户要一次输出整集

不要把整集塞进一个 prompt。必须拆为多个 Seedance 提示词包，每包 4-15 秒。

### 4. 用户问“为什么 Seedance 画面漂移”

优先检查：

- 是否没有角色定稿图
- 是否没有 `@Image` 绑定
- prompt 是否动作过多
- 是否场景切换过多
- 是否没有 Must Keep
- 是否没有末帧延续
- 是否同一角色使用了不同参考图

## 十八、红线

1. 不把 04 的分镜表原样当作 Seedance prompt；必须适配为官方 `@图片/@视频/@音频` 或兼容 `@Image/@Video/@Audio`、4-15 秒单元、字段化纯净提示词和 Seedance 可读限制。
2. 不凭空写不存在的 `@图片/@视频/@音频` 或 `@Image/@Video/@Audio`。
3. 不输出低于 4 秒或高于 15 秒的单段 prompt。
4. 不交付超过 2000 字的纯净提示词代码框；内部草稿超过 2000 字时必须先删除低收益后缀、管理话术、重复字段和空泛词。1901-2000 不能直接放行，必须先压缩一轮。若 5-7 个完整镜头或高密度 8-10 个短镜头仍超限，按镜头边界拆成连续 4-15 秒单元，并用上一单元段末状态承接下一单元第一帧。
5. 不省略任一镜头的必填信息：焦段、光圈、景深与焦点锁、机位、构图、运镜、主体动作/表情、台词与语气、光影、限制、可见衔接。C 可合并进镜头轨，A 才逐项展开。
6. 不忽略资产库的状态；未定稿必须标风险。
7. 不删除中文台词的语气和角色身份；有对白时不得只写“说话 / 低声说 / 轻声说”，必须单独保留 `台词与语气` 字段。
7.1 不在 06 中擅自改写、压缩或删减台词；06 只做台词可执行性检查。对白无法在建议时长内以自然语速说完时，不得用超过 6 字/秒的过快语速硬塞；必须延长到 15 秒内、按台词节拍拆连续单元，或建议回 03 台词医生精修。
8. 不只写“电影感、高质量、8K”，必须写主体动作和情绪目标。
8.1 不只写“电影级布光 / 高级光影 / 氛围光”，必须写具体光源、亮暗区域、脸部受光、轮廓光、色温和反差。
8.2 不只写“悲伤 / 愤怒 / 害怕 / 心动”，必须写可见微表情、呼吸和身体动作，并写清禁止过度表演。
8.3 不把“大哭 / 怒吼 / 崩溃”当作起始状态；必须写情绪从克制、压不住到爆发的过程。
8.4 不只写“固定 / 手持 / 跟拍 / 退拍 / 复杂运镜”；必须写成摄影机行为锁句，包含位置、距离、高度、运动方向、稳定程度、速度、起止状态和禁止项。
8.5 不默认在纯净提示词正文里写硬时间戳。总时长、画幅、模式和任务类型放代码框外；正文用镜头顺序和软节奏。用户明确要时间戳时，必须标注为“节奏参考，非精确控制”。
8.6 不把短视频平台 10-15 秒段落默认压成 1-2 个镜头。必须继承或补判节奏档位：电影感中速 / 短视频中高密度 / 高密度动作或强钩子 / 慢节奏但高信息；只有命中慢节奏白名单并写清慢镜头功能时，才允许保留 1-2 镜。不得为了压字数删除镜头密度、台词节拍或段末钩子。
9. 不承诺某个接入端的字段完全通用；平台字段必须按实际文档调整。
10. 不让 `@Video` 参考同时承担太多职责。
11. 不省略保持项（Must Keep）/ 禁止项（Avoid）。
12. 不让下一段丢失上一段的末帧状态。
13. 不把表格、JSON、解释说明、参数建议混进“字段化纯净投喂提示词”代码块。
13.1 不把 `【Seedance 段 Sxx】`、段号、时长、画幅、分辨率、模式、任务类型等给用户确认的投喂信息放进纯净提示词代码框，除非用户明确要求“一键复制完整包，包含元信息”。
13.2 不把“未启用 / 不使用 / 不继承 / 无则删除 / 没有则删除 / 不替代 / 普通段不强制”等管理话术写进纯净提示词代码框；未命中的增强字段直接不输出，说明放代码框外。
13.3 不把 `接下一大分镜 / 接下一段 / 承接下一段 / 接分镜2` 写进纯净提示词；衔接必须改写成模型可生成的可见动作、可见转接或段末状态。
14. 不默认输出只有管理信息、没有可复制正文的“提示词包”。
15. 不为了强连续增强而删掉旧版基础结构；`下一段衔接`、`通用后缀`、`段末状态` 必须保留。
16. 不把强连续规则套到所有段落；普通衔接模式不强制调度图和点位表。
17. 独立批量强连续模式不能只写“承接 B01 / 上一段 / 仍然 / 继续 / 同一场景”，必须改写成当前视频第一帧可见状态。
18. 不把首帧功能套到所有段落；只有 A 必须首帧、B 建议首帧或用户明确要求时才处理首帧。C 压入 `参考/连续性声明`，A 详细版可单列 `首帧参考`。
19. 不把 FF 首帧图当成整段视频控制图；FF 只锁定第 0 秒，后续动作、运镜和段末状态必须继续写。
20. 不让 FF 替代 SC/SCV/CH/PR/MAP/SB；首帧图、场景母版、场景角度图、角色图、道具图、调度图必须职责分离。
21. FF 与 SCV/MAP/SB/点位表冲突时，不输出最终 prompt，先回到 05/04 修正资产。
22. 不隐藏 A/B/C 输出模式。用户要求 Seedance prompt 时，必须先推荐 A 标准字段化详细版、B 导演执行增强版或 C 导演轨纯净版；用户不指定时默认按 C 继续，除非命中 A/B 条件，并在代码框外简短说明本段命中的视频延长、FF、MAP/SB、SCV、CR、PR 或复杂运镜增强。
23. 不在最终字段化纯净投喂提示词里只写 `ST001 / CL001 / NP001 / 继承 ST / 继承 CL / 继承 NP`；必须展开成 Seedance 可理解的项目风格、光影、画面质感和风格禁止项。
24. 不让风格锁覆盖当前镜头真实光源；ST/CL 与本段光影冲突时，以本段可见光源和剧情时段为准，同时保留项目质感、明暗反差、颗粒/渲染媒介和 NP 防跑偏禁止项。
23. 不把导演执行增强套到所有段落。普通段落默认用 C 导演轨纯净版；高难度镜头才推荐 B，或在 C 中吸收对应增强并回填到镜头轨、声音轨、硬锁和段末状态。
24. 不在用户不知道的情况下启用或跳过 SCV/FF/MAP/SB。判断需要多角度空间包、首帧图、调度图、空间侧别锁定时，必须在交接或输出前告诉用户。
25. 不把工程管理标签单独喂给 Seedance：`A2 / B2 / MAP001 / SB001 / 180 度轴线 / 不要越轴 / 锚点` 这类词如果出现，必须同时写成可见画面事实；否则删除。
26. 不把 04b 的内部运镜或动作组合编号写进最终 prompt；只能写具体摄影机行为、动作起手、接触点、受力结果和反应。
27. 不把视频延长套到所有段落；只有同场景顺延、下一段就是上一段动作和镜头的自然继续时才建议。
28. 不在换场景后继承上一场的点位表、MAP/SB、SCV、强连续空间或视频延长逻辑。
29. 不把视频延长启动句当成 `素材：` 字段；启动句放在最前面，后面仍必须保留对应的 06 A/C 输出结构。
30. 不让摄影机行为破坏空间连续：启用 SCV/MAP/SB 时，摄影机不得越过安全区、不得把窗内外/柜台内外/车内外关系拍反、不得在同一段内无动机换到反方向。
31. 不让同一关键道具因为同时引用 SC/SCV/FF 和 PR 图而复制成两个；PR 若只是外观参考，必须写明“不新增实例”。
32. 不裸写 `asset-xxx` 或无解释的内部资产 ID。角色、场景、视频、音频必须通过 `@图片N / @视频N / @音频N`、兼容英文别名、`<角色名>` 或自然语言桥接。
33. 多主体场景不得只靠 `@图片1 / @图片2` 反复裸写；必须按固定句式定义 `<角色名>`，并用身份、外观、服装等稳定静态特征区分人物，避免双胞胎、串脸和数字粘连歧义。
34. 不在单组可投喂提示词中引用超过 9 张图片参考；项目资产库可以超过 9 张，但每个 Seedance 单元最终上传和引用的 `@图片N / @ImageN` 总数必须不超过 9。
35. 编辑视频和延长视频不得写成“参考 @视频N”。编辑用 `严格编辑 @视频N`，延长用 `向后延长 @视频N` 或自然延长启动句。
