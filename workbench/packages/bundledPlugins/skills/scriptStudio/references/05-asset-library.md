## 1. 定位与边界

05 负责把角色、场景、道具、服装、参考图、生成图、视频参考、声音参考等整理成可复用的项目资产库，并为 04 分镜和 06 Seedance 提示词提供稳定编号、参考图映射和交接格式。

05 不负责写剧本、会诊剧本、改台词、生成最终分镜或最终 Seedance 纯净提示词。

如果用户只是要写故事，回到 `01-script-creation.md`；只是诊断剧本，回到 `02-script-doctor.md`；只是改台词，回到 `03-dialogue-expert.md`；需要把资产变成视频分镜，交给 `04-ai-video-storyboard.md`；需要最终 Seedance prompt，交给 `06-seedance2-adapter.md`。

---

## 2. 核心资产目标

资产库必须服务四件事：

1. **一致性**：同一个角色、场景、道具在不同场次、不同模型、不同生成批次中不漂移。
2. **可追溯**：每张图、每条 prompt、每个版本都知道来源、用途、状态。
3. **可交接**：剧本、台词、分镜、AI 视频 prompt 都使用同一套资产编号。
4. **可扩展**：后续新增角色、场景、道具、服装、镜头参考时，不破坏旧编号。

---

## 3. 稳定编号体系

所有资产必须有稳定编号。编号一旦确认，不因角色改名、场景改名而改变。

| 类型 | 前缀 | 示例 | 用途 |
|---|---|---|---|
| 角色 | CH | CH001_花十 | 主角、配角、群像人物 |
| 场景 | SC | SC001_茶餐厅 | 固定地点、关键空间 |
| 道具 | PR | PR001_银色打火机 | 有叙事作用的物件 |
| 服装 | CO | CO001_花十黑夹克 | 角色造型、换装 |
| 风格 | ST | ST001_港风写实 | 总体画风 |
| 色彩光影 | CL | CL001_暖黄茶餐厅 | 调色、布光母版、光影连续性 |
| 防跑偏负面词 | NP | NP001_港风防跑偏 | 图片 prompt 和 06 Avoid 转译 |
| 声音参考 | AU | AU001_茶餐厅环境声 | 环境音、角色声线、音乐 |
| 调度图 | MAP | MAP001_SC001_B01-B02 | 人物站位、移动路线、摄影机安全区、轴线 |
| 场景多角度空间包 | SCV | SCV001_SC001_便利店窗边 | PLAN、V01-V04 空场角度图和空间细节 |
| 空间侧别锁定 | SB | SB001_便利店窗边_内外侧 | 门窗/柜台/车窗/栏杆等分界面、人物允许区和禁止区 |
| 人群/群演调度 | CR | CR001_铜锣湾下班人流 | 路人数量、层次、移动方向和遮挡规则 |
| 首帧图 | FF | FF001_B05_便利店窗边首帧 | 某视频段第 0 秒构图、人物初始位置、道具位置、空间侧别和光影 |

内部编号可以出现在资产卡、记录表和交接说明中；最终可投喂图片或视频模型的 prompt 必须展开成自然语言，不得只写 `ST001 / CL001 / NP001 / SCV001 / MAP001`。

## 4. 风格锁硬规则

进入图片资产生成链路前，必须先确认、反推或暂定项目视觉风格。没有 `ST` 视觉风格锁定卡时，不直接输出角色、场景、道具、四视图、首帧图或高级角色资料卡 prompt；如果用户要求先推进，可以建立【暂定 ST001】，并在交接中标注可修改。

`ST/CL/NP` 的关系：

1. `ST` 定义项目媒介、人物审美、场景审美、画面质感。
2. `CL` 是光影执行层，必须写成可见光源、方向、亮暗区域、色温、反差和禁止项。
3. `NP` 是防跑偏负面词，给图片 prompt 和 06 Avoid 转译。
4. 如果 `ST/CL` 与当前场景真实光源冲突，当前场景真实光源和剧情时段优先；保留项目质感、反差、颗粒/渲染媒介和 `NP` 禁止项。

任何可复制给图像模型或视频模型的 prompt，不得只写“继承 ST001 / CL001 / NP001”，必须展开成自然语言。

生成角色、场景、道具、服装妆发、风格参考、四视图、高级角色资料卡、SCV 空场角度图、FF 首帧图等**图片资产 prompt**时，必须在每条可直接投喂的 prompt 末尾追加 `05-handoff-output.md` 中“出图 Prompt 默认尾缀”的清洁渲染约束。除非用户明确指定其他模型规则、明确要求去掉该尾缀，或该任务不是图片生成 prompt。

尾缀规则优先级：

1. 先完成 `ST/CL/NP` 自然语言转译。
2. 再在 prompt 末尾追加清洁渲染尾缀。
3. 尾缀必须跟在每条独立图片 prompt 末尾，不能只写在文件总纲或说明里。
4. 视频 prompt、Seedance 2.0 prompt、分镜文本不强制追加该尾缀。

## 5. 角色资产硬规则

核心角色必须建立角色资产卡。生成角色定稿图 / 角色资产图 / 人物参考图 / 角色设定图时，默认输出人物四视图设定图，除非用户明确要求单张头像、表情包、动作图或透明抠图。

四视图负责角色一致性基础；高级角色设定资料卡只在主角、重要配角、反派、怪物、幻兽、机甲、IP 核心角色或用户明确要求时启用，不替代四视图。

角色定稿后，脸型、年龄感、核心气质、标志性识别点不能随意变化。如果模型结果“好看但不像角色”，判定为失败。

详细模板读 `05-style-character.md`。

## 6. 场景连续性硬规则

场景母版图默认必须是空场景，只生成固定环境、空间结构、家具、门窗、招牌、光源和可移动区域；不要生成主角、路人、群演、随机顾客、随机车辆或不可控动态人群。人群由 `CR` 交给 04/06 动态写进视频提示词。

核心或高穿帮场景按需建立：

1. `SCV` 多角度空间包：PLAN、V01-V04 空场角度图，只锁定空间视角和固定物，不放人物、人群和剧情动作。
2. `SB` 空间侧别锁定卡：锁定内外侧、柜台两侧、玻璃两侧、人物允许区、禁止区和摄影机侧。
3. `MAP` 调度图：基于场景母版标注人物点位、移动路线、摄影机安全区和人物轴线。
4. `CL` 场景光影卡：绑定场景母版，给 04/06 继承可执行布光母版。

SCV 不替代场景母版、MAP、SB 或 FF；FF 只锁定某一段第 0 秒画面，不替代角色、场景、道具或调度资产。

详细模板读 `05-scene-continuity.md`。

## 7. 人群与道具硬规则

`CR` 不是人物资产，也不是场景图片资产。它是给 04/06 使用的文字调度卡，用来决定公共场景在某个故事时段是否有人、多少人、站在哪些景深层次、如何移动、是否允许遮挡主角。

私密空间或剧本没写第三人时，04/06 要在限制里写“不允许出现额外人物、路人、群演”。启用人群时，写路人不看镜头、不围观主角、不遮挡关键表情和关键道具、不同脸复制。

关键道具必须建立 `PR` 道具卡。若某个关键道具已经出现在场景母版、SCV 角度图或 FF 首帧图里，同时又提供同一件道具的 PR 外观图，必须建立 `PR` 道具单实例锁，写清：

1. PR 对应画面里哪一个可见道具。
2. PR 图只补外观、裂纹、材质、颜色或屏幕状态，不新增第二件道具。
3. 全片或本段只允许出现一个。
4. 道具被拿起后原位置为空，放下后手中为空。

详细模板读 `05-crowd-prop.md`。

## 8. @图N 与下游交接

05 的资产交接必须建立 `@图N` 映射和参考图用途映射表。每张图都要说明：

```text
只参考什么 / 不参考什么 / 给 04 用什么 / 给 06 用什么 / 风险
```

常见映射：

```text
@图1 = SC001_场景母版图
@图2 = CH001_角色定稿图
@图3 = PR001_关键道具图
@图4 = SCV001_SC001_V02_反向空景
@图5 = MAP001/SB001_调度或侧别参考
@图6 = FF001_Bxx_首帧图
```

交给 06 时，05/04 的 `@图N` 会在 06 中转成官方优先的 `@图片N / @视频N / @音频N`，或第三方兼容的 `@ImageN / @VideoN / @AudioN`。05 只负责说明资产来源和用途，最终 Seedance 字段化纯净提示词由 06 输出。

项目资产库可以保存超过 9 张图片资产，但交给 06 的每一组可投喂提示词 / 每个 Seedance 单元，实际使用的图片参考总数最多 9 张。这个 9 张包含角色图、场景图、道具图、首帧图、调度图、位置参考图、SCV 角度图等所有图片参考；视频和音频不计入图片张数。超过 9 张时，05 必须提示 06 优先保留当前段必需图片，并把低风险参考合并、延后到下一组或改写成文字约束。

分镜前资产检查、参考图用途映射、连续性资产交接包和 FF 首帧需求卡读 `05-handoff-output.md`。

## 9. 输出模式

按用户需求选择：

1. **快速资产库**：只输出核心角色、场景、道具、风格和待补项。
2. **完整资产库**：输出项目资产总表、角色卡、场景卡、道具卡、风格锁、映射表和交接注意。
3. **分镜前资产检查**：检查 04/06 是否够用，列缺失项和建议补图。
4. **角色四视图 Prompt**：生成角色定稿图 prompt。
5. **高级角色设定资料卡 Prompt**：只在高价值角色或用户明确要求时启用。
6. **连续性资产包**：输出 SCV/SB/MAP/CL/FF 等链路资产。
7. **光影设计卡输出**：输出 CL。
8. **场景多角度空间包输出**：输出 SCV。
9. **人群/群演调度卡输出**：输出 CR。
10. **首帧图需求与 Prompt 输出**：输出 FF 需求和首帧图 prompt。

凡上述输出模式生成的是图片资产 prompt，必须追加“出图 Prompt 默认尾缀”。

---

## 10. 快速自检

最终输出前快速检查：

1. 是否建立稳定编号，且编号不会因名称变化而改变。
2. 是否标明资产状态：待补 / 草稿 / 候选 / 定稿 / 废弃。
3. 是否已处理或暂定 `ST/CL/NP`，并在可投喂 prompt 中展开成自然语言。
4. 图片资产 prompt 是否已逐条追加 `05-handoff-output.md` 的“出图 Prompt 默认尾缀”。
5. 角色是否有四视图或定稿参考，核心角色是否避免只用单角度美图。
6. 场景母版是否保持空场，公共空间人群是否交给 `CR`。
7. 高穿帮场景是否判断 `SCV/SB/MAP/CL`。
8. 关键道具是否判断 `PR` 单实例锁。
9. 是否建立 `@图N` 和参考图用途映射表。
9.1 每一组 06 可投喂提示词实际使用的图片参考是否不超过 9 张；超过时是否已按“人物/当前场景/关键道具/首帧或调度优先”筛选，并把低风险参考转成文字或拆到下一组。
10. 是否给 04/06 交接“只参考什么 / 不参考什么”。
11. 是否没有把内部编号裸写进最终可投喂 prompt。
