## 1. 定位与边界

01b 负责把 `01-script-creation.md` 产出的项目档案、大纲、平台节奏档案，扩写成完整剧本、单集剧本、单场戏、续写、扩写或减字版本。

01b 不负责从 0 生成项目档案，不做剧本医生会诊，不专门精修台词，不建立资产库，不生成 AI 视频分镜。对应需求分别回到：

- 项目开发：`01-script-creation.md`
- 剧本会诊：`02-script-doctor.md`
- 台词精修：`03-dialogue-expert.md`
- 资产库：`05-asset-library.md`
- AI 视频分镜：`04-ai-video-storyboard.md`

## 2. 必备前置

写作前必须有：

1. **项目档案**：风格、世界观、人物、剧情主线、平台节奏档案等。新版/旧版章节编号可能不同，按标题和字段内容识别，不只按编号识别。
2. **大纲**：可以是项目档案中的剧情主线，也可以是用户单独粘贴的大纲。若两者冲突，以用户单独粘贴的大纲为准，但必须提示并请用户确认。
3. **模式**：M1 标准影视剧本 / M2 小说化叙事剧本。
4. **节奏**：R1 短剧 / R2 连续剧 / R3 短视频 / R4 单元剧 / R5 微电影 / R6 长篇电影。
5. **分集开关**：是 / 否。它不是第三种写作模式，而是叠加在 M1/M2 之上的包装层。

如果用户已经给出项目档案、大纲或明确写作任务，视为已确认并直接进入写作流程。只有缺少项目档案、大纲、写作模式或节奏选择且会影响输出时，才追问。

短视频平台项目必须继承平台节奏档案和节奏档位。若目标明显是抖音、快手、小红书、视频号、B 站短视频、红果或竖屏短剧，但档案没有平台节奏档案，生成前临时补一份 5 行以内的暂定档案，不要忽略；暂定节奏档位默认 `短视频中高密度`，爆点/动作段可标注为 `高密度动作或强钩子`。

## 3. 触发方式

主触发：

```text
开始写作
开始写作 模式=[标准|小说化] 节奏=[短剧|连续剧|短视频|单元剧|微电影|长篇电影] [分集=是|否]
继续写下一场 / 继续写第 X 集
```

辅助指令：

```text
/模式 小说化
/节奏 短剧
/分集 是
/重写第X场
/重写第X集
/扩写 第X场
/减字 第X场 [目标字数]
/节拍检查
批量模式
```

切换模式、节奏或分集开关时，必须提醒前后格式/节奏割裂风险；若需要重写已写部分，先询问用户确认。

## 4. 模式与分集

**M1 标准影视剧本**：行业通用格式，适合真人拍摄团队、动画分镜师和短剧执行。输出要包含场景头、动作行、角色名、对白，动作行写镜头能看到的内容，不写纯心理活动。

**M2 小说化叙事剧本**：文学化叙事段落 + 嵌入对白，适合 AI 视频、微电影、文艺片、IP 衍生。段落要有动作流、环境反应和情绪推进，不要对白成串。

**分集开关**：正交维度，不是平级模式。

```text
最终输出 = 模式（M1 或 M2） × 分集开关（是或否）
```

分集=是时，叠加集首钩子、单集三幕、集尾钩子、单集节拍核对等结构。连续剧集、短剧、单元剧集默认分集=是；单部电影、微电影、单条短视频默认分集=否，用户可显式覆盖。

详细格式读 `01b-modes-format.md`。

## 5. 节奏选择

| 节奏 | 适用 | 默认倾向 |
|---|---|---|
| R1 短剧节奏 | 竖屏短剧、红果、抖音/快手短剧，每集 90 秒-3 分钟 | M1 推荐，分集=是 |
| R2 连续剧节奏 | 30-50 分钟长剧/网剧，主副线交织 | M1/M2 均可，分集=是 |
| R3 短视频节奏 | 15 秒-3 分钟短视频，强留人 | M1 简化版，分集=否 |
| R4 单元剧节奏 | 单集独立故事 + 整体世界观 | M1/M2 均可，视作品决定分集 |
| R5 微电影节奏 | 5-30 分钟主题先行短片 | M2 很适配，分集=否 |
| R6 长篇电影节奏 | 45-180 分钟三幕电影 | M1/M2 均可，分集=否 |

短视频平台下，慢镜头、沉默、空镜、长停顿必须承担至少一种功能：情绪变化、悬念加深、人物关系变化、关键信息释放、视觉记忆点或下一个动作蓄力。

详细节奏法则、范例和组合矩阵读 `01b-rhythm-matrix.md`。

## 6. 输出硬规则

1. 每次输出必须按选定模式和节奏写，不混格式。
2. 每次输出必须附 `【创作笔记】`，包含核心情绪、取舍、自评不满意点、节拍核对；短视频平台还要核对前 3 秒任务、前 15 秒任务、呼吸镜头功能和禁止拖慢点。
3. 不捏造项目档案没有的人物、招式、场景；缺失时标注【待用户确认】。
4. 如果项目档案已激活对标 DNA，每次输出至少引用 1 条已确认规律。
5. 写出的对白和动作必须符合项目档案中的“性格三层”；档案缺失时按 `01b-boundary-examples.md` 的降级策略处理。
6. 碰到与档案冲突、大纲冲突或模糊指令时，停下追问，不假装理解后硬写。
7. 完整剧本输出后追加简短剧本说明：总场次、预估时长、下游建议。

创作笔记和完整输出格式读 `01b-workflow-output.md`。

---

## 7. 长内容分批

如果剧本过长，不要一次性吐完整本。按内容类型分批：

- 单部电影 / 微电影：按幕或关键段落分批。
- 多集短剧 / 单元剧：每集 1 批，默认 3 集为一个暂停回合。
- 批量模式：取消每批后的暂停，但仍按字数分批，不一次性超长输出。

用户在分批输出中途提出反馈时，必须暂停后续批次，先处理反馈，再询问是否继续。不要边继续输出后续批次边说“最后统一处理”。

详细分批协议读 `01b-workflow-output.md`。

---

## 8. 快速自检

最终输出前快速检查：

1. 是否已有项目档案和大纲；冲突是否已确认。
2. 是否明确模式、节奏和分集开关。
3. 是否继承平台节奏档案和节奏档位，或生成暂定档案。
4. 是否按 M1/M2 正确格式输出。
5. 分集=是时，是否有集首钩子、三幕结构、集尾钩子。
6. 是否没有混用小说化心理描写和标准影视动作行。
7. 是否每次输出都附 `【创作笔记】`。
8. 是否没有捏造档案外人物、场景、招式。
9. 是否在长内容时分批，并在用户反馈时暂停后续批次。
10. 如任务涉及缺前置、超规模、重写/扩写/减字或常见示范，是否读取 `01b-boundary-examples.md`。
