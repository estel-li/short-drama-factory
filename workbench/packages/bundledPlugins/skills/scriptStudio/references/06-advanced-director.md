### 10.2.2 导演执行型增强块（B 模式或按需吸收）

下面结构用于 B 导演执行增强版，也可在 A/C 模式命中一镜到底、强运镜、动作戏、人群调度、强声音叙事、色卡锁定或遮挡转场等高难度镜头时按需吸收。最终要回填到 C 的 `风格锁定 / 镜头轨 / 声音轨 / 硬锁 / 段末状态`，或 A 的 `运镜 / 主体动作/表情 / 台词与语气 / 光影 / 音效说明 / 限制 / 段末状态`，不能输出成另一套难复制的工程说明。

```text
[风格锁定 / STYLE LOCK]
[真实拍摄/动画/电影风格、胶片、调色、镜头质感、摄影师/作品参考、画幅、材质、整体摄影气质。不要只写高级感，要写可见质感。若来源是 ST/CL/NP，必须把项目风格、光影和禁止项展开为自然语言；不要只写 ST001/CL001/NP001。]

[素材/角色/色卡锁定]
[说明 @图片/@视频/@音频 各自用途；第三方接入端可使用 @Image/@Video/@Audio 别名。角色图只锁外观，场景母版只锁空间结构，SCV 角度图只锁当前镜头拍摄方向和空间透视，色卡只锁色彩方向，首帧图只锁第 0 秒。]

[场景空间结构]
[地点、人物所在区域、不可越界区域、镜头所在位置、前景/中景/远景关系、门窗/柜台/玻璃/道路/轨道等分界；如启用 SCV，写明使用 V01/V02/V03/V04/PLAN 中哪一张作为空间角度参考。]

[首帧/连续性锁定]
[仅需要时输出；写本视频第 0 秒可见事实，或 SCV 场景角度、MAP/SB 点位、移动路线、摄影机安全区。不要只写“承接上一段”。]

[环境持续锚点]
[全段持续存在的风、雨、沙尘、人群、灯光闪烁、布料摆动、城市噪音等，让画面有持续生命感；没有明确需求时不输出本块。]

[摄影机行为锁]
[写成可执行摄影机行为，而不是只列名词。必须包含：摄影机类型（固定/手持/稳定器/轨道/车载/主观视角）、位置（主体正面/背后/左前45°/过肩/窗外/柜台外/车内外）、距离（贴身/近景/中景/远距离）、高度与角度、运动方向（推近/后撤/横移/侧跟/前导倒退/环绕/升降/摇向目标）、稳定程度（完全稳定/微移/手持呼吸感/明显手持/剧烈晃动）、速度（极慢/缓慢/同步/快速/突然甩动）、起止状态。固定镜头也必须写清固定位置和禁止漂移。]

[可选行为模板]
- 固定锁：摄影机固定在[位置]、[高度]、[景别]，看向[主体/动作]，不推拉不摇移，不无动机变焦。
- 手持锁：摄影机在[主体侧别]约[距离]手持拍摄，[轻微呼吸感/明显手持/剧烈晃动]，跟随[动作]，主体不得出画。
- 跟拍锁：摄影机从[背后/侧面/正前方倒退]跟随[角色]，保持[距离和景别]，速度与角色同步，段末停在[位置]。
- 退拍锁：主体向镜头逼近时，摄影机从[近景]快速后撤到[全景/中景]，露出[空间/阻挡物]并稳住。
- 焦点锁：摄影机固定不动，焦点从[前景物件/人物]转到[后景人物/物件]，不改变构图。
- 遮挡转场锁：前景[人物/物体]完全遮住画面后切入[下一角度/下一场景]，遮挡前后空间方向保持一致。

[摄影机禁止项]
禁止随机漂移、无动机变焦、突然换机位、越轴、穿墙穿桌、手持强度失控、跟拍中角色出画、退拍后空间结构改变、遮挡转场后人物左右关系反掉。]

[构图与人物比例]
[人物占画面比例、全身/半身/远景、地平线位置、留白方向、前景遮挡、主体是否居中、禁止推近或裁切。]

[动作节奏与顺序]
[按镜头顺序或动作先后写，不默认按秒硬切。每个动作必须可见、可拍、可生成；复杂动作写触发点、过程、结果。快切/蒙太奇/卡点可写“每镜约 0.5-1 秒”等软节奏。]

[角色表演锁]
[角色的表情强度、微动作、反应上限、是否零反应、是否爆发；禁止过度表演。]

[对白与口型]
[有对白时写说话者、原台词、语气、音量、语速、口型同步要求；无对白时写无对白，并说明是否只有呼吸声、抽气声、环境声。]

[人群/群演调度]
[仅启用人群时输出；写前景/中景/远景人数、类型、移动方向、遮挡规则、不同脸不同体型、不看镜头、不抢戏。]

[道具单实例锁]
[仅同一 PR 道具已在场景/首帧中可见且又使用 PR 外观图，或道具会被拿起/移动/跨段延续时输出；写清 PR 图不是新增道具，只修正已存在那一件道具的外观；全片/本段只允许一个；移动后原位置和手中状态不能同时保留。]

[光影与色彩锁]
[主光方向、亮区、暗区、轮廓光、色温、色卡、视觉钉子色、明暗反差、禁止整体提亮或偏色。]

[声音叙事层]
[环境底噪、关键音效、动作绑定、声音距离、声音清晰度、是否对白、是否被环境淹没、是否无配乐。]

[转场/遮挡机制]
[布料揭开/遮满、路人擦镜、前景虚焦遮挡、物体 wipe、尾帧/首帧衔接；没有明确需求时不输出本块。]

[限制项]
[必须保持什么、禁止什么、不要出现什么错误；特别写角色身份、场景侧别、人物比例、道具文字、人群抢戏、镜头推近等。]

[段末状态 / 下一段衔接]
[段末人物位置、道具状态、光线、镜头方向、是否可作为下一段首帧候选。]
```

导演执行型增强使用规则：

1. 单段仍必须 4-15 秒；超过 15 秒必须拆。
2. 必须继承 04 的节奏档位判定和镜头密度判断；04 未给出时，B 模式先按平台、动作密度、对白长度和本段功能自动补判。高密度动作或强钩子可容纳 8-10 个短镜头，但仍要通过 1900/2000 字闸门，不得压回 1-2 镜。
3. 信息密度过高时，优先保留 STYLE LOCK、空间结构、摄影机行为锁、动作节奏与顺序、对白与口型、限制项和声音叙事层。
4. 不要把所有块机械输出进最终 prompt。没有人群就不写人群增强，没有转场就不写转场增强，没有色卡就只在 `光影` 里写清可见色彩。
5. 这些增强可以和 SCV 场景角度图、FF 首帧、MAP/SB、CR 人群、CL 光影、色卡共同使用，但每个素材用途必须分清。
6. 单组最终上传和引用的图片参考总数仍不得超过 9 张；B 高难镜头命中多个增强时，优先保留人物、当前场景、关键道具、首帧或调度图，低风险风格/角度参考转成文字或拆到下一组。
7. 最终提示词仍要可投喂，不要夹杂解释、表格、JSON 或多个备选版本，也不要把本块标题完整塞进默认模板。

### 10.2.7 工程语言清洗规则

05/04 可以保留 `A2 点位`、`MAP001`、`SB001`、`180 度轴线`、`摄影机安全区` 这类给人管理项目用的词；06 的最终可投喂 prompt 必须把它们翻译成当前画面可见事实。管理词可以出现在素材映射或项目说明里，但不要单独出现在纯净提示词的画面字段中。

转换原则：

1. 点位编号必须落成空间描述：`A2` 改写为 `茶几左侧、画面左侧区域`，`B2` 改写为 `沙发右端、画面右侧区域`。
2. 轴线规则必须落成摄影机侧别：`不要越轴` 改写为 `摄影机保持在茶几正前方这一侧，不切到两人背后的反方向`。
3. 调度图编号必须落成参考用途：`参考 MAP001` 改写为 `使用 @ImageN 作为调度图，只参考人物点位、移动路线、摄影机安全区和窗内外/柜台内外关系`。
4. 锚点必须落成画面物体：`以沙盘为锚点` 改写为 `沙盘位于画面中央，角色围绕沙盘左右分布，移动时不穿过沙盘`。
5. 04b 的运镜或动作组合编号不得进入最终 prompt，必须改写成具体摄影机行为和动作结果。

如果必须保留编号方便用户核对，写成“编号 + 可见解释”：

```text
林墨站在 A2（茶几左侧、画面左侧区域），苏眠坐在 B2（沙发右端、画面右侧区域）；摄影机位于 C1（茶几正前方这一侧），不切到两人背后的反方向。
```

禁止只写：

```text
林墨在 A2，苏眠在 B2，参考 MAP001，不要越轴。
```

## 十一、中文 Prompt 与英文 Prompt 规则

### 默认规则

Seedance 2.0 适配器默认输出中文提示词。中文正文要完整包含：

1. 素材引用：`@图片1/@视频1/@音频1` 分别是什么；第三方接入端可使用 `@Image1/@Video1/@Audio1` 兼容别名。
2. 场景环境：地点、时间、光线、氛围。
3. 角色动作：谁做什么，动作顺序是什么。
4. 镜头运动：推、拉、摇、移、跟、过肩、特写等。
5. 台词与语气：独立字段写清谁说、原台词、声音轻重、语速、情绪状态和口型要求；无对白时写无对白。
6. 保持项：角色、服装、场景、道具、光线等不能漂移。
7. 禁止项：不要字幕、水印、换脸、换装、生成 BGM 等；无人群需求时禁止额外人物、路人、群演；启用人群时改为禁止路人看镜头、挡脸、抢戏、同脸复制。

### 需要英文或中英双版的情况

1. 用户通过海外第三方 API 接入。
2. 画面风格、镜头语言、动作控制优先。
3. 需要更稳定识别 camera movement。
4. 用户明确说“英文版”“中英双版”“海外 API 版本”。

### 中英双版格式

需要中英双版时，按这个结构输出：

```text
中文主提示词：
说明素材、场景、角色动作、台词、情绪、镜头和限制。

English execution prompt:
Describe visible action, camera movement, lighting, composition, continuity constraints, and avoid items.
```

不要把同一句内容中英重复堆太多，否则 prompt 会变胖，模型反而容易忽略重点。

## 十二、音频生成规则

如果开启生成音频，必须写清：

1. 是否有对白。
2. 谁说话。
3. 语气、音量、语速。
4. 环境声。
5. 同步音效、画外音、非人声、多人同时出声和音量层级。
6. 是否明确不生成 BGM。

### 音频提示模板

```text
生成同步音频。茶餐厅环境声柔和真实：远处顾客低声交谈、杯子轻碰声、空调低频声。<林深> 用轻声、犹豫、带一点试探的语气说：“要不去我家看猫吧。” 不生成 BGM，不要让环境声盖过对白。
```

### 音频红线

1. 不生成 BGM；06 只处理环境声、对白原声、画外音、非人声和同步音效。
2. 有口型要求时，台词必须短。
3. 旁白和角色对白要分清。
4. 如果用户没有授权音乐参考，不要写“使用某某歌曲风格”。
