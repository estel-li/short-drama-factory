# 06 Core Format：Seedance 基础格式与标准输出

> 本文件由 06-seedance2-adapter.md 第二批瘦身拆分而来，保留原规则文本。按主路由命中时读取。

---

## 一、定位与边界

### 本模块负责

1. 把通用分镜转换成 Seedance 2.0 可读的自然语言 prompt。
2. 把资产库中的 `@图N` 转换为官方 `@图片1 / @视频1 / @音频1` 引用，并兼容第三方接入端的 `@Image1 / @Video1 / @Audio1` 别名。
3. 根据视频生成模式整理参数：时长、比例、分辨率、音频、参考素材、seed 等。
4. 把 04 的焦段 / 光圈 / 景深与焦点锁 / 机位 / 构图 / 运镜 / 主体动作 / 限制字段，整理成 Seedance 2.0 更容易执行的字段化提示词。
5. 为每段大分镜输出“提示词包”，可供用户复制到平台或开发接口中使用。

### 本模块不负责

1. 不写剧本。
2. 不会诊剧本。
3. 不改台词。
4. 不重新建立角色资产库。
5. 不替代 04 的分镜生成。
6. 不承诺某个第三方平台的 API 字段永远不变；平台字段以用户实际接入端为准。

---

## 二、什么时候调用本模块

用户出现以下需求时，调用本模块：

1. “转 Seedance 2.0”
2. “生成 Seedance 提示词”
3. “豆包视频 / Seedance / 火山方舟视频生成”
4. “把分镜转成可复制到 Seedance 的 prompt”
5. “按 @Image / @Video / @Audio 写提示词”
6. “帮我适配 Seedance 2.0 的首尾帧 / 图生视频 / 参考图”
7. “04 的分镜能不能变成 Seedance 2.0 用的”
8. “我要用 Seedance 2.0 做成片，帮我输出提示词包”

如果用户还没有分镜，先调用 `04-ai-video-storyboard.md`。  
如果用户还没有资产库或参考图映射，建议先调用 `05-asset-library.md`。  
如果用户只有剧本且没有定稿，先回到写作 / 会诊 / 台词模块。

## 三、Seedance 2.0 适配原则

Seedance 2.0 的提示词更适合“自然语言导演描述”，而不是纯表格字段。默认输出要采用字段化自然语言，让用户既能直接投喂，又能检查每个镜头是否漏项。适配时遵循：

0. **默认中文输出**：Seedance 提示词正文默认使用中文。官方面向用户的素材引用优先写 `@图片N / @视频N / @音频N`；如果用户使用英文 API、第三方接入端或原项目已采用英文别名，可兼容写 `@ImageN / @VideoN / @AudioN`。除模型参数字段、必要英文运镜术语和用户指定英文版外，不主动改成英文。
1. **先素材，后画面**：先说明 `@图片1` 是谁、`@视频1` 用作什么、`@音频1` 提供什么，再写画面动作。多主体或需跨镜头复用时，人物锚定固定写 `将 @图片N 中的[身份/外观/服装]定义为 <角色名>`，后续镜头用 `<角色名>` 指代。
2. **先整体，后镜头顺序 / 节奏策略**：先写本段目标，再按 `镜头1 / 镜头2 / 镜头3` 推进。默认不要写硬时间戳；总时长、画幅、分辨率、模式、任务类型、建议参数放在代码框外。快切、蒙太奇、广告卡点可写软时间节奏，例如“前段快速推进”“最后一镜稍停”，但不得把绝对秒数当成模型必须精确执行的硬控制。
3. **少堆术语，多写可见动作**：焦段、光圈、构图可以保留，但不要让术语淹没主体行为。
4. **台词与语气独立成字段**：有对白时，必须在每个相关分镜中单独输出 `台词与语气：`，用双引号保留原台词，并明确说话者、语气、音量、语速和口型要求；无对白时写 `台词与语气：无对白`。`主体动作/表情` 只负责可见动作、微表情、呼吸、身体反应和口型动作，不再承载完整台词文本。
4.1 **台词时长闸门**：06 不改写台词，只检查可执行性。输出建议时长前，必须估算本段/本镜对白能否以自然语速说完；若放不下，优先延长到 15 秒内，仍放不下则按台词自然停顿、问答回合或情绪转折拆连续单元；需要缩短台词时建议回 `03-dialogue-expert.md`，不得擅自删改原台词。
5. **限制要短而硬**：把 04 的限制字段压缩为“保持 / 禁止 / 不要”三类。
6. **一段只解决一个情绪转折**：Seedance 2.0 单段时长必须在 4-15 秒之间，不要把太多场景塞进一个 prompt。
6.1 **参数外置，画面内化**：纯净提示词中的 `全局控制` 只允许写模型需要生成的场景、情绪、光影、风格、动作密度和镜头执行原则；不得写 `9:16 / 13-15秒 / 1080p / 参考生视频 / 多模态参考` 等平台参数。纯净提示词的衔接必须写可见动作或段末画面状态，不写 `接下一大分镜 / 接下一段 / 承接下一段 / 接分镜2` 这类管理语。
7. **旧版字段信息是能力底座，不是默认展开表格**：必须保留素材、场景、人物位置关系、焦段、光圈、景深、机位、构图、运镜、动作、台词、光影、限制、衔接和段末状态这些控制信息。默认 C 可以把这些信息合并进导演轨；A 才逐项展开旧版 11 字段。新增规则只能增强，不得削弱这些信息。
8. **继承平台节奏标记和节奏档位**：如果 04 分镜含有“节奏档位判定 / 本段钩子 / 本段信息增量 / 本段情绪推进 / 呼吸镜头功能 / 段末继续看的理由”，必须压缩进纯净提示词或代码框外说明，不要只输出画面参数。节奏档位的管理说明放代码框外，纯净提示词只体现为镜头轨动作密度、转接速度、慢词控制和段末钩子。
9. **禁止无功能慢镜头**：慢推、空镜、沉默、长停顿必须服务情绪变化、悬念加深、人物关系变化、关键信息释放、视觉记忆点或下一段动作蓄力。
9.1 **继承镜头密度判断**：如果 04 已输出 `节奏档位判定` 和 `镜头密度判断`，06 必须继承建议分镜数和慢节奏风险。`短视频中高密度` 或 `高密度动作或强钩子` 段不得被压回 1-2 镜；10 秒以上只有 1-2 个镜头时，必须在代码框外提示慢节奏风险，并在纯净提示词内写清慢镜头功能。不得为了压缩字数把 04 已确认的功能镜头合并成 1-2 个镜头。
10. **先判断相邻段边界，再写提示词**：输出多段 Seedance 提示词时，必须先按相邻段关系给出连续性建议，判断每两段之间应该用“视频延长 / 首帧图 + 调度图 / 只首帧图 / 只调度图 / 普通衔接”。这一步由 06 主动判断并建议，不等用户先提出。
11. **同场景才默认强连续**：强连续空间延续、站位延续、MAP/SB 调度图、SCV 多角度空间包默认只用于同场景或同一空间系统。切换到新场景时，默认不继承上一场的点位表、调度图、空间侧别和视频延长逻辑，只保留角色身份、服装发型、道具状态、情绪任务和平台节奏。
12. **视频延长是同场景顺延优先项**：如果 B 段是 A 段的同场景自然顺延，动作、镜头方向、人物姿态、光线和道具状态都应该从 A 段末尾继续，优先建议 Seedance 2.0 的视频延长。纯净提示词最前面写：`使用 @视频1 作为上一段成片视频，只从上一段末尾继续自然延长 X 秒，接入本段动作。不重置角色身份、服装、发型、场景空间、光线方向、镜头方向和道具状态。` 后面继续保留对应的 C 导演轨纯净版或 A 标准字段化详细版结构；第三方接入端可改用 `@Video1`。
13. **首帧图和调度图是空间锁定项**：如果同场景起始画面复杂、人物位置容易错边、窗内外/柜台内外/车内外容易反，建议 FF 首帧图；如果风险主要在多人走位、轴线、内外侧、遮挡、摄影机安全区，建议 MAP/SB 调度图；两者都复杂时建议“首帧图 + 调度图”。
14. **场景首现多人调度也要首帧 + 调度图**：即使不是强连续，只要一个新场景第一次出现时人物很多、站位复杂、进出路线和遮挡关系需要被组织，也要建议 FF 首帧图 + MAP/SB 调度图，用来锁定第 0 秒构图、初始站位和调度路线。
15. **独立批量强连续不靠模型理解上一段**：如果是同场景强连续、回切强连续或用户要求批量生成少穿帮，但没有使用视频延长，纯净提示词必须在保留基础模板的前提下直接写“本视频第一帧状态”，不能只写“承接 B01 / 上一段 / 仍然 / 继续 / 同一客厅”这类依赖上下文的词。
16. **尾帧延续只是增强选项**：只有用户实际上传上一段视频、末帧或首尾帧参考时，才使用“从 @视频1 末帧继续 / 使用 @图片1 作为首帧”这类写法；第三方接入端可改用 `@Video1 / @Image1`。不要把尾帧当成默认流程。
17. **光影字段必须可见可执行**：`光影：` 不能只写“电影级布光 / 高级光影 / 氛围感”。必须写清光源来源、主光方向、亮区、暗区、脸部受光、轮廓光或背景分离、色温、明暗反差；如果写丁达尔光效，必须写光束来源、介质和落点。
18. **情绪表演必须拆成微动作**：`主体动作/表情：` 不能只写“悲伤 / 愤怒 / 害怕 / 心动”。必须写眼神、眨眼、嘴部、呼吸、肩颈、手部或身体重心的可见变化；`限制：` 必须写清禁止过度表演，如不要假哭、不要夸张皱眉、不要咆哮、不要突然失控，除非剧情明确爆发。
19. **人群是当前段的可见事实**：05 的 `CR` 人群/群演调度卡必须被翻译成 Seedance 能直接理解的 `人群密度` 句子，不要只写 `CR001`、`同上一段人群`、`保持之前人流`。场景母版如果是空场图，只作为空间结构、灯光、透视和固定物参考；启用人群时，直接写清本段可见的人数、层次、类型、移动方向和遮挡规则，不写“不继承空无一人状态”这类管理说明。无路人需求时，不新增 `人群密度` 字段，只在限制里写“不允许出现额外人物、路人、群演”。
20. **SCV 角度图是空间视角，不是新场景**：如果 05/04 提供 `SCV` 多角度空间包，06 必须在 `素材` 或 `场景角度参考` 中写清当前段使用哪张 V01/V02/V03/V04/PLAN，只参考拍摄方向、空间透视、门窗/家具相对位置和固定光源；不得让 SCV 替代 SC 场景母版、MAP 调度图、SB 空间侧别锁定卡或 FF 首帧图。
21. **工程语言必须转成画面语言**：05/04 可以使用轴线、锚点、点位表、MAP/SB 编号给人看；06 最终可投喂提示词必须把这些改写成 Seedance 更容易识别的画面事实，例如左侧/右侧、前景/中景/远景、摄影机在哪一侧、角色在窗内还是窗外、角色向画面哪个方向移动。不要只写“180度轴线 / 不要越轴 / A2点位 / 参考MAP001 / 以沙盘为锚点”。
22. **摄影机行为必须锁成可执行句**：`运镜` 和 `[摄影机行为锁]` 不能只写“固定 / 手持 / 跟拍 / 退拍”。必须写清摄影机类型、位置、距离、高度、运动方向、稳定程度、速度、起止状态和禁止项。固定镜头也要写成“摄影机固定在哪、看向哪里、禁止推拉摇移和无动机变焦”。
23. **ST/CL/NP 只作为管理来源，不作为最终投喂词**：05/04 的 `ST` 视觉风格锁定卡、`CL` 色彩光影设计卡、`NP` 风格防跑偏负面词包，可以出现在代码框外的投喂信息或素材管理说明里；代码框内的最终 Seedance 纯净提示词必须把它们翻译成自然语言。禁止只写 `ST001 / CL001 / NP001 / 继承 ST`。要写清项目风格、人物审美、场景审美、画面质感、当前镜头光影和风格禁止项。
24. **风格光影冲突时融合，不互相覆盖**：如果 ST/CL 的默认光影与当前分镜的真实光源、剧情时段或角色位置冲突，以当前镜头的真实光源和剧情时段为准；同时保留项目风格的媒介质感、明暗反差、颗粒/渲染方式、人物审美和 NP 禁止项。不要在同一提示词里同时写两套互相打架的光影系统。
25. **PR 道具图不是天然新增物体**：如果同一件关键道具已经出现在 SC 场景母版、SCV 角度图或 FF 首帧图中，同时又上传 PR 道具参考图，06 必须写清 PR 只修正这一件已存在道具的外观，不新增第二个实例。提示词必须包含数量限制、绑定位置、移动后原位置变化和禁止复制项，避免桌上一个、手里一个或背景又出现一个同款道具。
26. **先判定任务类型**：每段 06 输出前先在代码框外标注任务类型：`多模态参考 / 编辑视频 / 延长视频 / 组合任务`。多模态参考再判断简单路径 A 或复杂路径 B；编辑、延长、组合任务默认走路径 A 的单点操作逻辑。
27. **编辑 / 延长任务直接指向 @视频**：编辑视频必须写 `严格编辑 @视频N`；延长视频必须写 `向前/向后延长 @视频N` 或本技能既定的自然延长启动句。不要把编辑或延长写成“参考 @视频N”，否则模型可能误判成参考任务。
28. **官方符号可按需使用**：有明确音频/字幕/文字生成需求时，台词可用 `{台词}`，音效可用 `<音效>`，字幕/标题可用 `【字幕/标题】`。06 默认不生成 BGM；BGM 交给 07 后期声音设计。没有文字生成需求时，默认写“保持无字幕，避免生成任何文字或字幕”。

## 四、输入材料要求

### 最佳输入

```text
1. 04 输出的大分镜 + 分镜表
2. 05 输出的资产总表
3. 05 输出的分镜资产映射表
4. 用户使用的平台或接口：火山方舟 / 可视化平台 / fal / Cloudflare / Replicate / 其他
5. 目标比例、时长、分辨率、是否生成音频
6. 平台节奏档案或 04 输出的平台节奏标记（如有）
7. 04 输出的生成关系、本段第一帧状态、本段目标末端状态、下一段起始状态建议（强连续增强时必需）
8. 05 输出的场景母版、SCV 多角度空间包、空间解析卡、调度图和点位表（核心场景、反打、同场景强连续或回切强连续时建议提供）
9. 05 输出的 CR 人群/群演调度卡（公共空间、街道、商场、车站、学校、医院、营业餐厅等需要路人真实感时提供）
10. 05/04 输出的 FF 首帧图、首帧需求卡、参考图用途映射表和 SB 空间侧别锁定卡（A 必须首帧或 B 建议首帧时提供）
11. 05/04 输出的 ST 视觉风格锁定、CL 色彩光影设计、NP 风格防跑偏负面词包或“风格交接”（用于自然语言转译，不用于直接复制内部编号）
12. 05 输出的 PR 道具单实例锁（同一关键道具同时出现在 SC/SCV/FF 与 PR 参考图时必须提供）
```

### 可接受输入

```text
1. 定稿剧本 + 资产库
2. 定稿剧本 + 参考图说明
3. 单场戏 + 角色图 / 场景图
```

### 信息不足时

如果缺少平台参数，不要卡住，先用“推荐参数”输出，并标注：

```text
参数暂定，请按你的 Seedance 2.0 接入平台修改。
```

## 五、素材引用映射

04 和 05 使用 `@图N`，Seedance 2.0 官方提示词更适合使用中文素材引用；英文别名可作为 API 或海外接入兼容写法：

```text
官方优先：@图片1 / @图片2 / @图片3
官方优先：@视频1 / @视频2
官方优先：@音频1 / @音频2

兼容别名：@Image1 / @Image2 / @Image3
兼容别名：@Video1 / @Video2
兼容别名：@Audio1 / @Audio2
```

人物锚定固定句式：

```text
将 @图片1 中的青年男性、黑金纹饰旧袍定义为 <玄衡>，将 @图片2 中的女性、暗青色战衣定义为 <青鸢>
```

锚定后，后续镜头只用 `<玄衡>`、`<青鸢>` 这类 `<角色名>` 指代该角色；一致性细节放进素材锚定、具体镜头 `限制` 或 `段末状态`。锚定句只写定义，不追加说明。没有正式角色名时，临时命名为 `<角色A>`、`<角色B>`，仍按同一句式锚定；不使用编号主体标签做人物锚定。

如果 `@图片N` 后面紧接动词或方位词，必须改成 `<角色名>` 或补名词隔断，避免数字粘连歧义。最终投喂提示词不得裸写 `asset-xxx`、`ST001`、`CL001`、`MAP001` 这类模型无法理解的内部 ID。

### 映射规则

```text
@图1 = SC001_场景定稿图     → @图片1 = environment reference（兼容 @Image1）
@图2 = CH001_角色定稿图     → @图片2 = character reference（兼容 @Image2）
@图3 = CH002_角色定稿图     → @图片3 = character reference（兼容 @Image3）
@图4 = PR001_关键道具定稿图 → @图片4 = prop reference（兼容 @Image4）
```

### 素材引用红线

1. 没有用户提供的素材，不要凭空写 `@图片1` 或 `@Image1`。

7. 启用 FF 首帧图时，必须写清它只控制第 0 秒，不控制整段动作和结尾状态。
8. 启用 SCV 角度图时，必须写清它只控制当前镜头空间方向和透视，不控制人物站位、剧情动作、第 0 秒构图或整段结尾状态。
9. 场景母版、场景角度图、角色图、道具图、首帧图、调度图不能互相替代；每张图都必须说明“只参考什么 / 不参考什么”。
10. FF 首帧图与 SCV/MAP/SB/点位表冲突时，不要输出最终 prompt，先提示重做首帧或修正资产。
10. 如果 PR 道具图对应的道具已经在 SC/SCV/FF 中可见，不得把 PR 写成“添加一个道具”；必须写“PR 只作为已存在那一件道具的外观参考，不新增第二个实例”。

### 首帧/调度/参考图优先级

当同时存在 FF、MAP、SB、SC、CH、PR 时，按以下优先级理解素材：

1. `FF 首帧图`：只锁定本段第 0 秒的构图、人物初始位置、道具位置、空间侧别、摄影机侧和光影方向。
2. `MAP 调度图 / SB 空间侧别锁定卡`：锁定空间逻辑、点位、移动路线、摄影机安全区、轴线、内外侧和禁止区。
3. `SCV 场景角度图`：锁定当前镜头从哪个方向看同一空间、空间透视、门窗/家具相对位置和固定光源方向；不继承人物、人群、剧情动作或第 0 秒首帧构图。
4. `SC 场景母版`：锁定空间结构、固定家具、门窗、光源、透视和环境风格；不继承人物、人群或剧情动作。
5. `CH 角色图`：锁定脸型、发型、服装、体态和年龄感；不继承场景、临时表情和姿态。
6. `PR 道具图`：锁定外观、材质、裂纹、颜色、屏幕状态；文字内容必须在提示词里另写。如果该道具已经在 SC/SCV/FF 中出现，PR 只修正同一件道具的外观，不新增第二个道具。

冲突处理：

- FF 与 MAP/SB 冲突：停止输出，要求先重做 FF 或修正 MAP/SB。
- FF 与 SCV 冲突：先确认 SCV 是否与场景母版一致；若 SCV 正确，重做 FF；若 SCV 与母版冲突，重做 SCV。
- FF 与 SC 冲突：优先保留 SC 的空间结构，重做 FF。
- SCV 与 SC 冲突：优先保留用户确认的 SC 场景母版和空间解析卡，重做冲突角度图。
- FF 与 CH/PR 外观冲突：优先保留 CH/PR，重做 FF 或在限制中明确修正。
- SC/SCV/FF 中已有某个 PR 道具，且 PR 图也被引用：不视为冲突，但必须启用道具单实例锁；如果无法判断是不是同一件道具，先要求用户确认或在输出中标注高风险。
- 有 FF 时，06 的 `素材` 字段要先说明 FF 的第 0 秒用途，再说明 SC/SCV/CH/PR/MAP/SB 的用途。

### 6.0b 输出原则

1. **旧版信息是底座，C 是默认成品格式**：无论 A/B/C，都必须保留素材、场景、人物位置、焦点、摄影机、动作、台词、光影、限制、衔接和段末状态这些信息。C 默认用导演轨合并表达；A 才展开旧版 11 字段；B 在 C/A 的基础上叠加高难导演执行增强。
2. **升级能力按需启用**：视频延长、FF 首帧、MAP/SB 调度、SCV 场景角度、CR 人群、PR 道具单实例锁、复杂运镜或动作戏增强只在命中条件时加入；普通段落不默认全压上。
3. **用户可见但不啰嗦**：在代码框外简短说明推荐模式和命中的增强项，例如 `推荐 C 导演轨纯净版；已启用 FF 首帧参考 / PR 道具单实例锁；未命中的增强不写入纯净提示词`。
4. **1900 字安全红线 / 2000 字出门闸门**：单个可投喂提示词单元默认控制在 1900 字以内；2000 是平台硬上限。输出前必须估算代码框内纯净提示词字数：`≤1900` 可交付；`1901-2000` 必须先压缩一轮再交付；`>2000` 先删除低收益后缀、管理话术和重复字段，不得压扁每镜必填字段。
5. **强度保护**：不得为了压字数删除素材用途与人物锚定、场景与人物位置关系、景深与焦点锁、摄影机行为锁、台词与语气、可执行光影、段末状态，以及命中的 CR/FF/MAP/SB/SCV/PR/视频延长关键约束。
6. **重复去除**：人物锚点、字幕水印、全局风格、光线连续性、人群不抢戏、道具不复制等全局约束只集中写一次；不要在 `素材`、每镜 `限制`、`通用后缀`、`Must Keep`、`Avoid` 中反复展开同一件事。
7. **台词不越权处理**：03 负责改台词，04 负责分配台词节拍，06 只保留原台词并检查时长。06 不得为了短视频节奏把长台词改短，也不得用“极快语速”掩盖时长不足。

### 6.1 增强触发规则

| 命中情况 | 默认处理 |
|---|---|
| 普通剧情段 / 常规连续段 | 推荐 C；使用导演轨纯净版，不强行加入高级增强 |
| 用户明确要求完整字段、审查漏项、1-3 镜头高精度控制 | 推荐 A；展开旧版 11 字段 |
| 同场景顺延，下一段像继续拍下去 | 建议视频延长启动句；默认 C，用户要完整字段时用 A |
| A 必须首帧 / B 建议首帧 | 加入 `首帧参考`，说明 FF 只锁第 0 秒 |
| 多人站位、轴线、内外侧、遮挡、摄影机安全区高风险 | 加入 `调度图参考` 或 SB 侧别约束；复杂时推荐 B 或 C |
| 核心场景、反打、回切、复杂空间或高穿帮场景 | 加入 `场景角度参考`，说明 SCV 只锁拍摄方向和空间透视 |
| 公共空间、街道、商场、车站、学校、医院、营业餐厅等需要路人真实感 | 加入 `人群密度`，写清人数、层次、类型、移动方向和遮挡规则 |
| 同一 PR 道具已在 SC/SCV/FF 可见且又引用 PR 外观图，或道具会被拿起/移动/跨段延续 | 加入 `道具单实例锁` |
| 一镜到底、复杂运镜、动作戏、强遮挡转场、强声音叙事 | 推荐 B；吸收导演执行块写法，并回填到 C 镜头轨或 A 详细字段 |

如果命中多个增强导致单组超过 1900 字，优先使用 C 导演轨纯净版，删除低收益后缀、压缩管理话术、合并重复约束，把字数留给镜头轨的关键控制；不得删除关键控制信息，也不得为了字数压扁单镜头内部控制。若 5-7 个完整镜头或高密度 8-10 个短镜头仍超过 2000 字，按镜头边界拆成连续 Seedance 单元，用上一单元 `段末状态` 承接下一单元第一帧。

### 6.0c 输出前双闸门

每个 Seedance 单元输出前必须先过六道闸门：

1. **节奏档位闸门**：短视频、竖屏短剧、红果、抖音、快手、小红书、视频号场景下，先继承或补判 `电影感中速 / 短视频中高密度 / 高密度动作或强钩子 / 慢节奏但高信息`，再按建议时长检查镜头密度。闸门目标是防拖沓，不是强行切碎镜头。10 秒以上只有 1-2 镜时，先判断是否命中慢节奏白名单；命中则保留原节奏并写清慢镜头功能，未命中则补动作标点、道具信息、反应、空间关系或段末钩子镜头。
2. **台词时长闸门**：有对白时，先估算中文对白自然说完所需时长，再决定建议生成时长。强情绪慢速/低声耳语按 3-4 字/秒，正常短剧对白按 4-5 字/秒，短视频偏快对白按 5-6 字/秒；超过 6 字/秒默认高风险，只允许争吵、慌乱、快嘴喜剧或抢话。估算时叠加停顿和表演补偿：逗号/顿号约 0.2 秒，句号/问号/叹号约 0.4 秒，省略号/情绪停顿约 0.6-1 秒，开口前后反应或动作承接至少 0.5-1.5 秒。
3. **字数闸门**：写完纯净提示词后估算代码框内字数。`≤1900` 通过；`1901-2000` 先做压缩；`>2000` 继续删除低收益后缀、管理话术和重复字段。禁止因为字数超限就压扁单镜头字段；若 5-7 个完整镜头或高密度 8-10 个短镜头仍超限，可以按镜头边界拆成连续单元，拆分点必须落在镜头之间，并用段末状态承接下一单元第一帧。
4. **可投喂语义闸门**：删除模型无法执行的交接话术。`接下一大分镜 / 接下一段 / 接分镜2 / 承接上一段` 必须改成可见动作、可见转接或段末状态；`9:16 / 13-15秒 / 分辨率 / 模式 / 任务类型` 必须移到代码框外。
5. **单组图片数量闸门**：每一组可投喂提示词 / 每个 Seedance 单元实际使用的图片参考总数最多 9 张，包含人物、场景、道具、首帧、调度图、位置参考图、SCV 角度图等所有图片；项目资产库可以超过 9 张，但单组代码框内不得引用超过 9 个 `@图片N` / `@ImageN`。超过时先保留当前段必需图片，把低风险参考合并、转文字约束或拆到下一组。
6. **素材编号一致性闸门**：镜头轨中出现的每个 `@图片/@视频/@音频` 编号必须已在 `素材锚定` 或 `参考/连续性声明` 中定义，且角色、场景、道具、首帧、调度图、视频、音频职责不能混用；发现图号混用时先修正或提示用户确认，不直接交付。

压缩顺序固定为：删除管理话术和解释说明 -> 删除默认不输出的低收益后缀项 -> 合并重复限制 -> 缩短空泛形容词 -> 缩短非末镜可见转接 -> 把同一控制点集中到 `硬锁 / 声音轨 / 段末状态` -> 用更短但完整的摄影机行为句和光影句表达同一控制。仍超过 1900 时，优先选择 C 导演轨纯净版；若 5-7 个完整镜头或高密度 8-10 个短镜头仍超过 2000，按镜头边界拆成连续的 4-15 秒单元，不在单个镜头内部硬拆。

### 6.2 基础衔接、边界推荐与强连续增强

每次把 04 分镜转成 Seedance 2.0 prompt 前，先做三层判断：

- **基础衔接层**：所有段落默认保留。输出仍按旧版满意样式写：`下一段衔接`、高收益 `通用后缀` 和 `段末状态`。`一致性约束` 默认不单列，人物与场景一致性由素材锚定、镜头限制和段末状态承接。
- **相邻段边界推荐层**：多段输出时，先判断 A-B、B-C、C-D 这些相邻段之间用什么连续方案，并在正式提示词前给用户一张简短建议表。
- **强连续增强层**：只有同场景连续、同场景隐含跳秒、切走后回到同一场景且故事状态未变化，或场景首现多人调度复杂时才叠加。切换新场景后默认不继承上一场点位表、MAP/SB、SCV 和视频延长逻辑。

相邻段边界推荐表默认格式：

```markdown
| 边界 | 场景关系 | 连续风险 | 推荐方案 | 理由 |
|---|---|---|---|---|
| A → B | 同场景顺延 / 同场景非顺延 / 新场景首现 / 换场景 | 高 / 中 / 低 | 视频延长 / 首帧图 + 调度图 / 只首帧图 / 只调度图 / 普通衔接 | ____ |
```

推荐规则：

1. **同场景顺延**：B 就是 A 的自然继续，动作、镜头方向、光线和道具状态都不应重置，优先建议 `视频延长`。
2. **同场景复杂空间**：不是自然延长，但第 0 秒构图、人物站位、窗内外/柜台内外/车内外关系容易穿帮，建议 `首帧图 + 调度图`。
3. **只锁起点**：主要风险在第 0 秒构图、人物初始位置或道具位置，后续动作不复杂，建议 `只首帧图`。
4. **只锁调度**：主要风险在走位、轴线、内外侧、遮挡或摄影机安全区，第 0 秒不复杂，建议 `只调度图`。
5. **场景首现多人调度**：新场景第一次出现且人物多、站位复杂、进出路线和遮挡关系需要组织，建议 `首帧图 + 调度图`。
6. **换场景普通段**：默认 `普通衔接`，不启用上一场视频延长、强连续空间、点位表、SCV 或 MAP/SB。

### 6.3 连续性与参考素材使用模式

| 使用模式 | 适用情况 | 是否使用上一段视频/尾帧 | 输出重点 |
|---|---|---|---|
| 普通衔接模式 | 常规段落、跨场景段落、蒙太奇、普通连续段 | 否 | 默认用 C 导演轨纯净版，正常写可见转接和段末状态 |
| 独立批量强连续模式 | 同场景强连续 / 回切强连续，但用户要批量生成，未上传上一段视频/尾帧 | 否 | 在 C 的 `参考/连续性声明`、场景锚定和镜头轨里写本视频第一帧状态、点位、正确限制和禁止错误点位；A 详细版可单列 |
| 首帧增强模式 | A 必须首帧或 B 建议首帧，且用户提供/生成了 FF 首帧图 | 否 | C 压入 `参考/连续性声明`；A 可单列首帧参考。FF 只作为第 0 秒画面参考，仍继续写动作过程、空间锁定、光影、限制和段末状态 |
| 调度增强模式 | 同场景多人走位、场景首现多人调度、轴线/内外侧/遮挡风险高 | 否 | C 压入 `参考/连续性声明` 和镜头轨；A 可单列调度图参考。写清 MAP/SB 用途、人物点位、移动路线、摄影机安全区和禁止错误站位 |
| 视频延长强连续模式 | 同场景顺延，下一段是上一段动作和镜头的自然继续 | 是 | 在纯净提示词最前面写视频延长启动句，再接对应的 C 导演轨纯净版或 A 标准字段化详细版结构 |

选择规则：

1. 默认走“普通衔接模式”，使用 C 导演轨纯净版；用户明确要求完整字段、1-3 镜头高精度控制或审查漏项时才用 A 标准字段化详细版。
2. 同场景顺延，A → B 像继续拍下去，优先建议“视频延长强连续模式”。
3. 同场景强连续但不适合视频延长，或需要批量独立生成 → 走“独立批量强连续模式”。
4. A 必须首帧或 B 建议首帧，且已有 FF 首帧图 → 走“首帧增强模式”；如果同时也是强连续段或首现多人调度，则叠加 MAP/SB 和禁止错误站位。
5. 多人走位、轴线、内外侧、遮挡、摄影机安全区是主要风险 → 走“调度增强模式”。
6. 场景首次出现且人物很多、站位复杂 → 即使不是强连续，也建议“首帧增强模式 + 调度增强模式”。
7. 换场景后默认回到普通衔接，不沿用上一场强连续空间、视频延长、点位表或 SCV。

### 6.4 视频生成方式

| 模式 | 适用情况 | 需要素材 | 提示词重点 |
|---|---|---|---|
| 文生视频 | 没有参考图，只有文字 | 无 | 角色、场景、动作必须写得非常具体 |
| 图生视频 | 有首帧/角色图/场景图/场景角度图 | @Image | 如果有 FF，FF 只作为第 0 秒画面；场景/SCV角度/角色/道具/MAP/SB 作为分工明确的辅助参考；仍要描述运动和段末状态 |
| 首尾帧 | 有开始和结束状态 | @Image 起始 + @Image 结束 | 明确从 A 状态过渡到 B 状态 |
| 参考生视频 | 有多张图/视频/音频参考 | @图片/@视频/@音频（兼容 @Image/@Video/@Audio） | 明确每个素材的用途 |
| 视频延长 | 同场景顺延，有上一段生成结果作为 @Video | @Video | 将上一段成片自然延长 X 秒，不重置角色、场景、光线、镜头方向和道具状态 |
| 视频改写 | 有旧视频想重做 | @Video | 明确保留什么、改变什么 |

如果平台不支持某模式，不要强行输出该模式；改用最接近的可用模式。

普通衔接模式也可以使用文生视频、图生视频或参考生视频；它保留旧版“下一段衔接 / 通用后缀 / 段末状态”，只是不额外强制调度图和点位表。

6. 角色一致性优先时，使用参考图，不要只用纯文生视频。

## 八、04 分镜字段到 Seedance prompt 的转换

### 04 字段

```text
焦段：
光圈：
景深与焦点锁：
机位：
构图：
运镜：
主体动作/表情：
台词与语气：
限制：
```

Seedance 最终提示词默认要在 04 字段基础上补齐：

```text
光影：
下一段衔接：
```

### 转换方式

```text
焦段 + 光圈        → 画面质感与空间感
机位 + 构图        → 摄影机位置和主体关系
运镜              → camera movement
主体动作/表情      → prompt 主体、可见动作、微表情、口型动作、呼吸、身体反应、情绪弧线
台词与语气          → 原台词、说话者、语气、音量、语速；无对白时写明无对白
限制              → must keep / avoid，包含情绪过度表演禁止项
光影              → 光源来源、主光方向、亮区、暗区、脸部受光、轮廓光/背景分离、色温、明暗反差、丁达尔/雾化光束（如有）
下一段衔接          → 段末角色姿态、视线、道具、光线、镜头方向
```

默认不要把这些字段全部揉成一整段自然语言。Seedance 最终提示词要保留字段化结构，字段内可以使用自然语言写清画面。只有用户明确要求“自然语言版 / 更短版 / 不要字段”时，才输出整段自然语言。

### 光影字段写法

Seedance 最终提示词仍只保留一个 `光影：` 字段，不新增复杂表格。字段内部必须尽量写成一到两句可执行布光说明，优先包含：

```text
光源来源：窗光 / 台灯 / 霓虹 / 路灯 / 屏幕光 / 烛光 / 门缝光。
主光方向：从左前 / 右前 / 左后 / 右后 / 顶部 / 背后 / 侧面进入。
亮区：人物哪半张脸、哪只手、哪个道具、背景哪一块被照亮。
暗区：前景、背光面、走廊、墙面、背景哪一块保持低照度。
轮廓与分离：是否有轮廓光、逆光、发丝光、肩线高光。
色温与反差：冷白 / 暖黄 / 霓虹混色；脸部明暗比约 1:2 / 1:3 / 1:4。
空气与光束：薄雾、尘埃、雨雾、丁达尔光束；写清从哪里打入、穿过什么、落在哪。
禁止项：禁止整体提亮、禁止新增无来源面光、禁止夜景变白天、禁止双脸全亮。
```

推荐句式：

```text
光影：右侧台灯作暖色主光，只照亮人物右半张脸和手中道具；左侧脸颊与背景走廊保持低照度；左后方冷白轮廓光勾出头发和肩线，脸部明暗比约 1:3，禁止整体提亮。
光影：窗外斜射冷光从画面左侧打入，穿过薄雾形成轻微丁达尔光束，光束落在茶几和人物手背；人物正脸保持半明半暗，背景墙压暗，只保留台灯暖色小高光。
```

### 情绪表演字段写法

Seedance 最终提示词不要只写“角色很悲伤 / 很愤怒 / 很害怕”。强情绪镜头必须把情绪写成可见表演过程，并把“不要怎么演”写进 `限制`。

```text
主体动作/表情：角色先保持平静，眼神轻微下垂，眨眼变慢，嘴唇抿住又松开，喉咙轻轻吞咽，呼吸变浅，嘴角短暂轻颤，口型轻动。
台词与语气：角色低声说：“我知道了。”
限制：不要流泪，不要夸张哭脸，不要皱眉过度，不要突然崩溃大哭，不要大幅度低头捂脸。

主体动作/表情：角色下颌慢慢绷紧，鼻翼轻动，手指收紧但没有挥动，停顿半秒，口型先抿住。
台词与语气：角色压低声音说：“你再说一遍。”
限制：不要咆哮，不要夸张瞪眼，不要砸东西，不要突然冲向对方，保持压住怒气的状态。
```

常用禁止项：

```text
悲伤：不要假哭、不要立刻流泪、不要夸张哭脸、不要跪地崩溃；如果剧情需要大哭，必须先写克制到失控的过程。
愤怒：不要咆哮、不要过度瞪眼、不要乱挥手、不要砸东西，除非剧本明确爆发。
害怕：不要尖叫、不要夸张后仰、不要乱跑、不要双手抱头，除非类型明确需要。
心动：不要傻笑、不要夸张脸红、不要突然贴近对方、不要偶像剧式过度表情。
隐忍：不要面无表情到僵硬，必须保留细微泄露，如眨眼变慢、喉咙吞咽、手指收紧。
```

表情强度阶梯：

```text
0 级：表面平静，只有视线、眨眼、呼吸或手指轻微变化。
1 级：微表情泄露，抿唇、吞咽、嘴角轻颤、下颌绷紧。
2 级：情绪压上来，声音变轻/变硬，脸部肌肉开始失控，身体重心变化。
3 级：压不住，眼泪、颤音、肩膀轻颤、短促吸气出现。
4 级：明确爆发，大哭、怒吼、尖叫、崩溃；必须有 1-3 级铺垫，除非剧本要求突然爆发。
```

大哭写法示例：

```text
主体动作/表情：她先愣住半秒，眼神失焦，眨眼变慢，嘴唇用力抿住；她试图吸气说话却发不出声，眼眶迅速蓄泪，第一滴泪滑下，肩膀开始轻颤，口型几次张合后才失声。
台词与语气：无对白，只有断续的抽气声。
限制：不要第一帧就满脸泪水，不要张大嘴夸张嚎哭，不要跪地崩溃，不要大幅度捂脸遮住表情；哭泣必须从克制到失控逐步发生。
```

## 九、时长与节奏写法

Seedance 2.0 单段 prompt 必须控制在 4-15 秒。总时长、画幅、模式、参数建议默认放在代码框外；纯净提示词正文优先使用 `镜头1 / 镜头2 / 镜头3` 的顺序推进，不默认写 `0-3s / 3-6s` 这类硬时间戳。

### 代码框外写法

```text
【Seedance 段 S02】
建议生成时长：8 秒
画幅：9:16
任务类型：多模态参考
节奏策略：不用硬时间戳；按镜头顺序推进，镜头1承接状态，镜头2完成动作与台词，镜头3作为段末钩子。
```

### 纯净提示词正文写法

```text
【镜头1】
建立环境和角色位置，承接上一段末尾状态。

【镜头2】
角色执行核心动作，情绪开始变化。

【镜头3】
完成情绪命中点或动作结果，保留段末姿态。

节奏分配：
镜头1较短，只负责建立状态；镜头2占主体时长；镜头3略微放慢，留下段末钩子。
```

### 软时间节奏可用场景

以下情况可以写软节奏，但必须表述为节奏参考，而不是模型必须精确执行的硬时间码：

```text
快切/蒙太奇：连续 6 个短镜头，每镜约 0.5-1 秒，动作音和画面切点同步，最后一镜稍停。
广告卡点：前三个镜头按音乐强拍快速切换，产品出现时节奏放慢半拍。
12-15 秒复杂文戏：前段建立关系，中段完成台词交锋，后段留角色反应与段末状态。
动作戏：前半段连续追逐，后半段一次撞击结果和角色反应；不要精确写死每一秒。
```

### 短视频镜头密度继承

如果目标平台是短视频、竖屏短剧、红果、抖音、快手、小红书或视频号，06 在转换 04 分镜时必须执行“时长 × 节奏档位 × 镜头密度”检查：

| 节奏档位 | 4-6 秒 | 7-9 秒 | 10-12 秒 | 13-15 秒 |
|---|---:|---:|---:|---:|
| 电影感中速 | 1-2 镜 | 2-3 镜 | 3-5 镜 | 4-6 镜 |
| 短视频中高密度 | 2 镜 | 3-4 镜 | 4-6 镜 | 6-8 镜 |
| 高密度动作或强钩子 | 2-3 镜 | 4-5 镜 | 5-7 镜 | 7-10 镜 |
| 慢节奏但高信息 | 按功能保留 | 按功能保留 | 可 1-2 镜但必须说明慢镜头功能 | 可 1-2 镜但必须说明慢镜头功能 |

- 10 秒以上只有 1-2 个镜头时，代码框外必须提示“慢节奏风险”。
- 只有强情绪压迫、重要台词交锋、单镜头调度、反派登场、仪式感、高级悬疑凝视、同场景视频延长或用户指定电影感长停顿，才允许 10-15 秒保留 1-2 个镜头。
- 命中白名单时，纯净提示词必须写清慢镜头功能；未命中白名单时，优先补动作标点、道具信息、反应镜头、空间关系镜头或段末钩子镜头。
- 1900 字压缩时，先删低收益后缀、合并重复限制和空泛形容词，不得吞掉 04 已确认的镜头数量、台词节拍和段末钩子。若镜头密度合格后导致单元超过 2000 字，不删功能镜头，也不压扁单镜头字段；先改用 C 导演轨纯净版，仍超限则按镜头边界拆成连续单元。

### 时长红线

1. 单段时长不得低于 4 秒，不得高于 15 秒。
2. 小于 4 秒的镜头需求必须合并到相邻段，或扩展为 4 秒以上的完整动作。
3. 大于 15 秒的镜头需求必须拆成多个 Seedance prompt 包。
4. 默认不要在纯净提示词里写绝对秒数；如果用户明确要求时间戳，必须标注为“节奏参考，非精确控制”。
5. 不要在一个 8 秒 prompt 里写 5 个以上复杂动作。
6. 不要频繁切换场景。
7. 不要让两三个角色在同一镜头里同时做复杂动作；多人调度要写主次。
8. 如果需要多镜头剪辑，用 `镜头1 / 镜头2 / 镜头3` 或 “切到” 明确，不要让模型猜。
9. 如果要单镜头，明确写 “单一连续镜头 / single continuous shot”。
10. 精确剪辑点、绝对卡点和最终节奏，交给后期剪辑时间轴完成。

### 台词时长闸门

06 只做台词可执行性检查，不改写台词原文。输出建议时长前必须估算：

```text
台词基础时长 = 中文字数 ÷ 目标语速
停顿补偿 = 逗号/顿号约 0.2 秒，句号/问号/叹号约 0.4 秒，省略号/情绪停顿约 0.6-1 秒
表演补偿 = 开口前反应、说完后反应、视线变化、动作承接，至少 0.5-1.5 秒
最低建议时长 = 台词基础时长 + 停顿补偿 + 表演补偿
```

语速参考：

```text
强情绪慢速 / 古装压迫 / 低声耳语：3-4 字/秒
正常短剧对白：4-5 字/秒
短视频偏快对白：5-6 字/秒
超过 6 字/秒：高风险，只允许争吵、慌乱、快嘴喜剧或抢话
```

处理顺序：

1. 当前建议时长不足但不超过 15 秒时，优先延长建议时长。
2. 超过 15 秒仍放不下时，按台词自然停顿、问答回合或情绪转折拆成连续 4-15 秒单元。
3. 必须缩短台词时，建议回 `03-dialogue-expert.md` 精修；06 不得擅自删字、换句或改变角色语言。
4. 短视频平台可以快剪、快推进，但不得用失真的过快语速解决台词过长。

代码框外可简短输出：

```text
台词时长检查：本段对白约 X 字；建议语速 X 字/秒；自然说完最低约 X 秒；当前建议时长 X 秒；结论：可执行 / 偏紧 / 不可执行；处理：保持 / 延长 / 拆分 / 回 03 精修。
```

## 十、Seedance 输出格式（字段化纯净投喂优先）

每段大分镜转换后，默认必须先输出“可直接投喂 Seedance 2.0 的字段化纯净提示词”。这段内容必须能被用户整段复制到 Seedance / 豆包视频 / 火山方舟的视频生成文本框中。

字段化纯净提示词不是表格，也不是 JSON，而是用清晰字段组织的自然语言提示词。默认要比整段自然语言更可检查、更不漏项、更适合连续成片。

### 10.0 代码框边界规则（必须遵守）

输出 Seedance 提示词包时，必须把“给用户理解确认的投喂信息”和“真正喂给视频模型的提示词正文”分开。

代码框外必须放：

- `【Seedance 段 Sxx】`
- `段号：Sxx`
- `时长：X秒`
- `画幅：21:9 / 16:9 / 9:16`
- `模式：文生视频 / 图生视频 / 参考生视频 / 首尾帧 / 视频延展`
- 参数建议、素材映射表、风险提示、说明文字

代码框内只能放用户要复制给 Seedance / 豆包视频 / 火山方舟的视频提示词正文。C 导演轨纯净版默认可从 `特别注意：` 或 `素材锚定：` 开始；A 标准字段化详细版可从 `素材：` 开始。不要把 `【Seedance 段 Sxx】`、`时长`、`画幅`、`模式` 写进代码框。

正确格式：

````markdown
## S01A｜10秒｜维修店主板验尸

**投喂信息：** 段号 S01A｜时长：10秒｜画幅：21:9｜模式：参考生视频

```text
素材：使用 @Image6 作为地下手机维修店环境参考，使用 @Image22 作为烧穿手机主板参考。
事件交代：老板在地下维修店检查一块烧穿的手机主板，现实宣判从主板开始。
场景：内景，地下手机维修店，夜晚，暖黄台灯与冷蓝楼梯光交错。
...
```
````

错误格式：

```text
【Seedance 段 S01A】
时长：10秒
画幅：21:9
模式：参考生视频
素材：使用 @Image6 ...
```

如果用户明确要求“一键复制完整包，包含元信息”，才允许把这些元信息放进代码框；否则默认不允许。

### 10.1 默认输出顺序

```text
1. 投喂信息（代码框外，给用户确认）
2. 字段化纯净投喂提示词（代码框内，必须可直接复制给模型）
3. 参数建议（单独给，不混入提示词正文）
4. 素材映射 / 管理信息（可选，放在后面）
5. 下一段衔接说明（可选，放在后面）
```

投喂信息中如果引用 ST/CL/NP，必须同时写出自然语言摘要，例如：

```text
风格来源：ST001 港风写实 / CL001 暖黄侧光高反差 / NP001 防韩风网红脸。
代码框内处理：不写这些编号，直接写“90年代香港写实剧集质感、暖黄色侧光、柯达金200胶片颗粒、生活化亚洲面孔，避免冷白皮、尖下巴、韩式精修、网红脸”。
```

### 10.2 纯净投喂提示词格式

默认使用 `C 导演轨纯净版`。C 必须覆盖旧版 11 类控制信息，但不逐行展开表格字段；它把焦段、光圈、景深、机位、构图、运镜、动作、台词、光影、限制和衔接合并到镜头轨里。只有用户明确要求完整字段、1-3 镜头高精度控制、镜头漏项审查或教学拆解时，才使用 `A 标准字段化详细版`。

公共空间启用 `CR` 人群/群演调度卡时，在 C 的 `场景锚定` 或 `硬锁` 中写清人群密度；没有人群需求时不强行增加人群字段。启用视频延长时，在 `素材锚定：` 或 `素材：` 之前先写视频延长启动句，但不得替代后续完整提示词结构。

1. **素材引用**：优先使用官方 `@图片1/@图片2/@视频1/@音频1`，兼容 `@Image1/@Video1/@Audio1`；分别说明每个素材只参考什么、不参考什么。没有素材时写成文生视频描述，不要凭空写引用。
1.1 **人物锚定**：多主体或跨镜头复用时，先用固定句式定义 `将 @图片N 中的[身份/外观/服装]定义为 <角色名>`；多人物可在同一句连续定义。锚定句只写定义，不追加说明；后续镜头直接用 `<角色名>` 指代。不要裸写 asset ID 或让 `@图片N` 直接接动词。
1.2 **任务类型**：在代码框外标注 `任务类型：多模态参考 / 编辑视频 / 延长视频 / 组合任务`。编辑视频用 `严格编辑 @视频N`；延长视频用 `向后延长 @视频N` 或本技能自然延长启动句，不写“参考 @视频N”。
2. **生成目标**：风格、情绪目标和本段生成意图；视频时长、画面比例、生成模式默认放在代码框外的投喂信息里，除非平台要求写进 prompt 正文。Seedance 2.0 单个提示词单元必须是 4-15 秒。
2.1 **风格转译**：如果 04/05 提供 ST/CL/NP，必须在纯净提示词的 `风格继承`、`场景`、`光影`、`限制` 或 `通用后缀` 中展开为自然语言；可以写 `风格继承：90年代香港写实剧集质感、生活化亚洲面孔、暖黄高反差胶片颗粒`，不可以写 `风格继承：ST001/CL001/NP001`。
3. **字数上限**：单个 Seedance 提示词单元默认控制在 1900 字以内；1900 字是安全红线，2000 字是平台硬上限。输出前必须估算代码框内纯净提示词字数；1901-2000 先压缩，超过 2000 先删低收益后缀、管理话术和重复字段，不得牺牲每镜必填字段和命中增强来换字数。若 5-7 个完整镜头或高密度 8-10 个短镜头仍超限，按镜头边界拆成连续单元，不在单个镜头内部硬拆。
4. **大分镜前置信息**：事件交代、场景、人物位置关系、情绪基调。
4.1 **人群密度**：仅在 04 或 05 明确启用人群/路人/群演时输出，必须写清前景、中景、远景人数范围、人群类型、移动方向和遮挡规则；不要只写“人很多 / 有路人 / CR001”。
4.2 **道具单实例锁**：仅在同一 PR 道具同时出现在 SC/SCV/FF 和 PR 参考图中，或道具会被拿起/移动/跨段延续时输出。必须写清“PR 不是新增道具，只修正已存在那一件道具的外观”，并写数量限制、绑定位置、移动后原位置变化和禁止第二个同款道具。
5. **平台节奏继承**：节奏档位判定、本段钩子、信息增量、情绪推进、呼吸镜头功能、段末继续看的理由；如果没有平台要求，可写成“按剧情节奏自然推进”。节奏档位管理说明放代码框外，纯净提示词只体现执行结果。
6. **分镜字段**：C 模板每条镜头轨必须按 `N｜镜头功能标签｜镜头/焦点｜动作/台词｜光影/转接` 写。`镜头/焦点` 承载焦段、光圈、景深、机位、构图、运镜、焦点起点/落点和禁止跑焦对象；`动作/台词` 承载可见动作、微表情、呼吸、身体细节、原台词、说话者、语气、音量、语速和口型；`光影/转接` 承载光源、方向、亮暗区、限制和可见转接。A 模板才逐行列出 `焦段 / 光圈 / 景深与焦点锁 / 机位 / 构图 / 运镜 / 主体动作或表情 / 台词与语气 / 光影 / 限制 / 下一段衔接`。
6.1 **镜头功能标签随剧情生成**：镜头轨第一列是本镜功能，不是固定套话。必须根据本段剧情和信息增量生成，例如“误导开场 / 证据露出 / 情绪反咬 / 道具异变 / 选择逼近 / 威胁落点”。不得固定套用“开场钩子 / 动作打断 / 危险规则 / 旧伤暴露 / 关系反转 / 段末异变”。
7. **时长与节奏组织**：整段总时长 `建议生成时长：8 秒` 默认放在代码框外，不写进纯净提示词正文。正文默认按 C 的 `镜头轨` 推进，A 才按 `镜头1 / 镜头2 / 镜头3` 字段推进；快切、蒙太奇、广告卡点可写“前段快速推进 / 中段压迫 / 末镜稍停”这类软节奏，但不要把硬时间戳当成模型精确控制。
7.1 **镜头密度保护**：短视频平台下，06 必须按 04 的 `节奏档位判定` 和 `镜头密度判断` 保留合理镜头数量。`短视频中高密度` 和 `高密度动作或强钩子` 不得被压回 1-2 镜；只有命中慢节奏白名单并写清慢镜头功能时，才允许 10 秒以上保留 1-2 个镜头。压缩到 1900 字以内时，不得通过删除功能镜头来达成；超过 2000 字时先删低收益后缀和重复字段，仍超限则按镜头边界拆成连续单元。
7.2 **台词时长保护**：有对白时，必须先按原台词字数、目标语速、停顿和表演补偿判断建议时长是否足够。若台词无法以 ≤6 字/秒自然说完，不得强行写“语速很快”；优先延长到 15 秒内，仍超出则按台词节拍拆连续单元，或建议回 03 精修。
8. **台词与语气**：有对白时必须独立写成 `台词与语气：` 字段，写入原台词、说话者、语气、音量、语速和口型要求；无对白时写明“无对白”。这一字段不能塞回 `主体动作/表情`，也不得在 06 中擅自改写原台词。
9. **保持项**：角色身份、脸型、发型、服装、体态、场景、道具、光线、位置关系。
10. **禁止项**：字幕、水印、文字、换脸、换装、生成 BGM、改变场景、情绪表演用力过猛等。无人群需求时写禁止额外人物、路人、群演；启用人群时不要禁止路人，而要限制“路人不得看镜头、不得遮挡主角脸部和关键动作、不得抢戏、不得同脸复制”。
11. **高收益通用后缀**：每个可投喂提示词末尾默认保留 `音效说明 / 道具约束 / 文字约束 / 光线约束 / 风格约束`，`段末状态` 单独保留。不要省略 `道具约束`；如果本段没有关键道具，也写成“无关键道具，不新增或复制无关道具”。`一致性约束 / 节奏约束 / 画面规格` 默认不输出：一致性并入素材锚定和具体镜头限制，节奏并入镜头节奏和段末状态，画面比例/模式放代码框外投喂信息；只有用户明确要求时才追加。

### 10.2.0 重复去除规则

默认模板保留强字段格式，但同一控制点只集中强调一次：

1. **人物锚点只在 `素材` 强调一次**：按固定句式 `将 @图片N 中的[身份/外观/服装]定义为 <角色名>` 定义；后续每镜不再反复写完整人物一致性，只在本镜有换装、受伤、拿道具等风险时补充。
2. **文字风险只在通用后缀或具体文字镜头写一次**：无字幕、无水印、无 Logo、无随机文字默认放入 `文字约束`；手机、证件、纸条、招牌等必须出现文字时，本镜单独写允许文字。
3. **风格只写一次**：ST/CL/NP 转成自然语言后，优先放在 `素材` 或 `风格约束`；每镜 `光影` 只写当前真实光源、主光方向、亮暗关系和反差，不重复整套风格词。
4. **人群调度不删但集中写**：启用 CR 时，`人群密度` 必须完整写人数规模、前中远景分布、人群类型、移动方向、遮挡规则；`限制` 或 `人群约束` 只补“不看镜头、不抢戏、不长时间遮挡主角、不同脸复制”等关键禁止项。
5. **道具单实例锁不多处重复**：如启用 PR 单实例锁，`道具单实例锁` 字段写完整绑定关系、PR 用途、数量和移动后变化；本镜 `限制` 只写与当前动作相关的风险；末尾 `道具约束` 仍要用一句话锁定数量、位置和移动后原位置变化。
6. **衔接可短但必须可见**：非最后一镜的 `下一段衔接` 写成具体动作转接或视线/道具/光线变化，例如“剑鞘从右侧切入画面”“视线下移到腰侧血迹”“裂光拉低两人视线”；最后一镜只写可继承的段末画面状态。不要写“接分镜2 / 接下一大分镜 / 接下一段”。

### 10.2.0b 纯净投喂去管理话术规则

最终可复制给 Seedance / 豆包视频 / 火山方舟的代码框，只写当前视频模型需要生成的画面、动作、声音、保持项和具体可见禁止项。内部判断、模板说明、未启用项、无则删除说明、上一场不用什么等管理话术必须放在代码框外，或只留在本 reference 的规则层。

代码框内禁止出现：

- `无 FF 时删除本行`、`无调度图时删除本行`、`无 SCV 时删除本行`、`无需求时删除本行`、`无风险时删除本行`。
- `未启用 FF`、`未启用 SCV`、`未启用强连续调度图`、`不启用上一场视频延长`。
- `不使用上一场茶餐厅的点位、调度图或视频延长`、`不继承上一场点位表`、`换场景后默认普通衔接`。
- `FF 不替代角色图`、`SCV 不替代场景母版`、`强连续增强块不是新格式` 这类解释性说明。
- `如果没有则删除`、`没有则不写`、`普通段不强制` 这类模板编辑指令。

正确处理方式：

1. **未启用的增强字段直接不输出**：没有 FF 就不写 `首帧参考`；没有 SCV 就不写 `场景角度参考`；没有 CR 就不写 `人群密度`；没有 PR 复制风险就不写 `道具单实例锁`。但 `—— 通用后缀 ——` 的高收益项仍默认保留，其中 `道具约束` 必须写成当前段的道具保持/禁止新增规则。
2. **换场景只省略强连续资产**：切换新场景时，不在纯净提示词里解释“不要继承上一场”。直接写当前新场景、当前人物位置、当前光影和当前动作。
3. **空场景母版 + 人群用正向描述**：场景字段只写“@图片1 只参考空间结构、店铺位置、灯光和透视”；人群另用 `人群密度` 写当前段可见人群，不写“不继承空无一人状态”。
4. **职责分离说明放代码框外**：FF、SCV、MAP/SB、PR 的“只参考什么、不参考什么”可以写进纯净提示词，因为这是给模型看的素材用途；但“它不替代什么”“没有就删除”等解释放代码框外。
5. **禁止项只写可见错误**：可以写“禁止第二部同款手机”“禁止额外人物”“路人不得遮挡主角脸部”；不要写“本段未启用道具锁”“本段不用上一场调度图”。
6. **压字数先删低收益项**：触发 1900 字安全红线时，第一优先级删除管理说明、低收益后缀、重复限制和空泛形容词；不得删除景深、摄影机行为、台词、光影、段末状态和命中的增强约束。超过 2000 字时不得压扁单镜头字段；若 5-7 个完整镜头或高密度 8-10 个短镜头仍超限，按镜头边界拆成连续单元，并用上一单元段末状态承接下一单元第一帧。

### 10.2.1 小道具朝向锁定规则

Seedance / Sora / 其他视频模型生成手机、照片、证件、信封、戒指、硬币等小道具时，常会自动把信息面转向镜头，造成穿帮。凡是提示词中出现有正反面的关键道具，必须在 `主体动作/表情` 或 `限制` 字段写清朝向。

手机类道具尤其必须写：

```text
限制：手机背面朝镜头，黑色玻璃背板和斜排双摄清晰可见；屏幕正面朝向角色手心/桌面/身体，不可见；禁止把手机背面生成成屏幕、微信界面、发光 UI 或随机文字。
```

如果剧情必须展示手机 UI，则改写为：

```text
限制：手机屏幕正面朝镜头，只允许显示指定微信界面和指定中文/数字；手机背面不可见；禁止随机文字、错误联系人、错误电量、正反面同时都是屏幕。
```

适配规则：

1. 只要分镜中出现“拿出手机 / 举起手机 / 手机落地 / 手机在桌上 / 手机震动”，都要写手机朝向。
2. 如果画面不需要看屏幕，默认让屏幕朝向手心、桌面或角色身体，不要让屏幕自动朝镜头。
3. 如果要看屏幕，必须写清屏幕上允许出现的唯一文字和 UI。
4. 关键道具的段末状态也要写朝向，例如“段末手机背面仍朝镜头，屏幕朝向小雅手心”。


---

纯净提示词禁止包含：

- 表格。
- JSON 参数。
- `【Seedance 段 Sxx】`、`段号：Sxx`、`时长：X秒`、`画幅：21:9`、`模式：参考生视频` 这类给用户确认的元信息，除非用户明确要求一并复制。
- “本段目标 / 素材映射 / 参数建议”这些管理标题；但分镜内部的 `下一段衔接：` 字段必须保留。
- `全局控制：9:16，13-15秒` 这类把画幅、时长、分辨率、模式、任务类型混入正文的写法。`全局控制` 只能写画面控制。
- `接下一大分镜 / 接下一段 / 承接下一段 / 接分镜2` 这类模型不知道具体内容的交接语；必须改写成可见画面状态或动作转接。
- 解释性文字，如“以下是提示词”“你可以复制”。
- 多个备选版本，除非用户明确要求。
- 未启用项、无则删除说明、换场景不用什么、上一场不继承什么、某增强不替代什么等流程管理话术。

纯净提示词允许包含：

- 视频延长启动句，如 `使用 @视频1 作为上一段成片视频，只从上一段末尾继续自然延长 X 秒，接入本段动作。不重置角色身份、服装、发型、场景空间、光线方向、镜头方向和道具状态。`
- `【大分镜 B01】`、`【分镜 1】` 这类投喂用结构标题。
- `—— 通用后缀 ——` 这类投喂用约束分隔。
- 字段化冒号行，如 `焦段：`、`光圈：`、`限制：`。

模板生成说明：

- 下面模板是字段结构示例，不代表每行都要输出。
- `特别注意` 只放最高优先级画面/摄影/表演红线，例如全程手持、人物静止、不继承参考图构图、严格按镜头轨重新构图；不要在这里写声音要求。
- `参考/连续性声明` 只在命中时输出：参考图只取人物关系或环境不继承构图、承接上一段动作但不用尾帧首帧、视频参考但不是延长、FF/MAP/SB/SCV/PR 的“只参考什么 / 不参考什么”都放这里。
- `风格锁定` 只在用户或资产给出 CG、UE5、MetaHuman、动捕、3A 游戏过场、实时渲染、禁止真人质感等风格要求时输出；普通真人写实段不强行输出。
- 只有启用视频延长时，才在纯净提示词最前输出视频延长启动句；视频参考但不是延长时，写进 `参考/连续性声明`。
- C 默认把 FF 首帧、MAP/SB 调度、SCV 场景角度、PR 单实例职责压进 `参考/连续性声明`；A 详细版或用户明确要求完整字段时，可单列 `首帧参考 / 调度图参考 / 场景角度参考 / 道具单实例锁`。
- 只有启用 CR 人群/路人/群演调度时，才输出 `人群密度：`。
- 只有存在同一 PR 道具复制风险或关键道具跨段移动风险时，才写道具单实例锁；C 压进 `参考/连续性声明` 和 `硬锁`，A 可单列增强字段；A 的 `—— 通用后缀 ——` 内 `道具约束` 仍是高收益默认项，必须按当前段写成道具保持/禁止新增规则。
- 未启用的字段直接不写，不要在纯净提示词中写“未启用 / 无则删除 / 不使用上一场 / 不继承上一段”。
