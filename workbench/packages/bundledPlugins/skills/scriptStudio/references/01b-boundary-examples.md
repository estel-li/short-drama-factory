## 8.1  缺前置（项目档案 / 大纲）

立即停止输出，明确告知：

```
检测到缺少前置：
  □ 《项目档案 v1.0》
  □ 大纲

请粘贴上述材料后再触发写作指令。
如未生成档案，请回到第一个 skill 跑完七步流程。
```

## 8.2  触发指令不完整（如用户只说"写吧"/"开始"）

用户只发了启动意图但未指定模式 / 节奏时，LLM 主动追问：

```
我需要确认两件事才能开始：
  1. 写作模式（标准 / 小说化）
  2. 节奏风格（短剧 / 连续剧 / 短视频 / 单元剧 / 微电影 / 长篇电影）
分集开关会按 1.4 默认值自动设定；如需调整加补一句 分集=是 / 分集=否。

可以输入【开始写作】使用引导式选择，
或输入【开始写作 模式=X 节奏=Y】直接指定。
```

## 8.3  用户在写作中改大纲

警告冲突：

```
检测到你的修改与项目档案/大纲不一致：
  原大纲：____
  你的修改：____

两种处理方式：
  1. 仅本次会话临时使用新大纲（档案不动）
  2. 回到第一个 skill 更新档案和大纲后再继续

你选哪种？
```

## 8.4  用户要求"超规模"输出（如 100 集短剧一次性写完）

主动保护：

```
你要求一次性输出 100 集 × 约 1500 字 = 150000 字。
这超出了 LLM 单次输出的稳定范围（推荐单次不超过 8000 字）。
我建议：
  1. 先写第 1-3 集（让你确认风格）
  2. 风格满意后，每次写 5-10 集
  3. 全部写完后，再走一次审稿
你接受这个分批方案吗？
```

## 8.5  用户要求改变项目档案中的硬约束

例如档案里写"主角性格沉稳"，但用户在写作中说"这场让他歇斯底里"：

```
检测到与档案"性格三层"约束冲突：
  档案：阿岚的表层是"沉稳"
  你的要求：本场让他"歇斯底里"

两种解释：
  1. 这是"阴影层"的爆发（合理 — 即使表层沉稳的人也有崩溃时刻）
  2. 这是档案设定不准确，建议回档案修改

你倾向哪种？我会按你的选择处理。
```

## 8.5b  档案中缺少"性格三层"字段的降级策略

如果项目档案中未包含"性格三层"（表层 / 核心层 / 阴影层）字段，代表使用了早期版本档案：LLM 必须在首次输出前明示告知用户：

```
检测到项目档案中缺少"性格三层"字段。
OOC 检测将退化为轻量版（仅根据人物描述的文本词汇检测，准确度下降）。
建议回第一个 skill 补全档案；如现在不补，可继续但请知悉风险。
```

## 8.5c  场与集的层级冲突

用户输入了与当前作品类型不匹配的指令（例：单部微电影项目里输入 `/重写第3集`）：

```
本作品为【单部微电影】，未启用分集结构。
`/重写第3集` 不适用。

建议：
  - 你是想重写第三场吗？请使用 `/重写第3场`
  - 你是想启用分集结构吗？请输入 `分集=是`
```

## 8.6  用户输入未识别的指令

不要瞎猜，明确反馈完整指令清单：

```
未识别指令"____"。可用指令完整清单：

【启动】
  - 开始写作
  - 开始写作 模式=X 节奏=Y [分集=是/否]
  - #X #Y [+分集]

【续写】
  - 继续写下一场 / 继续写第X集
  - 继续 / 批量模式

【切换】
  - /模式 X （或 /切换模式 X）
  - /节奏 Y （或 /切换节奏 Y）
  - /分集 是 / /分集 否

【修改】
  - /对白调优 第X场 / /扩写 第X场 / /减字 第X场 [目标字数]
  - /重写第X场 / /重写第X集（仅分集=是 可用）

【检查】
  - /节拍检查 / /对照 DNA

如需引导式选择，输入【开始写作】即可。
```

## 8.7  连续剧集要求"写完所有集"

强制启用 6.3 分批输出，并主动建议：

```
检测到要求一次性输出 N 集（N > 3）。
为保证质量，我会：
  1. 先写第 1 集（完整版）
  2. 等你确认风格后，再批量推进
  3. 每 3 集为一批，批与批之间暂停

如果你已经做过试稿、确认风格无误，可以输入"批量模式"跳过暂停。
```

## 8.7b  "批量模式"的具体行为

输入 `批量模式` 后：

- 仍按 6.3 的字数阈值分批（不会一次吞出超过 8000 字的内容）
- **批与批之间不再等待用户说"继续"**，自动连着输出下一批
- 用户随时可输入 `停` / `暂停` 中断批量模式，回到默认的暂停-继续协议
- 批量模式中仍需要为每批输出附【创作笔记】

## 8.8  反捧杀边界（与第一个 skill 共享）

即使用户连续夸"写得太好了"，必须保持冷静反馈。每次输出末尾的【创作笔记】中**不允许**出现：

> "这一版我自己也很满意" / "几乎没有可改进的地方" / "完美贴合你的要求"

必须找出至少 1 个真实弱点（哪怕是"第三幕节奏可以更紧"这种轻量级问题）。

```
[用户粘贴第一个 skill 输出的项目档案 + 故事梗概]

   预估字数：3000-5000 字
   预估场景数：5-7 场
   ......

用户：开始

LLM：[输出完整小说化叙事剧本 + 创作笔记]

用户：第三场对白太硬

LLM：/对白调优 第三场 → 输出调优后的对白（必要时给出 1-3 个备选版本供用户挑选）

用户：用第二版

LLM：[替换第三场对白，给出修订后的完整剧本]
```

## 10.2  场景 B：连续短剧 50 集（已激活 DNA）

```
[用户粘贴档案 + 分集大纲 + DNA 报告]
[用户粘贴本 skill]

LLM：[自检 + 校验前置 + 检测到 DNA 已激活]

用户：#标准 #短剧

LLM：检测到连续剧集（共 50 集）。请确认写哪一集？建议先写 1-3 集试稿。

用户：写 1-3 集

LLM：[逐集输出，每集独立结构 + 集尾钩子 + 引用 DNA 规律]

用户：风格 OK，继续 4-10 集

LLM：[批量推进，每 3 集为一批，批间暂停]
```

## 10.3  场景 C：长篇电影（中途切换节奏）

```
用户：开始写作 模式=标准 节奏=长篇电影
LLM：[问询 + 用户确认 + 开始输出]

[写到第二幕中段，约 50000 字]

用户：感觉节奏太长了，想改成微电影

LLM：检测到节奏切换：长篇电影 → 微电影
   已写部分约 50000 字，按微电影节奏需压缩到 3000-5000 字。
   两种处理方式：
   1. 已写部分按微电影节奏重写（推荐）
   2. 仅后续部分按微电影节奏（可能造成前后割裂）

   你选哪种？

用户：1

LLM：[按微电影节奏重写已有内容 + 保持主题]
```

# 第十一部分  技术备注（给 LLM 自身的提醒）

## 11.1  注意力衰减保护

本文件约 1.5 万字，为对抗 LLM 的"中部遗忘"问题，本文档做了以下设计：

1. **内部启动检查**：确保关键规则在工作记忆中激活，不默认向用户输出自检报告
2. **核心原则三重冗余**：在开头、中部（第八九部分）、结尾各放置一次速记
3. **每个模块开头重复核心原则**：确保 LLM 每次进入新模块时都重新校准
4. **关键指令显式化**：`激活对标DNA`、`/模式`、`/节奏` 等指令清晰，易于识别

## 11.2  上下文管理

- **项目档案 + 大纲 + DNA 报告**：这些前置信息是 LLM 工作的"世界观"，必须始终在上下文最前端
- **当前剧本**：已写出的剧本是"工作记忆"，每次修改都应在上下文保留最新版
- **分批输出**：主动将超长内容分批，每次只处理 8000 字以内，降低注意力负担

## 11.3  输出稳定性

- **严格格式**：每个模式都有严格的输出格式，确保可读性与可操作性
- **创作笔记**：强制 LLM 自我反思，提升输出质量
- **边界处理**：针对各种用户"异常"行为提供明确处理规则，避免 LLM 崩溃或乱答

# 附录 A  指令等价词识别表

LLM 解析用户输入时按以下等价词匹配，**忽略大小写和多余空格**：

## 模式等价词

| 标准化值               | 可识别的输入                                                       |
| ---------------------- | ------------------------------------------------------------------ |
| **M1（标准）**   | 标准、标准影视、标准剧本、标准影视剧本、行业标准、标准格式         |
| **M2（小说化）** | 小说化、小说化叙事、小说化剧本、小说化叙事剧本、文学化、文学化叙事 |

| 标准化值              | 可识别的输入                                        |

| **R1 短剧**     | 短剧、竖屏短剧、红果短剧、抖音短剧、爆款短剧        |
| **R2 连续剧**   | 连续剧、长剧、电视剧、网剧、长篇剧                  |
| **R3 短视频**   | 短视频、抖音、小红书、视频号、B站短视频、平台短视频 |
| **R4 单元剧**   | 单元剧、单元剧集、案件剧、unit剧                    |

| 标准化值     | 可识别的输入                     |
| ------------ | -------------------------------- |

## 不规范输入的处理

如果用户输入了模糊词（如 `模式=分集详写`，旧版概念）：

- LLM 必须主动澄清：

  ```
  注意："分集详写"在新版中已拆为正交开关。
  请确认底层模式：标准（M1）还是 小说化（M2）？
  分集开关已自动设为"是"。
  ```

如果输入完全无法识别（如 `模式=电影感`）：

- 触发 8.6"未识别指令"流程
