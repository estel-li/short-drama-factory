## 十一、资产库与四个旧模块的协作方式

### 1. 与剧本创作模块协作

在 `01-script-creation.md` 的 Step 7 项目档案完成后，读取本模块，把项目档案转成资产库。

交接输入：

- 项目名称
- 作品类型
- 视觉风格
- 人物档案
- 世界观设定
- 主要场景
- 关键道具
- 已写出的关键场景与台词

交接输出：

- 资产总表
- 角色资产卡
- 场景资产卡
- CR 人群/群演调度卡（公共空间或需要路人真实感时；不写入场景母版图）
- 道具资产卡
- 待补资产清单

### 2. 与剧本医生模块协作

在 `02-script-doctor.md` 会诊后，如果评委指出“主角不鲜明”“场景卖点不足”“视觉记忆点弱”，本模块负责把这些诊断转成资产层面的修改任务。

示例：

```text
会诊问题：主角记忆点不足。
资产任务：重做 CH001 标志性识别点，增加剪影特征、服装色彩、常用动作。
```

### 3. 与台词专家模块协作

在 `03-dialogue-expert.md` 输出角色语言指纹后，本模块要把语言指纹写入角色资产卡。

写入位置：

- 角色语言与表演
- 说话风格
- 口头禅
- 常用表情
- 常用动作

### 4. 与 AI 视频分镜模块协作

在 `04-ai-video-storyboard.md` 开始 Phase 0 参考图询问前，如果已有资产库，必须优先建立以下映射：

```text
@图1 = SC001_场景名_定稿图
@图2 = CH001_角色名_定稿图
@图3 = CH002_角色名_定稿图
@图4 = PR001_关键道具_定稿图
```

如果资产未定稿，必须提示：

```text
当前 CH001/SC001 仍是“参考”状态，不建议直接进入 AI 视频生成。
可以继续分镜，但角色/场景一致性风险较高。
```

## 十二、资产需求反推规则

如果用户提供的是剧本或分镜，但没有资产库，先反推资产需求。

```markdown
## 资产需求反推表

| 类型 | 临时编号 | 名称 | 来源场次 | 叙事作用 | 是否必须定稿 | 原因 |
|---|---|---|---|---|---|---|
| 角色 | CH001 |  | 第X场 | 主角 | 是 | 多场出现，影响一致性 |
| 场景 | SC001 |  | 第X场 | 开场空间 | 是 | 影响整体视觉风格 |
| 人群调度 | CR001 |  | 第X场 | 公共空间真实感 / 压迫感 / 遮挡调度 | 视情况 | 需要路人或群演，但不能烘焙进场景母版 |
| 道具 | PR001 |  | 第X场 | 线索 | 是 | 需要特写/跨场延续 |
```

判断“必须定稿”的标准：

1. 多场出现。
2. 影响剧情理解。
3. 需要特写或微距。
4. 需要跨段连续。
5. 是角色身份、情绪、反转、伏笔的承载物。

## 十三、出图 Prompt 默认尾缀

当本模块为角色、场景、道具、服装妆发、风格参考等资产生成 **图片 prompt** 时，默认在每条可直接投喂的 prompt 末尾追加以下清洁渲染约束。除非用户明确指定其他模型规则、明确要求去掉负面尾缀，或该任务不是图片生成 prompt。

追加清洁渲染约束前，必须先完成 `ST/CL/NP` 转译：正向 prompt 中写入项目风格、媒介质感、人物/场景审美和当前光影；负向 prompt 中合并风格防跑偏词。清洁尾缀只负责渲染稳定，不替代风格锁定。

推荐尾缀：

```text
clean illustration, smooth shading, soft lighting,
controlled details, minimal texture, high clarity,
refined edges, smooth gradients --no noise, grain,
artifacts, high frequency detail, dirty texture,
oversharpen, blotchy, chaotic details.
```

使用规则：

1. 该尾缀用于提高出图稳定性，尤其适合 GPT image 2 / 通用图像生成模型。
2. 尾缀必须写在每条独立图片 prompt 的末尾，不能只写在文件总纲里。
3. 如果已有负面词段落，也要确保包含 `noise / grain / artifacts / high frequency detail / dirty texture / oversharpen / blotchy / chaotic details` 等约束。
4. 如果用户给出自定义尾缀，以用户版本为准，但要检查拼写，优先使用 `soft lighting`、`high frequency detail` 这类空格清晰的标准写法。
5. 视频 prompt、Seedance 2.0 prompt、分镜文本不强制追加该尾缀；只有图片资产 prompt 默认追加。

## 十四、出图 Prompt 记录规则

每次为资产生成图片 prompt 时，必须记录。

```markdown
## AI 出图记录

| 日期 | 资产编号 | 版本 | 模型 | Prompt | 负面词 | 参数 | 结果 | 备注 |
|---|---|---|---|---|---|---|---|---|
| YYYY-MM-DD | CH001 | v0.1 | Midjourney/SD/即梦/可灵 |  |  |  | 候选/废弃/定稿 |  |
```

如果用户要求生成图像提示词，输出必须包含：

1. 正向 prompt
2. 负向 prompt
3. 比例建议
4. 风格约束：必须把 `ST` 展开成自然语言，不得只写 ST 编号
5. 一致性锁定词
6. 禁止漂移点
7. 本次版本号
8. 光影继承：必须把 `CL` 展开成当前资产可执行光影，不得只写 CL 编号
9. 防跑偏负面词：必须把 `NP` 合并进负向 prompt，不得只写 NP 编号

## 十五、分镜资产映射表

进入分镜前，必须输出或确认以下映射。

```markdown
# 分镜资产映射表

| @图编号 | 资产编号 | 资产名 | 类型 | 状态 | 使用范围 | 风险 |
|---|---|---|---|---|---|---|
| @图1 | SC001 |  | 场景 | 定稿 | B01-B03 | 无 |
| @图2 | CH001 |  | 角色 | 定稿 | 全片 | 无 |
| @图3 | CH002 |  | 角色 | 参考 | B02 | 未定稿，可能漂移 |
| @图3A | PR001 | 碎屏手机 | 道具 | 定稿 | B01-B03 | 如已出现在 SC/FF 中，必须启用单实例锁 |
| @图4 | SC001_V01 | SCV001_正向空景 | 场景角度图 | 定稿/参考 | B01-B03 | 只参考空间角度，不替代母版 |
| @图5 | MAP001 | SC001_B01-B02调度图 | 调度图 | 定稿/参考 | B01-B02 | 点位未确认会影响连续性 |
| @图6 | FF001 | B05_便利店窗边首帧 | 首帧图 | 定稿/候选 | B05 第 0 秒 | 与 MAP/SB 冲突时必须重做 |
```

映射规则：

- `@图1` 优先给主环境或当前大分镜的环境。
- `@图2` 起优先给核心角色。
- 关键道具需要特写时，也可以分配 `@图N`。
- 同一角色在整部作品中尽量使用同一个 @图编号。
- 如果同角色有不同状态，使用子标记：`@图2A = CH001 默认造型`，`@图2B = CH001 受伤造型`。
- 核心场景、反打、横移、回切或高穿帮场景，建议把当前镜头需要的 SCV 角度图加入映射；SCV 可以占用独立 `@图N`，后续由 06 转成 `@ImageN` 并写清只参考拍摄方向和空间透视。
- 同场景连续两段以上，或切走后又回到同一场景，必须把场景母版、SCV 推荐角度图、空间解析卡和调度图加入映射；调度图可以占用独立 `@图N`，后续由 06 转成 `@ImageN`。
- SCV 角度图只用于说明当前镜头从哪个方向看同一空间，不替代 SC 场景母版；分镜仍必须同时引用场景母版图。
- 调度图只用于说明空间、站位、移动路线、摄影机安全区和轴线，不替代场景定稿图；分镜仍必须同时引用场景母版图。
- 调度图中的点位命名必须稳定，例如 `A1=门口内侧`、`A2=茶几左侧`、`B2=沙发右端`、`C1=摄影机安全区`。后续 04/06 不要写“旁边、原位、刚才那里”，要写具体点位。
- 如果同一场景切走后又切回来，且故事时间没有改变或人物没有完成离场/换位动作，必须读取最近一次场景状态，并在调度图或场景状态卡里继续使用同一批点位。
- `CR` 人群/群演调度卡不占用 `@图N`，除非用户明确做了“人群参考图”。常规情况下只在映射表备注中写 `CR001=某场景人群密度卡`，交给 04/06 转成提示词里的 `人群密度` 和 `限制` 字段。
- 项目资产库和分镜资产映射表可以超过 9 张图，但每一组可投喂提示词 / 每个 Seedance 单元实际上传和引用的图片参考总数最多 9 张。进入 06 前必须按单组筛选：人物、当前场景、关键道具、首帧或调度图优先；低风险风格参考、额外 SCV、非关键道具细节优先转成文字约束或拆到下一组。
- `PR` 道具图如果只是补充已在场景母版、SCV 角度图或 FF 首帧图中可见的同一件道具，必须在风险或备注中写“只补外观，不新增实例”，并交给 04/06 输出道具单实例锁。
- `FF` 首帧图可以占用独立 `@图N`，但必须写清它只锁定本段第 0 秒的构图、人物初始位置、道具位置、空间内外侧、摄影机侧和光影，不控制整段动作发展。
- `FF` 首帧图不能替代 `SC` 场景母版、`SCV` 场景角度图、`CH` 角色图、`PR` 道具图、`MAP` 调度图或 `SB` 空间侧别锁定卡；如果 FF 与 SCV/MAP/SB 冲突，先重做 FF、修正 SCV 或修正调度图，不要把冲突交给 04/06 硬写。

### 参考图用途映射表

当一个视频段同时使用场景图、角色图、道具图、调度图和首帧图时，必须输出“参考图用途映射表”。这张表的目的不是增加复杂度，而是防止 AI 把不同参考图的职责混淆。

```markdown
# 参考图用途映射表

| 引用 | 资产编号 | 资产类型 | 用途 | 只参考 | 不参考 | 状态 | 风险 |
|---|---|---|---|---|---|---|---|
| @图1 | SC001 | 场景母版 | 空间结构参考 | 窗框、玻璃、柜台、货架、固定光源、空间透视 | 人物位置、剧情动作、人群状态 | 定稿 | 无 |
| @图2 | CH001 | 角色 | 林小雅外观参考 | 脸型、发型、服装、体态、年龄感 | 场景、动作、光影、道具 | 定稿 | 无 |
| @图3 | PR001 | 道具 | 碎屏手机外观参考 | 裂纹形态、机身颜色、屏幕状态；如果同一手机已在 SC/FF 中出现，只修正那一部手机的外观 | 随机文字、人物手势、第二部同款手机、复制到背景或其他桌面 | 定稿 | 文字风险；如同段引用 SC/FF，必须单实例锁 |
| @图4 | SC001_V01 | 场景角度图 | 当前镜头空间角度参考 | 拍摄方向、空间透视、门窗/家具相对位置、固定光源方向 | 人物位置、剧情动作、人群状态、第 0 秒构图 | 定稿/参考 | 与母版冲突则重做 |
| @图5 | MAP001 | 调度图 | 空间逻辑参考 | 点位、移动路线、摄影机安全区、轴线 | 画面风格、角色长相、光影 | 参考 | 仅逻辑参考 |
| @图6 | FF001 | 首帧图 | 本段第 0 秒画面参考 | 构图、人物初始位置、道具初始位置、空间内外侧、光影方向 | 后续动作、完整视频结尾 | 定稿/候选 | 与 MAP/SB 冲突则重做 |
```

参考图用途映射规则：

1. 每个 `@图N` 都要写清“只参考什么”和“不参考什么”。
2. 场景母版默认是空场环境图，只参考空间结构、固定光源、家具、门窗、透视；是否有人群由 CR 卡和视频段需求决定。
3. SCV 角度图只参考当前拍摄方向、空间透视、固定家具/门窗相对位置和固定光源方向；不继承人物、人群、剧情动作，也不替代第 0 秒首帧。
4. 角色图只参考人物外观，不继承角色在图片里的姿态、场景、光线或临时情绪，除非用户明确把该图指定为表演参考。
5. 首帧图只锁定第 0 秒，不等于整段视频都静止在这张图；06 仍要写清后续动作、运镜和段末状态。
6. 调度图、SB 空间侧别锁定卡和 FF 首帧图的优先级必须一致：FF 的视觉结果要服从 MAP/SB 的空间逻辑。
7. 如果同一 PR 道具已经出现在 SC/SCV/FF 中，又上传 PR 外观图，参考图用途必须写清“PR 只修正该已存在道具的外观，不新增实例”，并在 06 中输出 `道具单实例锁`。

### 连续性资产交接包

当用户要做 AI 视频、Seedance 2.0、批量生成连续片段，且两段以上发生在同一场景时，资产库除了常规 `@图N` 映射，还要输出“连续性资产交接包”。

```markdown
## 连续性资产交接包

- 场景母版：@图1 = SC001_场景名_母版图（固定环境、家具、门窗、光源）
- SCV 多角度空间包：@图4 = SC001_V01/V02/V03/V04（按当前镜头选择；只参考空间角度和透视）
- 空间解析卡：SC001_空间解析_v1.0（门窗、家具、可走区域、不可移动区域）
- 调度图：@图5 = MAP001_SC001_B01-B02（人物点位、移动路线、摄影机安全区、轴线）
- 人群调度：CR001 = SC001_场景名_人群密度卡（仅公共空间或需要路人真实感时启用；不生成到场景母版图）
- 道具单实例锁：PR001 = @图6 首帧中桌面右下角那一部道具；@图3 只补外观，不新增第二个实例
- 点位表：
  - A1 = ____
  - A2 = ____
  - B1 = ____
  - B2 = ____
  - C1 = 摄影机安全区 ____
- 当前场景状态：
  - 故事时间：____
  - 光线：____
  - 角色位置：____
  - 道具位置：____
  - 最近一段末端状态：____
- 交给 04 的要求：分镜必须写清本段第一帧状态、本段目标末端状态、下一段起始状态建议。
- 交给 06 的要求：Seedance 独立批量生成时，提示词必须直接写可见首帧状态，不依赖“承接上一段”。
```

连续性资产交接包的核心不是让视频模型理解“上一段发生了什么”，而是让下游模块把“本段第一帧应该看见什么”写清楚。

### 首帧图需求卡 / First Frame Card

首帧图是高风险段落的“第 0 秒画面锚点”。它解决的是 AI 视频开头容易把人物放错侧、把道具放错边、把窗外/窗内搞反、把桌台/柜台当双面空间的问题。它不是默认流程，也不是替代文字提示词；启用首帧后，04/06 仍然必须写清空间锁定、人物点位、道具位置、光影和限制。

#### 首帧风险等级

| 风险等级 | 是否建议首帧 | 触发条件 |
|---|---|---|
| A 必须首帧 | 必须输出 FF 首帧需求和首帧图 prompt | 玻璃/窗户内外、柜台/吧台两侧、车内外、门框内外、栏杆/围挡/镜面反射、人物容易坐到错误一侧；同场景强连续且批量生成；关键道具位置必须精准；MAP/SB 已经标注高穿帮风险 |
| B 建议首帧 | 建议输出 FF，用户可跳过 | 复杂光影、强情绪近景、道具特写、多人同画面但空间关系不算危险、首镜构图对叙事很关键 |
| C 可不用首帧 | 默认不输出 FF | 单人简单空间、跨场景新段落、无精确站位要求、用户希望让 AI 自由发挥且穿帮风险低 |

#### 首帧图需求卡模板

```markdown
# FF001_Bxx_场景名_首帧需求卡

- FF 编号：
- 绑定大分镜：
- 绑定场景：
- 风险等级：A 必须首帧 / B 建议首帧 / C 可不用首帧
- 是否生成首帧图：是 / 建议 / 否
- 首帧锁定内容：构图 / 人物初始位置 / 道具初始位置 / 空间内外侧 / 摄影机侧 / 光影方向 / 人群初始状态（如有）
- 关联资产：SC____ / CH____ / PR____ / MAP____ / SB____ / CL____ / CR____
- 参考图用途：@图1=____；@图2=____；@图3=____；@图4=____；@图5=FF____
- 与 MAP/SB 校验：一致 / 冲突需重做
- 不锁定内容：后续动作、完整视频结尾、演员微表情发展、运镜结束位置
- 交给 04 的要求：本段第一帧状态必须用文字复述 FF 的可见事实。
- 交给 06 的要求：如果使用 FF，`素材` 字段必须先说明 FF 只作为本段第 0 秒首帧参考，再说明 SC/CH/PR/MAP/SB 的用途。
```

#### 首帧图 Prompt 结构

生成首帧图时，优先使用用户验证过的“画面调度 + 具体视觉锚点”结构。不要写抽象规则，不要只写“保持同一场景”，要把参考图用途和空间侧别写成画面事实。

```text
【参考图用途】
图片1：SC001_场景母版，只参考空间结构、固定光源、玻璃/门窗/桌台/柜台位置，不继承人物和人群。
图片2：CH001_角色名，只参考脸型、发型、服装、体态。
图片3：PR001_道具名，只参考道具外观和关键细节；本首帧中只生成这一件道具，后续 06 如同时引用 FF 和 PR，必须写单实例锁。
图片4：MAP001/SB001，只参考点位、移动路线、摄影机安全区、内外侧分界，不参考画风。

【首帧目标】
```

#### 首帧使用红线

1. 不把首帧图当作所有段落的默认步骤；只有 A 必须、B 建议时输出。
2. 不把 `FF` 写成“承接上一段”这种模型不懂的上下文词；要写成“本段第 0 秒画面”。
3. 不让首帧图替代文字锁定。即使使用 FF，06 仍必须写人物点位、空间侧别、道具位置、光影和禁止项。
4. 不让首帧图替代角色/场景/道具参考。FF 负责第 0 秒构图，CH/SC/PR 负责身份和资产一致性。
5. 如果 FF 与 SCV/MAP/SB/点位表冲突，停止交接，先修正资产；不要让 04/06 用提示词硬补冲突。

## 十六、输出模式

根据用户需求选择输出模式。

### 1. 快速资产库

适合早期项目。

输出：

- 资产总表
- 待补资产清单
- 下一步建议

### 2. 完整资产库

适合准备出图、分镜、AI 视频。

输出：

- 推荐目录结构
- 资产总表
- 项目视觉风格锁定卡（ST）：媒介类型、时代质感、人物审美、场景审美、画面质感和风格禁止项
- 项目风格防跑偏负面词包（NP）：人物、场景、画面质感、渲染媒介的禁止项
- 核心角色资产卡
- 核心角色四视图定稿图 prompt（左侧大头/胸像 + 右侧正面/侧面/背面全身，影棚灰色背景）
- 核心/高级角色设定资料卡 prompt（可选增强，默认 3:2 横版；与四视图共存，不替代四视图）
- 核心场景资产卡
- 核心/高穿帮场景 SCV 多角度空间包需求：PLAN 俯视空间图、V01-V04 空场角度图、验收标准和负面提示词
- 核心场景光影设计卡（CL）：主光、辅光、轮廓光、亮区暗区、色温、丁达尔/雾化光束、连续性约束
- 公共空间 CR 人群/群演调度卡：密度等级、数量范围、前中远景分布、人群类型、移动方向、遮挡规则、禁止项
- A/B 风险段的 FF 首帧需求卡、首帧图 prompt 和参考图用途映射表
- 关键道具资产卡
- 出图 prompt 记录表
- 所有可复制给图像模型的 prompt 都必须把 ST/CL/NP 展开成自然语言，不得只写内部编号
- 分镜资产映射表
- 待补资产清单

### 3. 分镜前资产检查

适合已有剧本和资产，准备进入 AI 视频分镜。

输出：

- 已定稿资产
- 未定稿资产
- 高风险资产
- @图N 映射表
- 光影母版 / CL 光影设计卡是否齐全
- 场景母版 / SCV 多角度空间包 / 空间解析 / 调度图是否齐全
- 公共空间是否需要 CR 人群/群演调度卡；私密空间是否需要明确禁止额外人物
- 是否存在 A/B 首帧风险；是否需要 FF 首帧图、SB 空间侧别锁定卡和参考图用途映射表
- 是否建议进入分镜

### 4. 角色四视图 Prompt 输出

适合用户明确说“给我人物资产提示词 / 角色定稿图提示词 / 按这张图的格式生成角色图”。

输出：

- 角色四视图正向 prompt
- 角色四视图负向 prompt
- 风格转译说明：如果存在 ST/CL/NP，代码块内的最终 prompt 必须直接写出项目风格、人物审美、光影质感和负面词；不得只写 `ST001 / CL001 / NP001`
- 推荐比例：横向宽图，优先 `21:9`、`16:9` 或平台支持的横向大画布
- 版本号：如 `CH001_角色名_v1.0_四视图候选`
- 验收标准：同一脸型、同一发型、同一服装、同一鞋子、同一配饰、灰色影棚背景
- 下一步：用户选定后进入 `02_定稿图` 和 `05_四视图设定`；如果该角色是主角/重要反派/怪物/幻兽/机甲/IP 核心角色，提醒用户是否额外生成 `06_高级角色资料卡`

### 4b. 高级角色设定资料卡 Prompt 输出

适合用户明确说“高级角色卡 / 角色资料卡 / 像设定集一样 / 资产卡更高级”，或资产检查判断该角色为主角、重要配角、重要反派、怪物、幻兽、机甲、IP 核心角色。

输出：

- 启用理由：为什么该角色需要高级资料卡
- 资料卡正向 prompt
- 资料卡负向 prompt / 禁止项
- 风格转译说明：如果存在 ST/CL/NP，资料卡 prompt 必须把项目风格、人物审美、画面质感、光影设计和防跑偏负面词写成自然语言；不得只写内部编号
- 推荐比例：默认 `3:2 横版`；如用于宣发展示可另给 `16:9 横版展示版`
- 参考图要求：必须绑定已确认的四视图定稿图或角色定稿图
- 版本号：如 `CH001_角色名_v1.0_高级资料卡候选`
- 验收标准：同脸、同发型、同服装、同体型、同道具；面部特写/三视图/比例/细节展示互相一致
- 下一步：用户选定后进入 `06_高级角色资料卡` 归档，并在参考图用途映射表中说明它只作为角色资产归档和细节参考，不替代视频生成时的 CH 定稿图

### 5. 连续性资产包

适合用户要做同场景多段 Seedance / AI 视频，或明确担心人物站位、空间调度、回切穿帮。

输出：

- 场景母版图需求 / 已有母版图
- SCV 多角度空间包需求 / 已有角度图：PLAN、V01、V02、V03、V04
- 空间解析卡
- 调度图 prompt 或调度图说明
- 点位表
- B01 起始状态、B01 目标末端状态
- B02 起始状态建议、B02 目标末端状态
- A/B 风险段的首帧需求卡、首帧图 prompt、参考图用途映射表
- 可交给 04 的连续性说明
- 可交给 06 的独立批量生成限制说明

### 6. 光影设计卡输出

适合用户明确说“光影太弱 / 布光不够 / 想要电影感布光 / 需要丁达尔光 / 想统一场景光线”，或核心场景准备进入 04/06。

输出：

- CL 编号与绑定场景

### 7. 场景多角度空间包输出

适合用户明确说“场景只有一张母图 / 需要多角度 / 反打容易变空间 / 回切穿帮 / 人物坐错边 / 做核心场景资产”，或资产检查判断场景属于核心场景、高频回切场景、高穿帮空间。

- V01 正向空景 prompt
- V02 反向空景 prompt
- V03 左侧空景 prompt
- V04 右侧空景 prompt

适合用户明确说“场景里要有路人 / 群演 / 人流 / 街上不能太空 / 商场要真实 / 车站要拥挤”，或剧本出现公共空间、营业场所、交通枢纽、学校、医院、街道、演唱会、活动现场等。

输出：

- CR 编号与绑定 SC 场景
- 密度等级：空场 / 稀疏 / 日常 / 繁忙 / 高峰拥挤
- 数量范围：前景、中景、远景分别多少人
- 人群类型：职业、年龄、服装、行为

- 是否允许短暂遮挡，以及不能遮挡哪些关键表情/道具/动作

- 交给 04/06 的文字锁定说明：FF 只作为第 0 秒画面，06 仍要写清动作过程、段末状态和限制

## 十九、资产库红线

1. 不把“参考图”说成“定稿图”。
2. 不在用户未确认时擅自把候选资产定稿。
3. 不删除废弃资产，只移动到废弃并记录原因。
4. 不让未定稿角色直接进入长期 AI 视频生成。
5. 不用没有编号的角色、场景、道具进入分镜。
6. 不把出图 prompt 和最终图片混为一谈。
7. 不为了好看牺牲角色身份、剧情功能和视觉一致性。
8. 不把资产库变成单纯文件夹清单，必须能服务剧本、分镜和 AI 视频生产。
9. 不把路人、群演、人流、随机顾客烘焙进场景母版图；场景母版默认只保留空环境。
10. 不把 CR 人群调度卡当成图片资产；它是给 04/06 的文字调度规则。
11. 不用高级角色设定资料卡替代四视图定稿图；视频生成时仍需明确 CH 角色定稿图/四视图作为身份参考。
12. 不强制所有角色生成高级资料卡；只给核心、高价值或用户明确要求的角色启用。
13. 不把高级资料卡当作首帧图、场景图或分镜调度图；它只服务角色归档、细节核对和团队交接。
14. 不在最终可复制给图像模型的 prompt 里只写 `ST001 / CL001 / NP001`；必须展开成具体风格、光影、质感和负面词。
15. 不让已选择的项目风格失效：港风不能跑成韩风网红感，动漫不能跑成真人照片，3D 不能跑成 2D 插画，国风不能默认跑成赛博或欧式奇幻，除非用户明确要求混合风格。
16. 不让同一个关键道具在场景母版/首帧图和 PR 道具图中被当成两个实例；凡同段同时引用已含该道具的 SC/SCV/FF 与 PR，必须启用道具单实例锁。
