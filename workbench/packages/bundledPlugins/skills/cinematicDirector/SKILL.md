**提示词构建。**

> 这套东西来自 Higgsfield Studio 公开的 **14 部全 AI 生成影片**（含一部 115 分钟长片）的真实

## 0. 这是什么

**不是**"怎么让画面好看"的提示词模板集。
**是**一套**判决流程**：给定一个剧情，决定该写什么、不该写什么、写多细，然后组装成一条模型能执行的指令。

它交付三样东西：
1. 一条**能被模型执行**的提示词（不是一段文学描写）；
2. 一份**知道哪里会坏**的预判清单；
3. 一个**按剧情伸缩**的加载方案——短片只读 2 个文件，长片才读 6 个。

---

## 1. 唯一定理

> **一条提示词，是写给一个没有记忆、没有常识、只会看字面的人在某一刻的封闭指令书：
> 一个人，在一个地方，一种光下，一颗镜头里，为了一件事，做一件事。
> 不在这句话里的东西，生成前删掉。**

推论（后面所有分支都是这条的展开）：

| 推论 | 含义 |
|---|---|
| **没有"上一镜"** | 模型无记忆。光、镜头、服装、道具、声音、走位，每一镜从零重写。"同上"是无效指令。 |
| **只写必须出现的** | 提示词不是剧本，是施工单。没让模型画的东西写进去只会污染注意力。 |
| **参数不进正文** | 时长、画幅、分辨率是 UI 的事；写进正文会与真实参数打架。 |
| **状态，不是转变** | 模型拍"是什么"，不拍"变成什么"。要写已经进行中的状态。 |
| **想得到的效果，写可见的证据** | 不写"35mm 长焦"，写"背景压平成一团柔色，只有主体是清晰的"。 |
| **提示词买的是命中率，不是一次命中** | 真实工作室是"写好提示词 → 大量重抽 → 筛选"，实测平均每条提示词被提交 2 次、最多 9.4 次。**抽卡预算、判定标准与三振法则见 `14-reroll`。** |

## 2. 五步循环

拿到任何请求，都走这五步（每步一行，不跳步）：

| 步 | 做什么 | 产出 |
|---|---|---|
| **① 读** | 把请求拆成「剧情卡」（§3.1）。**先确认风格与情绪——缺就先问一句。** | 剧情卡 11 格 |
| **② 定形** | 形态 = 单镜 / 场景 / 段落 / 短片 / 剧集。**同时算清"这场戏要做几条视频"**（§2.1）。 | form + runtime + **生成条数** |
| **③ 选装** | 用分流表（§3.2）决定加载哪几个模块。**只加载需要的。** | 2–5 个文件 |
| **④ 组装** | 按骨架（§5）逐槽填。每槽只写该槽的东西。 | 提示词草稿 |
| **⑤ 过闸** | 跑交付前闸门（§6）。任何一项不过，回 ④。 | 可发送的提示词 |

**②③ 的顺序不能反。** 先判形态再选模块——单镜不需要多镜连续性，5 秒短片不需要角色档案。

### 2.1 一条生成装多个镜头，装到模型上限为止 ★

**这是最容易被写错的一步。** 默认姿势不是"一个镜头生成一条视频"，而是：

> **把这场戏的镜头拼成一次生成，时长开到该模型的上限。**
> 4 s + 5 s + 6 s = 15 s → **一条 15 s 的视频（3 个镜头、2 个硬切）**，不是三条视频。

| 规则 | 说明 |
|---|---|
| **先选模型** | **默认用 Seedance 2.5**（30 s 上限）：一条生成装得下整场戏，少切一条就少一次跨条漂移。只有 2.5 不可用、或确实要做 15 s 以内的极短单品时才回退 2.0 |
| **定输出参数** | **分辨率默认 720p**。用户已经指定或自己调过（1080p / 2K / 竖屏规格等）→ **沿用用户的**，不要再改回去 |
| **再算条数** | `条数 = ceil(总时长 ÷ 单次上限)`。上限：Seedance 2.0 = 15 s，2.5 = 30 s（**换成自己平台核实过的值**；推荐的是模型，不是那个数字） |
| **填满优先** | 前 `n−1` 条填到上限，最后一条吃余数；余数 < 3 s 就改成均分 |
| **不满就补** | 单条不满上限时，用**反打 / 细节插入 / 环境覆盖 / 0.3 s 节拍停顿**补满——补的是真内容，不是放慢动作 |
| **一条内多镜** | 写 `SHOT n — 时长` + 绝对秒数的剪切点（`HARD CUTS at 0.5s / 3.5s`）+ 结尾 `TOTAL RUNTIME` 确认 |
| **超上限才拆** | 70 s 用 30 s 上限 → **30 + 30 + 10**（拆在上限处，一刀不浪费） |

**实测依据**：语料 1,469 条视频提示词里 `multi_shots` 全是 `false`、`multi_shot_mode` 全是 `"custom"`（多镜头写在正文里）；约一半提示词含剪切表；UI 的 `duration` 峰值**正好停在上限**（2.0：82/200 条 = 15 s）。**这条流水线就是"一次生成装多个镜头"的流水线。**

**为什么这很重要：** 独立短片各自为政，接起来必断（光向、方向、节奏、状态全要重对）。装进一条生成里，模型自己就把它们连上了。**这是免费的一致性。**

> 完整算例、填充策略、拆条后的连续性补丁 → `banks/F-model-caps.md`（形态判定阶段就要查）。

## 3. 剧情分流 ★

### 3.1 先填剧情卡（11 格）

从用户的请求里**判断**填格。其中两格是门把手：**风格定位**与**情绪**——它们决定镜头语言、光、节奏，
也决定每一节该写多深。**这两格缺任何一项，动笔前先问一句。** 其余都能推出来。

| 格 | 取值 | 怎么判 |
|---|---|---|
| **风格定位** ★ | 参考影片或导演 · 年代（70 年代、近未来）· 画幅格式（变形 2.39、4:3、16mm）· 影像质感（自然光纪录片、高反差黑色、柔彩动画）· 类型片的视觉语域 | 找任何被点名的影片、导演、摄影师、年代或"像 X 那样"。**缺了就问：**「你希望它像哪部片、哪种质感？」 |
| **情绪** ★ | 紧张 / 温柔 / 嚣张 / 悲恸 / 释然 / 敬畏 / 压抑 / 喜剧感 / 惆怅 | 这颗镜头结束时，观众该**感觉到**什么？**缺了就问：**「你想让观众感受到什么？」 |
| **形态** | 单镜 / 场景（2–5 镜）/ 段落（一场戏）/ 短片 / 剧集 | 用户给了几个动作？一个＝单镜；有对话来回＝场景；有起承转合＝段落 |
| **时长** | <10s / 10–30s / 30–120s / >2min | 时长直接决定镜数上限与细节密度 |
| **引擎** | 写实真人 / 风格化动画 / 混合 | 有"动画/插画/黏土/2D"＝风格化；反过来默认写实 |
| **类型** | 动作 / 喜剧 / 恐怖 / 爱情 / 剧情 / MV / 广告 / 纪录 | 决定光、节奏、镜头语言的默认值 |
| **人物负荷** | 1 / 2–3 / 群像 | 人数越多，走位与视线越要写死 |
| **场景数** | 1 / 少 / 多 | 多场景＝必须建地点板，否则每镜都变样 |
| **驱动力** | 对白 / 动作 / 氛围 / 音乐 / 产品 | **这一格决定 60% 的加载量** |
| **连续性** | 无 / 镜内 / 跨镜 / 跨集 | 跨镜就要账本，跨集还要项目技能 |
| **风险标记** | 脸·手 / 动物 / 人群 / 武器 / 液体火 / 画面文字 / 口音·生造语 | 每命中一个，多读一个模块 |

### 3.2 分流矩阵（信号 → 加载）

**永远加载：** `§4` 永远条款 + `§6` 闸门（就在本文件里，不必另读）。
**其余按命中加载，命中几条就读几个：**

| 剧情卡的信号 | 加载 | 为什么 |
|---|---|---|
| **任何要生成视频的请求** | **`banks/F-model-caps`**（查表，5 秒）+ **`banks/G-prompt-depth`**（定每节写多深） | 先定"做几条、每条多长"，再定"每节写多深"——这两件事都在动笔之前 |
| 卡在措辞上（那句话写不出来） | **`banks/B-phrase-bank`** | 真实语料的高频句式，直接拼，比自己造词稳 |
| **用户说得清剧情类型**（"这是恐怖片／是产品广告／是一镜到底的情绪片"） | **`banks/J-story-router`**（先查叶子，再落笔） | 21 个叶子，每个叶子直接给出镜头语言、光、声、锁与配方句——比从头判断快 |
| 抽卡/命中率问题（"抽了很多次都不对"） | `14-reroll` 
| 形态＝单镜 | `04-optics` `05-light` `09-assembly`（＋有实质动作时 `06-motion`） | 单镜没有剪辑可救，全靠一镜之内的镜头/光/物理 |
| 形态＝场景 / 段落 / 短片 / 剧集 | **`01-story`** ＋ 下面各条 | 先有分镜，再谈单镜 |
| 驱动力＝**对白** | `02-cast` `13-acting` `08-sound` `banks/H-dialogue-safety` `09-assembly` | 表演与台词时序是主要失效点；台词写法与声音环境在 H 库 |
| 驱动力＝**动作** | `06-motion` `04-optics` | 物理可信度 + 广/长焦切换 |
| 驱动力＝**氛围** | `05-light` `04-optics` `03-space` | 氛围＝光 + 空间纵深 |
| 驱动力＝**音乐** | `07-sequence` `08-sound` | 卡点剪辑；禁对白 |
| 驱动力＝**产品/广告** | `10-assets` `banks/I-image-models` `05-light` | 产品即资产，先出板再造镜；模型路由决定板子怎么写 |
| 人物负荷 ≥2 或 风险＝脸·手 | `02-cast` `13-acting` `03-space` ＋ §5.6 五锁 | 表演 + 走位/视线/地标邻近锁 |
| 场景数＝多 | `03-space` `10-assets` | 不建地点板，每镜是另一个世界 |
| 连续性＝跨镜 / 跨集 | `07-sequence` ＋（跨集）`11-project-skill` | 账本 + 项目技能 |
| 风险＝动物 | `06-motion` `02-cast`（LIVING MOMENT 变体） | 动物不能套人物表演法 |
| 风险＝武器 / 液体·火 | `06-motion` | 重量与流体是最高频的假 |
| 风险＝画面文字 | `10-assets` `banks/A-optics-bank` | 文字单独当资产做（图里出字，视频里只引用） |
| 类型＝**恐怖** | `05-light`（低照度/逆光）＋`banks/C-negative-bank` | 恐怖＝看不见的东西，光比脸重要 |
| 类型＝**喜剧** | `02-cast` `07-sequence` | 喜感在节拍与反应，不在表情 |
| 时长 >2min 或 形态＝短片/剧集 | **`01-story`** `07-sequence` `11-project-skill` `10-assets` | 长片先建世界，再建镜 |
| 用户说"生成很假/不像/漂移" | `banks/E-failure-atlas` ＋ 对应模块 | 按症状反查，别整本读 |
| 用户要"角色/地点/道具设定" | `10-assets` `banks/I-image-models` `banks/A-optics-bank` | 属于图像车道，不是视频车道；先认模型再下笔 |
| 镜头里有明确命中/冲击瞬间 | `06-motion` + `12-verified-rules` | 打击感 12 项是实测最强的一条（+1.20） |
| 大远景/空镜不能显得空 | `03-space` `05-light` + `12-verified-rules` | 空气 40–60%、三层明度（+0.46） |
| 用户提到跨段接不上（可选建议） | `07-sequence`（**先问要不要用上一段尾帧，默认不用**） | 尾帧续接近景 +0.75、宽景 +0.15；属建议，不是默认规则 |
| **任何多镜生成** | **§5.6 五个锁**（本文件内，逐条过） | 首帧占位 / 空间走位 / 视线朝向 / 地标邻近 / 多镜连续——五句锁，缺一条就留一个漂移口 |
| 镜头一镜到底、或机位有明确起终点 | `04-optics`（复合运镜例外条款）＋ §5.6 | 有主轴 + 起终点的复合运动可以用；没坐标的堆叠不行 |
| 平台拒稿 / 生成被降质 | `banks/H-dialogue-safety`（安全用语一节） | 某些写法会触发平台过滤，换说法就过 |
| 提示词发胖、一句话塞三件事 | `banks/H-dialogue-safety`（密度控制一节） | 密度不是字数，是每句只装一件事 |

> `12-verified-rules` 是 2026-11 的 A/B 补充：只收**实测有效**的两条；无效/不可复现的规则（以及多图配色职责拆分——真实多图多是不同角色/场景/道具）刻意不在里面，别再从别的 skill 里把它们加回来。尾帧续接只作**按需建议**：用户提到时才提，先问是否采用。

### 3.3 加载预算（硬规则）

- **按形态给预算：** 单镜 **2–3** 个 · 场景/段落 **3–4** 个 · 短片/长片 **5–6** 个。
  超出上限说明你没做第 ②③ 步，在拿资料代替判断。
- 单镜请求的加载范围：`04` `05` `09`（＋动作戏补 `06`）。
- 图像/设定请求的加载范围：`10` `banks/A-optics-bank`。
- 需要查具体数值（视角、短语、正面改写）时开 `banks/`，按需查一两条就走。
- 读完先回答一句：「我加载了 X，因为剧情卡里 Y＝Z」。答不上来说明加载错了。

## 4. 永远生效的 16 条

写完任何提示词，这些都必须已经成立。它们不依赖加载哪个模块。

| # | 条款 | 为什么 / 症状 |
|---|---|---|
| 1 | **语言跟随输入**：中文问 → 中文提示词，英文问 → 英文提示词（细则见 §4.1） | 用户要和自己的工作语言一致；混语言会让模型两头都读不透 |
| 2 | **只写"会改变画面"的**——但不等于写得少 | 不相关的东西会抢走注意力；而"该有的细节没写"会让画面空。删的是**无关**与**重复**，不是细节（深度基线见 §5.2） |
| 3 | **每镜从零重写**（光/镜头/服/道具/声） | 模型无记忆，"同上"＝不写 = 随机 |
| 4 | **参数不进正文**（时长/画幅/分辨率/模型名）—— 它们在 **UI 里设**：分辨率默认 **720p**，用户已指定就沿用用户的 | 与 UI 打架；且会挤掉真正的内容。**画幅尤其危险：实测写入正文的 637 条里 12% 与真实输出矛盾，且是"抄来的常量"故障**（见下） |
| 5 | **成稿全正面**：每一句都写"要什么"，把"不要 X"翻译成"Y" | 模型执行的是你写下的东西；写下"不要字幕"它就多了一个"字幕"概念。全正面既更少歧义，也更少触发词 |
| 6 | **一个风险，一条本地锁**，不堆负面块 | 远处的大负面块会被忽略；本地短句生效 |
| 7 | **资产图必须挂**——每条视频提示词用 `{{ref 1}}`…`{{ref N}}` **逐张绑定**本次要用的角色板/地点板/道具板 | 只写「男主角色参考」这种名字等于没绑；不挂引用模型自由发挥，写再多外观描写也不如一张图 |
| 8 | **写可见证据，不写器材**（角度/度数/构图结果） | "35mm"在视频模型里不稳定，结果描述稳定 |
| 9 | **每颗镜头只承载一种内容类型**（脸 / 全景 / 微距不混） | 混＝模型把三样折中，得到漂移 |
| 10 | **开场状态（t=0）就必须满员**（文字写死，不是首帧图） | 不写清 t=0 的在场与站位，模型会留空、延迟揭示或让人物乱入 |
| 11 | **写状态，不写转变** | 模型拍"是"，不拍"变成" |
| 12 | **时间必须是数字**（0:00–0:03 / 0.5 s） | 不给时间，模型自己分配，节奏必坏 |
| 13 | **多镜必须逐镜定义剪切**，并且**尽量塞进一次生成、开到模型时长上限** | 不定义模型自创蒙太奇；拆成多条独立短片必断（见 §2.1） |
| 14 | **只说剧本里的那句台词**——声音、文字都来自画内 | 凭空多出的文字会被模型当成要生成的字幕 |
| 15 | **风格锚点一行**：一位摄影师，或一部片，只此一个 | 多个锚点＝模型取平均，得到通用广告感 |
| 16 | **密度 ≠ 长度**：密度是**信息种类**多，不是句子短。该细的细（身份/走位/开场状态/时间/光/材质/声），该粗的粗（通用美感形容词/背景闲人） | 一条 6 镜 30 秒的提示词应在 8,000 字符以上、上不封顶；只有 1,500–2,500 就是每节都太浅 |

> 这 16 条是**在所有案例里反复被验证**的（详见 `_analysis/A_skill_files_mining.md` §4.16 与 14 个案例摘要）。
> 它们也是"为什么生成很假"的**第一诊断表**：症状 → 回查第几条。

### 4.1 输出语言：跟着输入走

**规则一句话：用户用什么语言提要求，提示词就用什么语言写。** 中文提问 → 中文提示词；英文提问 → 英文提示词。

不是"英文更好所以都写英文"。语料本身就是双语的：331 条中文主导的视频提示词，分布在 8 个案例里（`red-flag` 99、`cully-hill-boys` 90、`kok-boru-film` 50、`hell-grind` 30…），**块骨架在翻译后完全成立**——中文标签与英文标签是一一对应的（`场景背景`=SCENE CONTEXT、`空间地理`=LOCATION MAP、`作用于画面左`=`screen-left`、`绝对禁止`=NEGATIVE）。

**这套 skill 有两个版本，结构完全对应：**

| 版本 | 正文 | 块标签 | 什么时候用 |
|---|---|---|---|
| `cinematic-director` | 英文 | `SCENE CONTEXT` / `OPENING STATE` / `POSITIVE LOCKS` … | 英文场景，或用户要英文输出 |
| `cinematic-director-zh`（本版） | 中文 | `场景背景` / `开场状态` / `正向锁定` … | 中文场景，或用户要中文输出 |

按**提问语言**选版本，不按偏好。两个版本的规则、tip 编号、数字、文件结构完全相同——一边写的提示词，永远可以在另一边重建。

**分三类处理：**

| 类别 | 怎么做 | 例子 |
|---|---|---|
| **跟随输入语言** | 块标签、描述、指令、结果短语、镜头/光/表演/物理的表述 | 中文提问 → `【空间地理】` 而不是 `LOCATION MAP`；`背景压平成一团柔色` 而不是 `background compressed flat` |
| **保持原语言，绝不翻译** | **台词**、生造语、歌词、方言 | 西里尔生造语行永远是西里尔原文；粤语台词永远粤语；不写"翻译后的台词" |
| **不翻译** | 数字、度数、时间码、比例、型号名 | `47°`、`0:00–0:03`、`2.39:1`、`Seedance 2.5` |

**中文提示词的两种写法都真实存在，都可用：**
1. **英文标签 + 中文正文** —— `SCENE CONTEXT` 标题保留英文，下面全中文（Cully 的写法）
2. **中文标签包在【】里** —— `【空间地理】`、`【风格＝绝对最高优先】`、`【绝对禁止】`（kok-boru-film / red-flag / trigger 的写法，最多）

**选一种并贯穿全篇。** 混排会让模型把同一个槽当成两种东西。

**混合输入怎么判：** 看**请求主体的语言**，不是看文件名或术语。用户写"帮我做一个 15 秒的中文短片"，主体是中文 → 中文提示词，即使里面夹了英文技术词。
**台词语言独立于提示词语言**：中文提示词里可以有英文台词，英文提示词里可以有中文台词——那由剧本决定，不由提问语言决定。

> `banks/` 里每条片段都有语言分栏：**本版取中文**（语料原文优先），英文版取英文。中文栏是语料原文，比直译更贴。

### 4.2 成稿全正面 —— 写"要怎样做"

**规则：成稿里一句否定都不要。** 不是"少写否定"，是**零否定**。
理由不只是模型会想到那个东西——更实际的是：**否定句不告诉模型该做什么**。
「不要字幕」只说了别做一件事，模型得自己猜"那我该做什么"；而「画面填满整个画幅，只有图像内容」直接给了它要做的事。

**三步改写：**

1. **定位**：找出成稿里所有以「不要 / 不许 / 无 / 别 / 禁止 / 避免」起头的句子。
2. **问"那要什么"**：每一句的背后都有一个想要的状态。把那句话写出来。
3. **替换**：用正面句替换否定句，**不是两边都留**。

**对照表（左边是你想禁止的，右边是直接可用成稿的写法）：**

| 想说的禁令 | 写进成稿的正面句 |
|---|---|
| 无配乐 / 不要音乐 | `声音只有现场声：日光灯电流、椅木轻响、他近处的呼吸。` |
| 无字幕 / 不要文字 / 不要水印 | `画面填满整个画幅，只有图像内容。` |
| 无旁白 / 不要画外音 | `只有画内的人声与现场声。` |
| 不要慢动作 | `全片实时速度。` |
| 不要平光 / 不留平光无影 | `脸留在阴影里，只有轮廓光与地面反弹揭示细节。` |
| 不要补光 / 不要美颜光 | `曝光只给背景，人物作为剪影读出。` |
| 不要过曝 | `高光只出现在：水面反光、手电光斑、眼底一点光。` |
| 不要剪切（除指定点） | `每一刀都在此表内：5.0s / 10.0s / 14.0s。` |
| 不要淡入淡出 / 不要叠化 | `每一刀都是硬切，落在动作中段。` |
| 不要新角色进画 | `画面里始终只有这两个人。` |
| 不要看到怪物全貌 | `怪物始终处在暗部，只有下颌与齿落在光里。` |
| 不要夸张表情 | `脸只在肌肉层面动：下颌紧一次、呼吸停半拍。` |
| 不要分屏 / 不要多画幅 | `一个画幅，实时速度，一镜到底。` |
| 不要炫技运镜 | `机位固定，只有手持的呼吸浮动。` |
| 不要多手多指 / 不要穿模 | `画面里只有两只手：左手握着电筒，右手空着。` |
| 不要 AI 感 / 不要塑料感 | `皮肤有毛孔与油光，布料有纤维与折痕，金属有划痕。` |
| 不要让角色变脸 | `脸上每一帧都是参考图那张脸。` |
| 不要天空更亮 | `天空是画面里最暗的区域。` |
| 不要出现现代物件 | `街上只有 1978 年的车，橱窗里只有那时的货。` |

**注意最后两行**：像「不要天空更亮」「不要出现现代物件」这类，**正面化的关键是点名要出现的那一版**——
把"不要什么年代的东西"写成"只有那个年代的东西"。这是最有效的一种翻译。

### 4.3 唯一允许否定的地方：约束清单

**例外只开一个口子：正向约束／负面约束这一节的"清单体"。**

源技能（`seedance-master-zh` 01 / 04）里，`NEGATIVE CONSTRAINTS` 是**独立一节**，写法是**短句列举**：
`无多余人物 · 无慢动作 · 无字幕 · 无CGI · 不允许空镜头`。这种清单用否定反而更省字数、更不容易被忽略——
因为**约束的作用是排除，不是描述**。

| 文本类型 | 用哪种 | 例 |
|---|---|---|
| **描述性正文**（场景／参考／光学／光／物理／时间轴） | **全正面**（§4.2） | `画面填满整个画幅，只有图像内容。` |
| **约束清单**（`正向约束`／`负面约束` 一节） | **允许否定**，短句列举 | `无多余人物 · 无慢动作 · 无字幕 · 无配乐 · 无CGI` |
| **单条锁**（`正向锁定` 里的一句） | **全正面** | `每一刀都在此表内。` |

**判断标准：** 这句话是在**描述一个状态**（→ 正面），还是在**排除一种可能**（→ 可否定）。

> 一条实测佐证：用户提供的一条效果很好的 15 秒提示词，约束清单里用了 10 处否定，
> 而它的描述性正文全部是正面陈述。**两者并不矛盾，混着用才出问题。**

**否定只留在一个地方：自检清单。**
`banks/C-negative-bank.md` 里的禁令表是**给你自己查稿用的**，不是给你往成稿里粘的。
用法：写完正面稿 → 拿 C 库逐条对一遍 → 发现漏了什么 → **把漏的那件事用正面句补上**。

**一个完整的改写示例（同一件事，两种成稿）：**

> ✗ 全否定版（每句都在说"别"）：
> `六镜一次生成，不许未指定的剪切，不许随机蒙太奇，不许 fade / crossfade / dissolve。无配乐、无旁白、无画外音、无字幕。不补平光、不过曝。不要慢动作、不要分屏。`

> ✓ 全正面版（每句都在说"要"）：
> `六镜一次生成，每一刀都在此表内：0.0 / 1.0 / 6.0 / 12.0 / 20.0 / 26.0 秒，每刀落在动作中段。声音只有现场声：风过草叶、椅木轻响、鞋底踩草。只有画内的人声与现场声。画面填满整个画幅，只有图像内容。曝光只给落日与逆光轮廓，脸留在暗部，只有轮廓光与地面反弹揭示细节。全片实时速度，一个画幅，一镜到底。`

两版字数几乎一样，但**右版每一句都告诉模型该做什么**。

### 两条必须说清的边界

**① `OPENING STATE` 是文字，不是图。**
第 10 条里的"开场状态"指的是：用几句话写死 **t=0 时谁在哪、朝哪、手上有什么、什么已经在动**。
它**不是分镜首帧图**，也**不需要你为每个镜头产出一张图**。这套工作流是**多参直接生成**——输入是资产图（角色板/地点板/道具板）+ 文字，输出是视频；中间没有"首帧图"这一环。

**② 参考图这一节有两部分：绑定清单 + 一句职责声明。**

**第一部分 · 绑定清单（必须完整）。** 本次要用的每一张图都要出现，并且用 `{{ref N}}` 绑上；逐张写它**拥有什么 / 不拥有什么**。资源少一张，模型就少一条约束——这一部分写短了，整条提示词的稳定性直接掉一档。格式与字数见 §5.2 第 2 槽。

**第二部分 · 职责声明（只写一句）。** 关于"这张图怎么用"，只写下面这一句，写完就停：

`本参考图只控制身份与几何，不控制构图、裁切、机位高度或角度。`

这一句用于替掉"从参考图第几帧开始""把第一张图当开场帧""参考图作为关键帧"这类描述——它们会让模型照抄那张图的构图，你拿到的是近似复制品而不是新机位。一句正面声明就够，不必再补任何解释。

> **别把第二部分当成整节的规格。** §4.2 讲的是"用正面声明替代否定"，**不是**"参考图只写一句"。
> 绑定清单该多长就多长：中文约 950 字、英文约 1,550 字（见 `banks/G-prompt-depth.md` G.2）。

**第二部分还有第二种写法，也是允许的：限定用途。** 当参考图是**视频／前一段尾段／构图参考**时，它的用途边界必须写清，否则模型会把它当成本镜的模板：

`{{ref 5}}——上一段（0–30s）的尾段影像：只提供运动方向、手持呼吸的节奏、光向、场地与人物外观；本段的动作与走位由提示词给出。`

`{{ref 4}}——构图参考：只提供人物在画面中的位置关系；光、景别、机位高度由本镜提示词给出。`

> **允许的：「这张图用来干什么／不用来干什么」的职责限定。**
> **禁止的：「从这张图的第几帧开始演」「把第一张图当开场帧」——那是规定动作起点，会让模型照抄构图。**
> 两者只差一句话：**限定用途是划边界，规定起点是交出控制权。**

### 第 4 条的补充：画幅进不进正文（实测数据在这里）

我一开始想给它开个"当画幅是长相时可以写"的例外。**实测把这个例外否掉了**：

| 实测（1,469 条视频提示词，逐条比对 `width×height` 推出的真实画幅） | |
|---|---|
| 在正文里写了画幅 | 637 条（43%） |
| 写对了 | 561 条（88%） |
| **与真实输出画幅矛盾** | **76 条（12%）** |
| `red-flag` | 19 条全错 —— 正文写 `21:9`，实际输出全是 16:9 → **100% 矛盾** |
| `hell-grind` | 23 条错 —— 反向：正文写 `16:9`，实际是 21:9 |
| `oneiric` | 18 条错 |
| `anerneq` / `passport-rush` / `vengeance` / `if-you-stop` | 基本全对（51/81/113/97 条对，0–4 条错） |

**规律：错不在"写了画幅"，错在"画幅是抄来的"。** 写对的片子，正文画幅与项目画幅一致且长期没变；写错的片子，提示词是从别的项目复用来的、或者中途改过画幅而正文没跟着改。这是典型的**陈旧常量**故障。

**所以第 4 条收紧为：**
- **默认不写。** 画面形态靠 `OPTICS` 的结果短语 + `STYLE` 的器材/质感词表达——那才是真正控制"长相"的地方。
- **要写就必须是"项目常量"，不是逐镜手写。** 一旦写定，与 UI 里的 `aspect_ratio` 绑定，改一处必须全局替换。
- **判断标准：** 这一行能不能保证永远与输出参数一致？不能 → 删掉。

**另一条不该被忽略的细节：** `@TAG` 命名（人类用的可读索引）**不进提示词**；机器层用 `{{uuid}}`。所以一份项目里同时存在两套标识是正常的——人读 tag，模型读 uuid。

## 5. 提示词骨架

下面这个顺序**不是设计出来的，是数出来的**：跨 12 部片、656 条去重后的视频提示词里，每块的平均出现位置与覆盖案例数（`_analysis/E_cross_case_patterns.md` §3）。

### 5.1 四层结构 —— 顺序为什么是这个顺序

26 个块的平均位置落在四个几乎不重叠的区段里。这不是排版习惯，是**阅读重力**：

| 层 | 位置 | 块 | 在回答什么 |
|---|---|---|---|
| **① 身份** | 10–35% | `SCENE CONTEXT` · `ACTIVE REFERENCES` · `LOCATION MAP` · `FORMAT MODE` · `CHARACTERS` · `OPENING STATE` | **这是什么镜头，谁拥有它，t=0 时里面已有什么** |
| **② 光学与身体** | 40–57% | `STYLE` · `OPTICS` · `CAMERA` · `COMPOSITION` · `COLOR` · `LIGHTING` · `ACTION TIMING` · `PERFORMANCE` | **它怎么被拍，什么在动** |
| **③ 模拟** | 65–77% | `PHYSICS` · `CONTINUITY` · `AUDIO` · `FINAL FRAME` | **什么必须真实地服从物理** |
| **④ 强制** | 80–88% | `LOCK ANNOTATION` · `POSITIVE LOCKS` · `NEGATIVE` | **什么不许漂** |

**最重要的一条反直觉发现：锁和禁令写在最后（85–87% 位置），不是开头。**
它们是**回述**，不是前置声明。先让模型看到整个世界，再用最后一句话把它钉住。（例外：`oneiric` / `vengeance` 会把 `GLOBAL … LOCK` 放在最前面，取"先读、绝对"的语气——两种都有效，但别混用。）

### 5.2 必备的 13 块（≥10/12 部片使用）

按实测顺序。**这 13 块是下限**；其余 13 块见 `banks/D-block-orders.md`，按需加。
**中英文标签都给出来了**——本版用中文栏，英文版用英文栏（§4.1）。

| # | 槽（中） | 槽（英） | **写多少字** | 这一节要问完什么 |
|---|---|---|---|---|
| 1 | `场景背景` | `SCENE CONTEXT` | **约 780** | 情境 + 这一条要交付什么 |
| 2 | `参考图` / `激活参考` | `ACTIVE REFERENCES` | **约 1,550** | 先一句汇总绑定（共几张 + 每张 `{{ref N}}` 是什么），再一句职责声明，然后逐张 1–3 句写拥有/不拥有 |
| 3 | `拍摄模式` | `FORMAT MODE` | 约 200 | 几镜、在哪秒切、总时长 |
| 4 | `空间地理` | `LOCATION MAP` | **约 900** | 家具/方位/距离逐个点名 + 影子朝哪 + 轴线 |
| 5 | `开场状态` | `OPENING STATE` | **约 560／每镜一段** | 每人：x%/y% 位置·朝向·手在哪·重心在哪 |
| 6 | `光学镜头` / `景别` | `OPTICS` | 约 480 | 每镜视角 + 相机距离 + 结果短语 |
| 7 | `风格` | `STYLE` | 约 410 | 一行锚点 + 60:30:10 色比 + 质感词 |
| 8 | `运镜` / `机位` | `CAMERA` | 约 540 | 逐镜写，或写"锁定"及理由 |
| 9 | `动作时间轴` | `ACTION TIMING` | **约 1,500** | 镜内再分 3–5 个时间片，每片一个微事件 |
| 10 | `光照` / `灯光` | `LIGHTING` | 约 450 | 源·色温·方向·明暗侧·曝光优先·**允许高光清单** |
| 11 | `物理` | `PHYSICS` | **约 640** | **逐材质**写行为，不写"真实" |
| 12 | `音频` / `声音` | `AUDIO` | 约 480 | 底噪 + **带秒数的声事件** + 远近层次 |
| 13 | `正向锁定` / `硬性` | `POSITIVE LOCKS` | **约 1,780** | **10–20 条锁**，不是 1–2 条 |

### ★ 每槽写多深（这一列比槽名更重要）

**每一节是一整段，不是一行。** 上表是结构化真实提示词的每节中位字数（**按形态分列，不要相加**）：

| 形态 | 单镜 | 2–3 镜 | 4–6 镜 | 7 镜以上 |
|---|---|---|---|---|
| **中位总字数** | **6,700** | 6,200 | **10,400** | 11,500 |

> 一条 6 镜 30 秒的提示词，**8,000 字符往上是正常区间，上限不设**（中位参考 10,400–14,200；9,000、15,000 都正常）。
> 真正的红线是**下限**：多镜低于 5,800、单镜低于 4,000，就一定是某一节被写成了一行。

**「感觉」不在形容词里，在这五样里：**
① 具体名词（不是"潮湿"，是"结着灰和油的水面，反光是碎的"）
② 可量测（`5200K` / `1.4 米` / `x36% / y64%` / `15.7s`）
③ 微事件（每 1–2 秒一个具体小动作：罐头滚动、钢件弹两下、水冠起来）
④ 材质行为（湿帽衫"粘着拖、不飘"；湿头发"慢慢剥离、慢半拍"）
⑤ 声光时序（`21.4s 全片最响的一下`）

**每节至少命中 3 样。** 完整的每节颗粒度清单、"薄→厚"逐块改法、以及各形态字数区间 → **`banks/G-prompt-depth.md`**。

> 中文标签是从语料里数出来的，不是我翻的：`场景背景` 108 次、`空间地理` 175、`风格` 295、`声音` 580、`物理` 194、`光照` 250、`动作时间轴` 79、`拍摄模式` 68、`激活参考` 91、`正向锁定` 79、`硬性` 507。
> **两套写法都能用**：英文标签 + 中文正文（Cully 式），或中文标签包在【】里（kok-boru-film 式）。选一套，别混。

> **参考怎么绑（`{{ref N}}`）：** 光写「女主角色参考」等于没绑——**每一个参考都要有 `{{ref N}}`**。
> **图片、视频、音频共用同一套编号**，按绑定顺序连号排下去，一个参考一个号、只用一次。
> 三行就够，写在 `参考图` 这一节的开头：
>
> ```
> 本段共五个参考：{{ref 1}} 女主角色、{{ref 2}} 三名同伴角色、{{ref 3}} 潮湿沙滩与海边木栈道场景、
> {{ref 4}} 沥青球场／海边水泥广场／浅水区场景、{{ref 5}} 上一段（0–30s）的尾段影像。
> 图片与视频参考只控制身份、几何与外观，不控制构图、裁切、机位高度与角度。
> ```
>
> 然后逐个补 1–3 句"它拥有什么 / 不拥有什么"。**汇总那一行的作用是说清有几个、谁是谁**——检查时一眼就能数出有没有漏。
>
> **视频参考单独写一句职责**（它最容易越界去接管动作）。照这个句法写：
>
> `{{ref 5}}——上一段（0–30s）的尾段影像参考：只提供运动方向、手持呼吸的节奏、光向、场地与人物外观；本段的动作与走位由提示词给出。`
>
> 音频参考同理，只写它提供什么（`{{ref 6}}——配乐轨：只提供 tempo 与段落起伏；画面动作与它对位，不反过来。`）。
> 语料原文用的是尖括号 token 与资产 uuid；本包统一改成**花括号 token `{{ref N}}`**，编号方式不变。

> **第 5 槽是文字块。** 它不产出图，也不假设某张参考图就是这一镜 t=0 的画面。写的是"模型在 t=0 应该看到什么"。

**条件块（按镜头加）：** `CHARACTERS`（有常驻角色）· `PERFORMANCE` + `ACTING OBJECTIVES`（表演是主题）· `CONTINUITY`（跨镜）· `COLOR`（STYLE 不带调色）· `SINGLE-TAKE LOCK`（一镜到底）· `TEXTURE/MATERIAL`（材质是卖点）· `COMPOSITION`（构图是卖点）· `NEGATIVE`（见下）。

**从不进成品的两块：** `WORKFLOW/META` 与 `NOTES` 是**写作时的脚手架**（目标、平台、UI 参数、缺陷记录）。它们存在是因为工作台保存了整个工作文档，**不是模型需要**。发出去之前删掉。

### 5.3 三条从数据里读出来的硬结论

1. **`AUDIO` 覆盖 12/12 部片 —— 唯一从不缺席的块。** 每一条提示词都要写声音，哪怕只写"只有对白和室内底噪，无配乐"。
2. **`NEGATIVE` 块只在 5/12 部片出现，且位置在最后。** Cully 的 300 条里**一条都没有**——它把禁令全部改写成正面结果，塞进所属那一节。
   **但请注意：这里没有唯一正解，两种都能出片。**
   - `ANERNEQ` 走向另一极端：**74 项负面尾巴**（最长 188 项），是全提示词里最大的单一块，正片照样成立。
   - `VENGEANCE IS MINE` 走第一条路到极致：**0 个负面块**，改用 38 条具名正面锁（`THE X LOCK` / `THE X COUNTER`），并在文件里写明"一个负面句会生成那个被禁止的东西"。
   - `HELL GRIND` 在中间：小的负面尾巴 + 把动作改写成正面。
   **可操作结论：** 这是**一部片级的策略选择**，选一条并贯穿全片。默认选"正面锁"（更容易执行、失败更少）；只有当你的片有大量"必须时时刻刻防住"的元素（生造语、水印、字幕、特定器械）时才改用片级禁令脊椎。
3. **块是可复用的"钉板"。** 同一批描述块被复用几十到上百次（例：含 `100% match…` 的提示词 170 条，其中完整句 `100% matches the reference` 117 条）。**写一次，逐字粘贴，只改 10–20%。** 这是"模型无记忆"的直接推论——复用不是偷懒，是唯一能保证一致的方法。

**只填命中的槽。** 单镜无对白，可整段删表演与台词。删槽不是偷懒，是减噪。

> 各家流派对照（26 块跨案普查 / ANERNEQ 20 槽 / CINEDANCE 12 槽 / VENGEANCE 14 槽 / 图像车道）→ `banks/D-block-orders.md`。

**语言按输入语言走**（细则 §4.1）：中文提问用中文（`【…·硬锁】` 内联标注是这个语料里常见的中文硬锁写法），英文提问用英文。**模型不在乎语言，在乎结构是否可执行。**

### 5.4 骨架是通用的，写法是私人的

这一点很重要，否则你会把某个工作室的排版当成行业规范。我们在**同一个案例库里数出了至少三种完全不同的编码方式**：

| 写法 | 长什么样 | 出现在 |
|---|---|---|
| **大写字幕块**（本文件默认） | `SCENE CONTEXT` / `OPTICS` / `LIGHTING` … | Cully、Passport Rush、Red Flag 等多数案例 |
| **叙事小标题句** | `THE IMAGES` / `WHAT WE SEE OF HER` / `HOW THE WATER IS MADE` | `if-you-stop-loving-me-ill-die` |
| **JSON 对象** | `SCENE{Setting, Subject, Geographic Context}` / `HEX VALUES[8–10]` / `CAMERA_AND_LENS{…}` | `zephyr` 的 `soul_cinematic` 车道 |

**共同的不是排版，是四件事：**
1. 角色化 / 定域的参考图（谁拥有身份、谁拥有空间）；
2. 开场状态（t=0）与走位的显式声明；
3. 光与镜头作为**结果**而非器材；
4. 一条把禁止写成正面结果的收尾。

**所以：** 拿不定用哪种写法时，用本文件的默认；但如果你在改一条已经能出片的提示词，**保留它原来的写法**，只补它缺的那四件事。换排版不是改进。

### 5.5 类型不改变骨架，改变的是"装配什么"

跨 4 个类型（动作喜剧 / 爱情 / 黑色 / 恐怖）的对比结论：

- **骨架不变**：背景 → 定域参考 → 镜头/光学 → 时间轴 → 物理材质 → 光 → 声 → 锁。
- **变的是四样**：
  - **装配清单**：动作片要"某物的物理法则"（轮胎永远正圆、悬挂才允许形变）；对白片要"表演任务 + 台词"；氛围片两者都可无。
  - **命名风格**：技术式（`OPTICS`）还是叙事式（`HOW IT MOVES`）。
  - **禁令放哪**：内联锁句 / 片级禁令块 / 完全融进正面散文——三种都真实存在且都有效。
  - **密度**：实测每分钟成片对应 **1.3–22 条**不同的视频提示词，差 17 倍。**密度跟类型走，不跟时长走。**

> 推论：先问"这部片的信息在动作里还是在表演里"，长度跟着这个答案走。

### 5.6 五个锁 —— 每镜都要过一遍的强制清单

源技能（`seedance-master-zh` 01）把防飘拆成五个**具名的锁**，每镜逐条写。归纳版原来把这些内容散在各处，
现在收成一张可勾选的表——**写完之后逐行对，缺哪行补哪行。**

| 锁 | 锁的是什么 | 一行的写法 |
|---|---|---|
| **首帧占位锁** | 硬切之后的**第一帧**必须已经有什么（人或物，以及数量） | `硬切后首帧已包含她胸部以上，手机已放下，嘴即将张开。` |
| **空间走位锁** | 谁在画面的哪一侧、朝哪、距谁多远 | `她位于画面右下三分之一，面朝他，两人相距约两米。` |
| **视线与身体朝向锁** | 谁在看谁、身体朝哪个方向 | `他的视线锁在她脸上，身体朝画面右。` |
| **地标邻近锁** | 人物与**固定地标**的距离关系（防整体移位） | `她站在门框左缘外侧约一步，肩与门框平行。` |
| **多镜连续性锁** | 切完之后什么必须没变（身份／服装／光向／道具手位） | `每一刀后是同一张脸、同一件外套、同一侧光。` |

**用法：** 这五条**不是五段散文，是五句锁**。写完整篇之后从上面往下核一遍，
哪一条写不出来，说明那一镜的空间或连续性还没想清楚。

> 为什么必须写"地标邻近"：模型最容易犯的错不是人物走形，而是**整个人连同空间一起平移**。
> 把人和一个不动的地标绑在一起（门框、柱子、桌沿、墙角），漂移立刻被压住。

## 6. 交付前闸门

发送前逐项过。任何一项 ✗，回 §2 第 ④ 步改到全过为止。

> 源技能把这一节叫「**输出前的静默自检**」——写完之后自己在心里逐条问一遍，**不要**把自检过程写进提示词里。

- [ ] **语言检查**：提示词语言 = 提问语言？块标签**全篇只用一套**？台词保持原语言没被翻译？
- [ ] **条数检查**：这场戏该做几条？`ceil(总时长 ÷ 模型上限)` 算过了吗？每条都开到了上限吗？余数 <3 s 时改成均分了吗？
- [ ] **一句话自检**：能用"某人想要什么、在哪、什么光、什么镜头、做什么"复述这条提示词吗？
- [ ] **引用检查**：`ACTIVE REFERENCES` 里每张图都用 `{{ref 1}}`…`{{ref N}}` **真的绑上了**吗（不是只写名字）？每张的角色写清了吗？每个只出现一次、编号连续吗？（图片、视频、音频同一套 `{{ref N}}` 连号）数量在预算内（9 图 / 3 视频 / 3 音频）吗？
- [ ] **开场状态检查**：`OPENING STATE` 是**文字**，写清了 t=0 时谁已在场、朝哪、手上有什么吗？（不是首帧图）
- [ ] **参考句检查**：全文只有一句职责声明（`本参考图只控制身份与几何…`）？删到只剩这一句。
- [ ] **身份检查**：每个角色都挂了资产图 + 最少锚点，且写了"100% 匹配参考"？
- [ ] **镜头检查**：一种内容类型？视角 + 相机距离都有？没有混焦段？
- [ ] **光检查**：光源/方向/明暗侧/曝光优先级 4 项都有？没有"平光无影"？
- [ ] **时间检查**：有数字吗？每个动作放得进它的时间窗吗？多镜的每一刀都有绝对秒数吗？
- [ ] **多镜检查**（若多镜）：逐镜定义了？账本（服/伤/道具/方向/光向）都续上了？`TOTAL RUNTIME` 写了吗？
- [ ] **拆条检查**（若拆了多条）：每条都重写了光/镜头/服/伤/道具/方位？条与条接头处对得上？**没有写"接上一条"**吗？
- [ ] **声音检查**：只有剧本台词？没有旁白/字幕/画外音？环境与人声关系写了？
- [ ] **参数检查**：正文里没有时长/画幅/分辨率？（或：写了，且确认与 UI 恒定一致）
- [ ] **全正面检查**：成稿里还有以「不要 / 不许 / 无 / 别 / 禁止」起头的句子吗？**全部翻成正面的状态**（对照表见 §4.2）
- [ ] **抽卡检查**（要出片时）：抽之前写下了判定标准吗（五维 1–5 分）？这一轮只变了一个变量吗？连抽三次不中，回去改提示词了吗（不是继续抽）？抽中的那条归档成锚了吗？系统性问题（脸崩/空间乱）当成运气了吗？
- [ ] **五锁检查**（§5.6，逐条过）：**首帧占位**——每个硬切后的第一帧已经有什么？**空间走位**——谁在画面哪一侧、距谁多远？**视线朝向**——谁看谁、身体朝哪？**地标邻近**——人物与哪件不动的地标绑定了距离？**多镜连续**——切完什么必须没变？
- [ ] **台词检查**（有台词时）：说话人标清了吗？台词逐字保留原语言了吗？重音落在哪写了吗？声音环境（被遮挡／近麦／回响）写了吗？对白与动作时间轴的秒数对得上吗？
- [ ] **约束清单检查**：约束是否写成短句清单（这一节**允许否定**，见 §4.3）？描述性正文是否全正面？两者是否混了？
- [ ] **锁句检查**：该锁的都锁了吗？`正向锁定` 10–20 条，每条是一个**正面状态**？
- [ ] **深度检查**：总字数过了基线下限（§5.2 / `banks/G-prompt-depth.md`）——上限不设？每节都过了颗粒度清单？`正向锁定` 有 10–20 条？`物理` 是逐材质写的？`音频` 有带秒数的声事件？
- [ ] **模型检查**：有没有写只有人会懂的意图（"他感到背叛"）？改成可见行为。

## 8. 三条元规则

1. **不确定就少写。** 一条短而确定的指令，胜过长而含糊的描述。所有案例里最短的提示词（1.2 KB）和最长的（12 KB）都能出片，差别在**每一句是否可执行**。
2. **失效优先于优雅。** 你的目标是让模型无法误解。宁可笨拙具体。
3. **记录，才可复现。** 每次失败都写下"症状 → 我改了什么"，这是这套体系里最被低估的一步（案例里有一份真实的「工作文档 → 缺陷台账 → 补丁日志 → 定稿」范本，见 `cases/adiliada.md`）。
