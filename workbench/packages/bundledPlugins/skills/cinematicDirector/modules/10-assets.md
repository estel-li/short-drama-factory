# 10 · 资产 —— 资产车道：板与外科式修图

## 这个模块解决什么

视频的一致性上限由**资产**决定，不由提示词决定。本模块管三件事：造板（角色 / 地点 / 道具）、改板（外科式修图）、以及什么时候该改词、什么时候该重建资产。真实语料里这条车道是**短的**：图片提示平均 1.6–2.7 KB，视频提示 8–10 KB——图片是外科手术，视频才是密封文档，两者不能互相套用。

**定位：** 资产图（角色板 / 地点板 / 道具板）的用途是作为视频生成的**参考输入**被引用，不是当前镜头的首帧；它们跨镜复用到整个项目。

**语料依据：** 1954 条提示中 484 条属图片车道（`nano_banana_2` 113、`soul_cinematic` 100、`seedream_v5_pro` 97、`gpt_image_2` 46、`seedream_v4_5` 42、`soul_cinema_studio` 29 …）；单案例 adiliada 118 条中 93 条图片、25 条视频，图片均值 0.9–2.4 KB，视频 8.3 KB。

**细表：** 图片车道的模型路由、两套写法、角色一致性、插画漂移、色板与编辑车道，逐条见 `banks/I-image-models.md`（18 条）。

**何时加载：** 新项目开工；需要跨镜同一张脸；要改已有资产（换装、伤口、天气、年龄）；需要地点板或道具板；risk=faces/hands。
**不加载：** 单镜且无参考图；纯文生视频（走 03 / 09）。

## 提示

### T-10-01 · 先造资产，再拍镜头
**为什么：** 后面每一颗镜头都在"消费"这张板；板的身份越稳，提示可以越短，返工越少。
**失效表现：** 边拍边找脸；同一角色靠长段文字描述，越写越不像。
**说：** 一个角色 = 一份文字描述 + 一张板；两者每次都成对出现、逐字粘贴。

### T-10-02 · 图片短，视频长
**为什么：** 图片车道是"一次外科手术"，只解决一件事；视频车道才需要把空间、光、表演全部密封进去。用视频的写法写图片会稀释指令。
**失效表现：** 图片提示写到 6 KB 还在堆形容词，出来的板反而更糊；或用一句 200 字的图片提示去拍视频，画面全靠猜。
**说：** 图片：`一个资产提示词只解决一个目标。1.6–2.7 KB。` 视频：整段密封文档，8–10 KB 是常态。

### T-10-03 · 三类板，各管一件事
**为什么：** 身份、地理、物件是三种不同的控制目标；混在一块板上，模型会把它们互相污染。
**失效表现：** 角色板上画了房间（房间的墙色跟着角色进每一镜）；地点板上站了人（人被当成布景复制）。
**说：** 角色板只交身份；地点板只交空间；道具板只交物件。

### T-10-04 · 角色板 = 三个面板 + 一张特写
**为什么：** 全身正面、全身背面、脸部特写，三张合一张图，模型才能拿到"同一个人"的多角度证据。
**失效表现：** 只有一张正面照，侧脸和后脑全靠模型编；换一个角度就换一个人。
**说：** `同一张照片级写实图被分成若干面板，共用一张连续的中性灰无缝背景纸：全身正面、全身背面，加一张头肩特写——同一个人，所有面板彼此一致。` `[译]`

### T-10-05 · 全身板去掉脸
**为什么：** 全身面板上的脸又小又软，而那正是模型会抄进远景的脸；把头去掉，脸的唯一来源就只剩特写。
**失效表现：** 远景里人物的脸糊成一团——因为模型忠实地复制了板上的小软脸。
**说：** `把全身面板上的头去掉；唯一的面部来源是那张特写肖像。` `[译]`

### T-10-06 · 特写要两张：笑与不笑
**为什么：** 否则模型第一次遇到角色大笑时会自己发明牙齿和下颌行为，笑出来像别人的嘴。
**失效表现：** 角色一笑就换人；牙齿数量、牙龈、嘴角弧度每次不同。
**说：** `两张特写：一张无表情，一张微笑——同一张脸、同一副牙齿、同一个下颌。` `[译]`

### T-10-07 · 中性灰 + 柔光，不写"棚"
**为什么：** 背景要纯净、光要软、无硬阴影、无过曝高光；而"studio"这个词可能让模型把灯架和主光画进画面，那盏主光会跟着进每一颗视频镜头。
**失效表现：** 板上出现摄影棚器材；或者板自带一盏主光，所有镜头都被这盏光锁定。
**说：** `中性灰无缝背景纸，柔和均匀的漫射光，阴影轻、反差低，高光不过曝，无影棚、无器材、无墙体。` `[译]`
**注：** 语料里也有写 `studio backdrop` 并成功的板；冲突只在"器材被画进画面"时成立，稳妥做法是用上面这句。

### T-10-08 · 板上禁止边缘光
**为什么：** 一张带漂亮轮廓光的板，会把那道光拖进每一个场景，并让角色不再对真实光源作出反应。
**失效表现：** 无论日戏夜戏，人物肩线永远有一圈同样的光；换场景不换光。
**说：** `不要轮廓光，不要边缘辉光——板本身不携带任何会被场景继承的光。` `[译]`

### T-10-09 · 板上双手要空
**为什么：** 在板里出生的道具永远没法被放下、扔掉或拿走——它已经和手长在一起了。每个物件都该是独立资产。
**失效表现：** 角色放下枪，枪还粘在手上；或者每颗镜头手里都凭空多一个东西。
**说：** `板上的手保持空着；每一件道具都是独立资产。` `[译]`

### T-10-10 · 面孔锁：把脸写成"不可触碰区域"
**为什么：** 修图和换装时，模型最想"顺手美化"的就是脸；必须用最高优先级把它钉住，并给出一个可勾选的禁区清单。
**失效表现：** 换一件外套，脸被磨皮、被美化、被换年龄；疤痕、痣、肤色悄悄变了。
**说：** `绝对最高优先级——不要改脸：脸必须与源图在每一个方面 100% 一致——同一身份、同一五官、同一骨相、同一肤色、同一头部角度、同一视线与表情；把脸当作锁死的、不可触碰的区域——不要重塑、不要美化、不要改脸型、不要改年龄、不要瘦脸、不要磨皮、不要重打光。` `[译]`

### T-10-11 · 修图四行语法
**为什么：** 修图不是重写，是"改一处 + 钉住其余"；把不变的东西逐条列出来，模型才没有自由发挥的空间。
**失效表现：** 只写"把外套换成黑色"，结果背景、光、构图、脸全被重画。
**说：** `修图：[一句话目标]。CHANGE: [只改这一处]。PRESERVE EXACTLY: 脸、身份、皮肤纹理、头发、疤痕、姿态、服装、布局、背景、光向、颗粒、构图、调色。ONLY CHANGE: [再写一遍这一处改动]。100% identical otherwise。` `[译]`
**注：** 语料里另有"连贯体"写法（`Edit ONLY the hair … keep every other element 100% identical and untouched — preserve the exact framing, the layout, the exposure, the grade, the grain, the light direction`），原则与四行语法完全相同，任选一种。

### T-10-12 · 一次只改一个主题
**为什么：** 每多一个变更，PRESERVE 清单就多一处漏洞；一个主题可以拆成编号子项，但不能一遍里换装又改脸又换背景。
**失效表现：** 一遍改完，客户说"太过了"——实际是改得太多，不是改得不对。
**说：** `CHANGE 1 —— 减少面部伤口：右眉上方一道小切口、右颧骨一处擦伤；去掉其余所有切口。PRESERVE EXACTLY: ……` `[译]`

### T-10-13 · 变体只改变化的部分
**为什么：** 整板重渲会让皮肤纹理和身份在模型里过第二遍而退化；只在原图上改，才保得住质感。
**失效表现：** 第二版还像，第五版已经换了人；皮肤越来越"AI 滑"。
**说：** `拿原始板，只改变化了的部分——另换的衣服、伤口、浸湿的布料——其余一律不动。` `[译]`

### T-10-14 · 新变体独立命名，不覆盖旧资产
**为什么：** 覆盖等于把历史版本删掉，之后就再也回不到"上一版才对"的那张板；版本号是唯一可回溯的锚。
**失效表现：** 想回退到三天前的脸，发现原图已被覆盖；同一场景里两版板混用。
**说：** 命名格式统一：`@char_[项目码]_[角色名]_v9`（角色·项目码·名·版本）· `@loc_[项目码]_[地点]_s6_v2`（地点·场景·版本）· `@prop_[项目码]_[道具]_s26_v2`（道具·场景·版本）。
**同一份空间的不同状态是不同资产：** 白天 / 夜晚 / 雨 = 三个资产；道具两种状态 = 两个资产；车的前舱与后舱内饰也各自独立。

### T-10-15 · 地点板用 3/4 视角
**为什么：** 正面拍的房间是平面墙纸，模型读不出体积，画面边缘以外每次都会自己发明新环境；3/4 给纵深，还能从一个板推出近乎一圈角度。
**失效表现：** 换机位就换房间；侧墙、天花板、纵深全靠猜。
**说：** `地点用宽的 3/4 视角，永不用正面——体积要足够让摄影机在其中移动。` `[译]`

### T-10-16 · 地点板三件套：锚点 + 一条光逻辑 + 无人无武器
**为什么：** 有锚点才能把调度写实（"人在灯旁、面向门"）；一条光逻辑才能让每个机位的光一致（一个光源、一个投影方向，绝不两个太阳）；有人有武器会让布景被当作可复制元素。
**失效表现：** 演员"在房间里"随机站位；同一场景两个机位出现两个方向的影子；地点板里的人影出现在每一颗镜头。
**说：** `画面里留一个锚点——一根柱子、一盏灯、一把歪椅子。一个光源，一个投影方向，绝不两个太阳。无人，无武器。真实表面：锈、裂缝、胶带、指纹、油渍、水痕。` `[译]`

### T-10-17 · 道具板用产品照语言
**为什么：** 道具在"产品摄影"语境里最真实；同时必须显式反掉 3D/CGI 质感，否则会得到塑料渲染。
**失效表现：** 道具像游戏资产；材质没有磨损、没有指纹；文字/标签糊掉。
**说：** `[道具] 的影棚产品照，放在中性中灰无缝背景纸上，柔和均匀的影棚光，真实的产品摄影，真实材质，细腻胶片颗粒，不是 3D/CGI，没有塑料渲染感。` `[译]`
**注：** 产品照是"不写 studio"规则的合法例外——孤立物件配无缝纸背景时，"影棚产品照"这套语言正是该用的。

### T-10-18 · 压力测试与修复顺序
**为什么：** 一张好看的板什么都不能证明；资产要在运动里活下来才算数。崩了时先改词，同一个问题第二次出现才重建资产。
**失效表现：** 板审通过，实拍十次十次不像；或者反过来，明明词写错了却把板重做三遍。
**说：** `十次生成——不同动作、不同景别、不同地点——十次里十次都认得出是他。把角色和他的地点放在一起测。先改词；只有同一个问题再次出现，才重建资产。` `[译]`

### T-10-19 · 资产图是长期引用资产，不是一次性首帧
**为什么：** 实际流程是多参直生成：同一张角色板会出现在几十条提示词里。若把每镜都当成"要新做一张图"，成本爆炸，身份反而更漂（每张图都略有不同）。
**做法：** 一套资产 → 一个固定版本号 → 所有镜头引用**同一张**；要改走"只改变化的部分"（T-10-12 / T-10-13），不做重渲染。
**失效表现：** 每个片段都去做一张新图，预算耗尽；角色在不同图之间已经开始漂移。
**说：** `同一张角色板、同一个版本，全片每一颗镜头都引用它。` `[译]`

### T-10-20 · 先认模型，再下笔
**为什么：** 图片车道只认这几个名字：角色走 Higgsfield Soul 2.0（**没有 21:9**）、地点走 Soul Cinema（21:9 在这里）、参考图组可先让 Cinema Studio AI Cast 自动出、道具与编辑走 Nano Banana Pro（NBP）、质感只走 Seedream 4.5、最后手段是 GPT Image 2。模型先定，画幅与参考图数量才有意义。
**失效表现：** 拿 Soul 2.0 做 21:9 角色板，人物被裁、脸被挤扁；或拿 Seedream 去改一处细节，整块表面被重画。
**说：** 先写一句"这一张走哪个模型"，再写提示词；逐模型的写法、画幅与参考上限见 `banks/I-image-models.md` §1。

### T-10-21 · 三种板各有专长模型与画幅
**为什么：** 三种板的分工不是并列的，是三种不同的生成任务：角色表走 Soul 2.0（画幅 16:9、质量 2k）；地点板走 Soul Cinema（cinemascope 画幅用 21:9、质量 2k）；道具板走 NBP / GPT Image 2（画幅 1:1，高的道具 3:4，分辨率 2k–4k）——道具是唯一**不**走 Soul 系的生成任务。
**失效表现：** 角色表用 1:1 出，三栏被裁成两栏半；地点板用 16:9 出，cinemascope 画幅被压扁；道具板交给 Soul 系，出来像插画。
**说：** 板型 → 模型 → 画幅三件一起定；三种板的参数与写法见 `banks/I-image-models.md` §1（T-I-01 / T-I-02 / T-I-04）。

### T-10-22 · 外科式修图：只改一处，其余逐字保留
**为什么：** 编辑是"改一处 + 钉住其余"，不是重写；把不变的东西逐条列进 `PRESERVE`，模型才没有自由发挥的空间，收尾的 `ONLY CHANGE` 与 `100% identical otherwise` 是最后一道闸。
**失效表现：** 只写"把外套换成黑色"，背景、光、构图、脸全被重画；或一遍改完客户说"太过了"——那是改得太多，不是改得不对。
**说：** 用外科式模板：`CHANGE` 只写一处，`PRESERVE EXACTLY` 逐项列全，收尾 `ONLY CHANGE: [再写一遍这一处改动]. 100% identical otherwise.`；模板逐字版与分工见 `banks/I-image-models.md` §6（T-I-15 / T-I-16）。

### T-10-23 · 板上的文字：精确文案 + 字体，或正面写成空白
**为什么：** 板上的字只有两种合法处理：要么给精确文案（引号）+ 字体 / 字重 / 颜色，要么在正向里写成空白、无品牌；含糊的 "add text" 会糊，品牌名一出现就会被画上去。帧内文字渲染 NBP 最好。
**失效表现：** 板上的招牌字糊成色块；道具上出现了不该有的品牌名；写"不要 logo"反而画出一个 logo。
**说：** `Write 'GENUINE' in bold red serif on the sign`；板上无字时写 `plain unbranded wrapper, blank matte surface`。

## 速查表

**三类板：谁管什么**

| 板 | 管 | 板上必须有 | 板上禁止 |
|---|---|---|---|
| 角色板 | 身份 | 三视图 + 特写（或四联：两全身 + 两特写） | 道具 · 场景 · 强光 · 器材 |
| 地点板 | 空间 | 3/4 视角 · 锚点 · 一条光逻辑 | 人 · 武器 · 两个光源 |
| 道具板 | 物件 | 产品照语言 · 材质与磨损 · 真实尺度 | 品牌 · 文字（除非指定） · CGI 质感 |

**角色板排布选择**

| 排布 | 内容 | 用在 |
|---|---|---|
| 2 面板 | 正面全身 + 面部特写 | 快速起步、次要角色 |
| 3 列（3-column） | 正面全身 + 背面全身 + 特写（特写用 3/4 角度） | 标准角色 |
| 4 联（4-panel） | 左半：正面 + 背面；右半：两个特写（带/不带遮挡物） | 有装备/面具/双状态的角色 |

**修图模板（逐字可用，`[译]`）**

```text
修图：[一句话目标]。

CHANGE: [只改这一处，描述精确]。

PRESERVE EXACTLY:
- 脸、身份、五官、肤色、皮肤纹理、毛孔
- 头发：长度、剪法、颜色、分缝，完全一致
- 身份标记：疤痕、痣、耳饰——位置与大小不变
- 姿态、构图、面板布局
- 服装与道具：设计与位置都不变
- 背景、光向、影子、调色、颗粒

ONLY CHANGE: [再写一遍这一处改动]。100% identical otherwise。
```

| 造板：角色 / 地点 / 道具 | 生成类（角色与场景模型；道具走产品照模型） | 一次一个目标；不带入下一次的光 |
| 改已完成的板：换装、伤口、天气、年龄 | 修图类优先（能"只改一处、其余像素不变"的模型） | 面孔锁 + PRESERVE 清单 |
| 只救质感：皮肤、布料、表面的"AI 滑" | 纹理修图 | 只做质地，不做定点修改 |
| 最细的局部微调 | 最后的修图手段 | CHANGE 越小越干净 |

**平台参数写在哪：** 支持参数的平台才写进提示（如 `--ar 21:9 --style raw --no people`，语料中地点板即如此）；不支持的模型一律走 UI，提示里不出现 `--ar`、`16:9` 之类（见模块 09）。
