# 11 · 项目技能 —— 把通用工具箱压成「一部片」的规则

## 这个模块解决什么

通用技能（CINEDANCE / ACTING / LIRA）是**编译器**：把一句场景描述编成一条可用的提示。项目技能（project skill）是**这部片的宪法 + 覆写 + 事故复盘**：它决定哪些东西在全片范围内固定（风格、光向、音色、资产名、几何），哪些每镜重写，以及这部片自己踩过的坑。

两者不是"详略"关系，而是**输出契约**不同：CINEDANCE 明确要求"只输出提示，不要解释"，项目技能则要求"锚点逐字照抄、有歧义先问、每个矛盾都要标出来"。没有第二层，150 条提示就是 150 次即兴——同一张脸漂三次、光向跨镜反转、一部片拍成七部。

**具体项目的完整形态**见 `skill/seedance-master-zh/04-anerneq-project-skill.md`（完整形态）与 `05-vengeance-project-rules.md`（轻量形态）。本模块只保留两者共用的**机制**，不保留任何具体项目的专名与私有内容。

**何时加载：** 任何多镜项目（同一部片、同一集、同一支片有 ≥2 个镜头）；**第一镜之前必须先加载**；跨镜连续性有要求；需要固定音色 / 语言 / 资产身份。
**不加载：** 单镜即弃的测试、单张图、纯探索、只需要一个镜头参数的问答。

## 提示

### T-11-01 · 先分清「可复用的编译器」和「不可复用的宪法」
**为什么：** 工具层解决「怎么写一条提示」，项目层解决「这部片到底长什么样」；把两者混在一个文件里，通用规则会被单片风格污染，单片规则又不敢写得足够硬。
**失效表现：** 150 条提示各发明一次风格；同一个角色在三场戏里像三个人；同一场景的光向每镜换一次。
**说：** `每条提示词都是一座孤岛：光、光学、服装、道具、音色与几何，每一镜都从头重新指定。` `[译]`

### T-11-02 · 立项先定负向策略：脊椎式，还是纯正向
**为什么：** 语料里两部片给出**互相矛盾**的两套法：一部把"禁止"写成必贴的负向脊椎（standing negative spine，永远放最后），另一部明令"负向词会生成被禁的东西"（`no subtitles` → 出现字幕），只允许正向锁。这个选择是**整片级**的，不能逐镜即兴，也不能两套并存 [推断：互斥性由两套逻辑推出，语料未直说]。
**失效表现：** 提示里既有大段 `no ...` 又有正向锁，模型两边都收到；写 `soft light` 又写 `no soft light`；负向块变成了违禁词的清单。
**说：** 脊椎式：`居中、对称、水平地平线、塑料皮肤、玩偶眼、音乐、配乐。` / 纯正向式：`画面填满整个画幅，边缘到边缘。` `[译]`

### T-11-03 · 项目技能的第一性产物是「区块顺序」，不是散文
**为什么：** 模型没有记忆，顺序就是它的注意力预算；顺序一旦固定，"几何/身份/光"就永远占据同一个位置，可被逐镜复用、可被逐段修。散文式的项目说明无法被执行。
**失效表现：** 每镜顺序都不同；关键空间关系被埋进风格形容词；改一版要整篇重写。
**说：** `1 场景背景 · 2 参考图 · 3 输出设置 · 4 风格 · 5 表演任务 · 6 空间地理 · 7 开场状态`

### T-11-04 · 风格与光是「逐字块」，写一次，粘到底
**为什么：** 风格和光是这部片唯一不该被"每镜重新决定"的东西；逐字块保证 150 条提示的调色和光向是同一个人写的。
**失效表现：** 越到后面越亮、越干净；反派场景和爱情场景不是一个 grade；正反打里两张脸的光来自相反方向。
**说：** 四槽填满即成型：`[介质] + [影调] + [颗粒] + [光源性质]`；例：`黑白，平灰色调，可见胶片颗粒，硬光；无柔光片、无光泽感。` `[译]`

### T-11-05 · 一元素一 TAG；状态变化 = 新 TAG，绝不覆盖
**为什么：** TAG 是资产的身份证。允许覆盖，就等于允许"湿的版本"顶掉基础脸，之后每一镜都在用被污染的资产。
**失效表现：** `@CHAR_A` 有时是干净脸、有时是冻伤脸、有时是湿的；同一件大衣在不同镜里换了颜色。
**说：** `@CHAR_A_WET` · `@CHAR_B_INJURED`（新状态 = 新名字；基础资产的像素永不重跑）

### T-11-06 · 注册表只能有一处，且必须由资产清单生成
**为什么：** 注册表是资产的索引，不是描述文献。一条记录只要四个字段就能被逐镜绑定：`@TAG`、所属类（char / loc / prop）、一句话文字描述、一张锚图；字段一多，写手就会在提示词里另描述一遍，同一件东西出现两个版本。语料实测：某长片项目的 TAG 名单里有 18 个名字，道具表里又定义 22 个，两处不一致——用得最多的那个名字根本不在 TAG 名单里；33 个已定义名字里只有 5 个真的出现在提示中。
**失效表现：** 提示里出现了注册表里没有的名字；或注册表很豪华但全片只用到 1/6；或同一样东西有两个名字（提示词里叫 `@COAT`、道具表里叫 `@PARKA_B`）；`@char_A_hood` 与 `@char_A_Hood` 被当成两个资产，绑定丢一半；一条记录只有名字没有锚图，模型回到按文字重造脸。
**说：** 每条一行：`@TAG — [class] — [一句话文字描述] — [一张锚图]`；类前缀固定为 `@char_…` / `@loc_…` / `@prop_…`，逐字母照写、大小写有区分；注册表 = 资产清单的投影，只住在一节。

> 编号说明：`T-11-15` 已并入本条（四字段、类前缀、大小写敏感、只住一节），该编号不复用，后续编号不重排。

### T-11-07 · 依赖必须自足：不引用没随包发出的文件
**为什么：** 语料里有技能写着"当前注册表在附带的 `tag-registry.md` 里"，而那个文件**没有随包发出**。项目技能一旦被复制到新片，悬空引用会让 agent 开始编造。
**失效表现：** 技能里出现 `see attached ...`、`per the blocking-map method` 却找不到对应文件；新项目第一镜就开始猜规则。
**说：** 要么自带（self-contained），要么在文件顶部逐条列出**伴生文件的路径与用途**。

### T-11-08 · 规则要写在"失败的过去时"——一条规则 = 一次事故
**为什么：** 好的项目技能不是美学宣言，是伤疤录。某轻量项目技能的规则编号断了 `30`、又多出 `20a`，说明它是**一条一条追加**出来的；每条都对应一次真实报废。
**失效表现：** 规则库抄满了漂亮话，却治不了自己的病；同一条坑反复踩，因为没人把它写成规则。
**说：** `下面每一条规则，都因为少写它而废过一颗镜头。` `[译]`

### T-11-09 · 陷阱条目三段式：症状 → 修法 → 放进哪个区块
**为什么：** 只写"会失败"没有用，agent 知道你怕什么但不知道改哪里；把修法绑定到区块，下一次才能定点修一条提示而不用重写整篇。
**失效表现：** 知道"眼睛会死"却写进 CAMERA 区块；同一条修法每次位置不同。
**说：** `玩偶眼、瞳孔冻住 → 瞳孔有微小漂移、眨眼不均 → 活跃面孔/眼睛 + 绝对禁止` `[译]`

### T-11-10 · 区块清单会落后于实践——给变体留一个正式位置
**为什么：** 语料实测：某长片项目声明的 20 区块顺序只出现在 13/121 条视频提示里，另外 49 条跑的是技能里**没有记录**的多镜变体（multishot）。不记录的变体会被每镜重新发明。
**失效表现：** 实战写法与技能文本两张皮；每次做多镜都从零设计；新人（或新 agent）按技能写反而做不出成片里的效果。
**说：** `MULTISHOT —— 一次 HARD CUT，张力上升：`（把它写进区块表，标明触发条件）

### T-11-11 · 音色锁定，表演重写
**为什么：** 观众靠音色认人；音色逐镜漂移＝换演员。表演段落每场重写，音色段落**一字不改**地粘贴，本场语气叠在上面。
**失效表现：** 同一角色三场戏像三个人；或音色对了但表演被复制，与情境无关。
**说：** 四段式：`VOICE LOCK —— @TAG：[生理条件] [音区与位置] [受力时的表现] [绝对禁止]` `[译]`

### T-11-12 · 一部片需要自己的「场景类型学」
**为什么：** 同一批词在不同场景里必须**相反**：倾斜地平线在"安静温暖"类里是禁忌，在"疯狂"类里是必需；镜头抖动同理。一张全局负向表会自相矛盾。
**失效表现：** 全片一套负向词，导致某类场景永远拍不出该有的失控感；或者导演每次口头纠正同一件事。
**说：** 类型 → 只改 4 个区块：`A 安静/温暖 · B 画外暴力 · C 疯狂 · D 人群 · E 动作隐藏 · F 极远景`

### T-11-13 · 交付自检要可执行，且必须问「模型会不会读成两种意思」
**为什么：** 自洽不等于无歧义；文案前后一致但模型能读成两解的句子，是真的会翻车。自检的第一问是自相矛盾，第二问才是歧义。
**失效表现：** 提示读起来很顺，生成出来的镜面和写的人想的相反（左右反、朝向反、谁在动反）。
**说：** `这段文字自相矛盾吗？模型会不会读成两种意思？` `[译]`

### T-11-14 · 尺寸与结构：15 KB 起步，40 KB 封顶
**为什么：** 语料实测：15 KB（某轻量项目技能）足够承担一部片的全部硬规则；39 KB（某长片项目技能）是上限，再大就必须拆。超过 40 KB 的单一文件，加载时可能被摘要或截断，等于规则失效 [推断]。
**失效表现：** 技能写成一部小说，agent 只读到前 1/3；或为了塞进去开始删规则。
**说：** 主文件放「提示机制 + 规则 + 陷阱」；剧本、语言词典、导演阐述拆成伴生文件。

### T-11-16 · 站位图是项目格式，每一镜都带
**为什么：** 语料里某项目把站位图定成"the project format, always"——它不是可选附件，而是每一镜都要出的**图示件**，由一条字段固定的图提示词生成，不靠手绘。字段固定成六项后，同一套走位在任何一镜都能复现：`COMPLETELY PLAIN WHITE background` / `NO background pattern of any kind` / 只画人物 / 一个角色加他的标志道具＝一个整体、一种颜色、一条连续轮廓线 / 多个人物各用一种哑色并配图例 / 纵深靠连接文字里的世界地标承担。颜色与字母的分工也是格式的一部分：颜色给图上，字母只出现在 `LETTER LEGEND` 的连接文字里。
**失效表现：** 站位图里冒出网格、方格纸或家具，模型把图当场景参考，画面里长出书架；两个人物同色，图例分不清谁是谁；图上写了字母，生成时字母被画进画面；下一镜不重出站位图，走位每镜重新发明。
**说：** `COMPLETELY PLAIN WHITE background, no background pattern of any kind; only the figures are drawn; one character plus his prop shares one continuous interlocking line with no gap.` 并把 `grid`、`graph paper`、`grid lines`、`squared paper` 列进约束清单。

### T-11-17 · 项目块序是这部片的私有顺序，与通用骨架分开存
**为什么：** 工程级骨架是 13 槽（19 槽超集见 `banks/D-block-orders.md`），而项目可以给自己定一套私有块序：块名不同、数量不同、颗粒度不同——把 `SPOKEN LINE`、`LIVING FACE/EYES`、`GEOMETRY ANCHOR` 这类块提成独立块。机制是**覆盖**，不是合并：项目块序整段替换通用骨架，通用骨架只在这一片没有项目技能时兜底；项目块序住在项目技能的 §1.1，通用 13/19 槽一个都不吸收它。这样同一部片的两个写手写出的块序一致，换新片时也不会把上一部片的私有块序带过去。
**失效表现：** 把私有块序硬塞进 13 槽，`SPOKEN LINE` 被并回 `THE SHOT`、`GEOMETRY ANCHOR` 被埋进 `LOCATION MAP`，这两个块就此消失；同一部片两条提示的块序不同；新片直接继承旧片的私有块序。
**说：** 一行指针写进项目技能 §1.1：`本项目私有序 → banks/D-block-orders.md D.10（项目级 20 块块序示例形态）`

### T-11-18 · anti-AI-tell 清单属于项目，不属于平台
**为什么：** 某长片项目的 26 条里，队列道具怎么摆、遮眼道具怎么挡眼、生造语音怎么被引擎糊掉、血怎么渗涌——每一条都长在这部片的题材上；换一部片，一半条目失效，另一半要点缺位。所以它是**项目资产**：每一条对应一次真实踩坑，新坑只追加一条新编号，旧条不重排、不删除；通用库只放跨片共有的失败图谱（见 `banks/E-failure-atlas.md`），项目清单不往通用库里溢。积累的方向也是固定的：从"哪一镜破的、哪个块破的"往回写，而不是从美学原则往下推。
**失效表现：** 把某一部片的 26 条贴进通用模块，其他片被无关规则污染；项目清单退化成"防止 AI 感"这类漂亮话，没有可执行修法；新坑只修了当时那一条提示，没有变成第 27 条。
**说：** 追加格式：`#27 — [症状] → [修法] → [放进哪个块]（首次出现：SC.14 / 第 3 次重生成）`；例：`玻璃眼是瞳孔冻住，不是高光 → 瞳孔漂移、眨眼不匀、眉眼嘴各自独立 → LIVING FACE/EYES`

### T-11-19 · 导演阐述与制作备注也要进项目技能
**为什么：** 前十一节管"每条提示怎么写"，第 10、11 节管"为什么这么写"和"按什么参数执行"——它们是后续所有镜头的**裁量依据**。导演阐述给的是判断标准：视觉语言是功能性的（只用自然光、定焦、固定画幅、手持）、摄影机规则（倾斜地平线只在失控时刻）、剪辑策略（跳切绕开长连续动作）、光与色、声音、母题（一个可复现的身体动作、一种反复出现的材质现象）；制作备注给的是执行参数（资产＝文字＋图、基础肖像此后永不再过模型、时长硬上限、单镜工作顺序）。缺这两节，每个新镜头都要回去问导演一次。
**失效表现：** 新镜头逐条去问"这条能不能倾斜地平线""这条要不要配乐"；母题被拍丢（首尾呼应的那个身体动作对不上）；资产被反复重跑，身份越跑越漂；单镜工作顺序各人一套，交付节奏乱。
**说：** 裁量测试：`这个选择服务于片子的哪一条视觉语言？`（例：倾斜地平线只在失控、疯狂与恐惧的时刻）

## 速查表

**项目的 12 个不变量区块（一部片的项目技能，缺一个就会在成片里露出来）**

| # | 区块 | 放什么 | 为什么存在 |
|---|---|---|---|
| 1 | `name` + `description` | 片名 + 触发词（角色名、地名、语言、道具） | 这是**加载开关**，不是介绍（见下节） |
| 2 | 格式事实 + 一句话论点 | 时长 / 画幅 / fps / 「这片讲的是 X 不是 Y」 | 后面所有取舍都靠它裁决 |
| 3 | 顺序化流程 | 「先写人话头四行 → 再写区块 → 再过陷阱」 | 防止直接开始堆形容词 |
| 4 | 区块顺序（编号、穷举） | 见 `banks/D-block-orders.md` | 注意力预算；可逐镜复用 |
| 5 | 风格 + 光，逐字块 | canon style / canon light | 全片唯一由逐字块固定的东西 |
| 6 | 命名 + 参考绑定 | TAG 注册表、状态后缀、参考图职责 | 身份不漂移 |
| 7 | 可粘贴样板 | 风格块、光块、负向脊椎、镜头锁 | 重复劳动只做一次 |
| 8 | 陷阱表 | 症状 → 修法 → 区块 | 这部片自己的伤疤 |
| 9 | 负向策略 | 脊椎式 **或** 明令禁写负向 | 两套不可共存，必须选一个 |
| 10 | 角色 / 资产档案 | 年龄、体型、服装、手、尺度落差 | 模型只认可见事实 |
| 11 | 音色 / 语言 / 发音锁 | 四段式 + 正字法策略 | 声音是身份的锚 |
| 12 | 交付前自检 | 可勾选清单 + 复检定义 | 最后一道闸 |

**`description` 就是加载开关（骨架版；把 `<...>` 换成这一片的真实内容）**

```yaml
name: "<片名>"
description: "<片名> 的项目技能：<时长 / 画幅 / 介质>。Use whenever writing or revising a video-generation prompt, scene, shot or dialogue line for <片名> — including any request mentioning <角色名>、<地名>、<生造语言>、<标志道具>、<本片特有的场景>。Holds <区块顺序 / 可粘贴样板 / 音色锁 / 陷阱清单 / 表演方法>。"
```

三句式：**是什么**（片名 + 时长 + 画幅）→ **何时触发**（`Use whenever ...` + 专有名词清单：角色名 / 地名 / 语言 / 标志道具 / 本片特有场景）→ **装了什么**（区块顺序 / 样板 / 音色锁 / 陷阱 / 表演法）。通用技能按**任务类型**触发（"whenever the user wants to write an image prompt"），项目技能必须按**专有名词**触发——因为出事的瞬间，正是对话里第一次出现那个角色名的那一刻。真实项目的逐字形态见 04/05 两份来源文件的文件头。

**一页启动清单（给新片现场用）**

| 阶段 | 动作 | 缺了就停 |
|---|---|---|
| 0 收集 | 时长 / 画幅 / fps / 镜头预算；资产清单（名字 + 一张锚图）；风格与光各一段样文；**负向策略**；角色档案（年龄/体型/服装/手/尺度）；音色与正字法；失败日志 | 没有资产清单 → 不写；没定负向策略 → 不写 |
| 1 写 | 12 个区块按上表顺序逐节写，每节 ≤ 1 屏 | 缺节 → 回上一步收集 |
| 2 补 | 场景类型学 / 剧本 / 导演阐述 / 资产管线 / 与人协作的协议（锚点逐字、最小改动、有歧义先问、矛盾必报） | 只在需要时补 |
| 3 测 | 拿 3 条已通过的提示回测：区块顺序对不对、风格块是否一字不差、TAG 是否都在注册表、陷阱是否都带区块、`description` 能否被 ≥3 个专有名词触发、有没有悬空依赖、体积 15–40 KB | 任一项失败 → 改，不发布 |

## 别犯这些错（来自语料实测）

| 缺陷 | 现场证据 | 怎么避免 |
|---|---|---|
| 注册表分裂，最常用的名字不在名单里 | 33 个 TAG；用得最多的那个名字（46 次）只在道具表出现，不在 TAG 名单 | 注册表由资产清单**生成**，一处定义 |
| 悬空依赖 | 规则写"见附带的 `tag-registry.md`"，该文件未随包发出 | 自足，或顶部列伴生文件 |
| 声明的顺序无人遵守 | 私有 20 块块序出现 13/121；49 条多镜变体未被记录 | 给变体正式位置 + 触发条件 |
| 规则两大套并存 | 负向脊椎 vs "负向词会生成被禁物" | 立项时二选一，写进第 9 区块 |
| 规则写得像美学宣言 | 编号断号、追加痕迹明显 | 每条规则都指向一次具体失败 |

## 自检（本模块相关）

- [ ] 项目技能有 `description` 三句式，且含 ≥3 个专有名词触发词
- [ ] 12 个不变量区块全部存在（缺的第 9 项必须显式声明"本片禁写负向"）
- [ ] 区块顺序被编号、被写进一份可引用的表（`banks/D-block-orders.md`；私有序见 D.10）
- [ ] 风格与光是 fenced 逐字块，且全片一字不改
- [ ] 每个 TAG 在注册表里，注册表里每个 TAG 都有用途；一条记录四个字段；状态变化用新 TAG
- [ ] 每条陷阱都能追到"症状 → 修法 → 区块"
- [ ] 无悬空依赖；体积 15–40 KB
- [ ] 场景变体（多镜 / 特殊机位）已有正式条目
- [ ] 全文不含任何具体项目的专名与私有内容（只保留"某长片项目"这类出处写法）
