# 09 · 组装 —— 逐槽拼装与外科式修补

## 这个模块解决什么

前面几个模块解决"写什么"，本模块解决**怎么把它装成一条能发出去的指令**，以及**发出去失败之后怎么改**。

两条真实工程结论决定了本模块的形态：**提示词是一份文件**——只修补失败的那一节，整条重写会丢掉已成立的部分（真实做法留下 137 条版本日志）；**提示词是施工单不是文学**——长片平均 9,700–11,000 字符，但密度 ≠ 长度。

**何时加载：** 任何要真正产出提示词的场合。

---

## 提示

### T-09-01 · 按槽装，不按感觉写
**为什么：** 顺序本身就是信息——模型先读空间，再读人，再读光学、光、时间。乱序会让注意力分配错。
**失效表现：** 提示词读起来合理，生成出来重点全在背景。
**做法：** 按 `banks/D-block-orders.md` 的 19 槽顺序填；没命中的槽整段删掉，不留空标题。

### T-09-02 · 没有负面块 —— 把禁令写成想要的结果
**为什么：** "他不会向后倒"对模型是**邀请它想向后倒**。禁令必须改写成正面结果。**这不是偏好，是统计事实：300 条真实视频提示词里，含独立 `NEGATIVE` 块的有 0 条。**
**失效表现：** 明明写了"不要倒地"，偏倒；明明写了"不要静态"，整个镜头死住。
**对照：**

| ✗ 禁写 | ✓ 改写 |
|---|---|
| 他不会向后倒 | 他向前扑倒，脸朝下 `[译]` |
| 不要平光 | 脸留在阴影里，只有轮廓光与窗户反光把细节带出来 `[译]` |
| 镜头不要动 | 机位固定，只有手持呼吸感：轻微颤动，水平线偏几度 `[译]` |

### T-09-03 · 一个风险，一条本地锁
**为什么：** 远处的大负面块会被忽略；紧挨着风险描述的本地短句才生效。
**失效表现：** 负面清单写了 20 条，画面里出现了清单上第 3 条。
**做法：** 预测本镜最可能坏的一件事，就在那个槽里加一句锁。
**说：** `在接触发生之前，他的双手始终干净、没有血。` `[译]`

### T-09-04 · 参考图：每个标签只出现一次
**为什么：** 重复的标签是**生成拒绝启动**最常见的原因（真实工程记录）。
**失效表现：** 点生成后没反应、报错、或静默失败。
**做法：** 所有 `{{uuid}}` / `@TAG` **只在参考图块出现一次**，正文里用人名/地名引用。

### T-09-05 · 地点参考必须显式禁止"继承构图"
**为什么：** 不写这句，模型会把你地点板的**构图**也照抄过来，而不是只拿它的几何、材质、光。
**失效表现：** 每个镜头都变成同一张地点板的近似复制品。
**说：** `本参考图只控制几何、材质、光与氛围，不控制构图、裁切、机位高度或角度。` `[译]`

### T-09-06 · 参考预算决定你能让几个人同框
**为什么：** 一次生成能吃下的参考是有上限的（实测：9 张图 / 3 段视频 / 3 段音）。这个上限反过来决定一场戏能塞几个主要角色。
**失效表现：** 四人同框时第四个人变得不像。
**做法：** 先数"本镜需要几个身份 + 几个地点/道具"，超预算就拆镜。

### T-09-07 · 标签顺序＝优先级：地点第一
**为什么：** 第一个标签对几何的控制力最强；地点决定所有家具、材质、实际光的位置。
**失效表现：** 空间对了但人物站位飘；或空间每镜都不同。
**做法：** 参考图块的顺序固定：**地点 → 角色 → 道具/车辆 → 风格**。

### T-09-08 · 密度地图：哪些必须写死，哪些一句都别写
**为什么：** 均匀用力等于处处不生效。注意力是有限预算。
**失效表现：** 提示词又长又漂亮，但站位漂、光变平、时间失控——预算全花在通用美感形容词上了。

| 必须写死（高密度） | 尽量少写（低密度） |
|---|---|
| 身份锚点 · 空间走位 · 开场状态 · 视线 · 地标距离 · 手部与道具状态 · 带时间的动作 · 光学 · 光锁 · 物理 · 台词 | 通用美感形容词 · 非关键服装细节 · 背景闲人 · 非在用道具 · 参考图已很明显的东西 |

### T-09-09 · 用可执行的动词和可量测的单位
**为什么：** 模型的词表里"可执行"的词有明确边界；抽象词只会扩大采样范围。
**失效表现：** 写"氛围压抑"，得到一张普通灰调照片。
**词表：**
- **动词：** `站 · 面向 · 看 · 持 · 走 · 抬 · 触 · 倾 · 呼吸 · 滴 · 落 · 滑 · 按 · 转 · 开 · 关 · 进`
- **可量测：** `1 米内 · 画左 · 画右 · 前景 · 中景 · 背景 · 齐腰高 · 齐眼高 · 47° 对角视角 · 0:03 · 一步 · 两个角色 · 三个可见人物`
- **避免：** 复杂嵌套从句；不落成可见行为的心理描写（"他感到被背叛"）。

### T-09-10 · 参数不进正文
**为什么：** 时长/画幅/分辨率是 UI 的事。写进正文会与真实参数打架，还会挤掉内容。
**失效表现：** 正文写 21:9，实际出片 16:9，构图被裁。
**做法：** 正文只留"这一镜内的世界"，参数放设置里；工作稿顶部记一行 `UI settings handled outside prompt`，不发进最终提示词。

### T-09-11 · 风格锚点只给一个，最多一行
**为什么：** 串烧风格（"库布里克 × 王家卫 × 诺兰"）会让模型取平均，得到通用广告感。
**失效表现：** 画面高级但没性格；每镜风格不一样。
**说：** `风格：HIGH NOON（1952，摄影 Floyd Crosby）——平直的沙漠光、无柔光片、无光泽感。` `[译]`

### T-09-12 · 视觉真实感写"过真实"，并点名这一镜的材质
**为什么：** 模型默认会往"干净、平滑、塑料"收敛。你得反向拉。
**失效表现：** 皮肤像蜡、布料像塑料、金属像 CG。
**说：** `过真实：汗珠在太阳穴上穿过灰尘留下痕迹，领口看得到织物纤维，硬光下是真实的皮肤毛孔。任何一个面看起来干净、塑料或像 CGI——就是错的。` `[译]`

### T-09-13 · 单镜默认一条连续长镜，除非命中换轨条件
**为什么：** 一条完成度高的长镜比三条平庸的剪辑更稳（没有接缝、没有轴跳）。
**失效表现：** 观众能看出"这是拼的"。
**换成多镜的条件：** 闪现/蒙太奇/插入镜/正反打/硬切 · 一个机位装不下动作 · 关键细节要特写 · 两个角度的情绪同时要给 · 需要地理+反应+细节 · 预告片式/碎片/梦境/音乐剪辑。**命中一条才换。**

### T-09-14 · 多镜就逐镜定义剪切，否则模型自创蒙太奇
**为什么：** 不定义，模型会自己发明转场（淡入淡出、叠化、乱剪）。**关键事实：真实工程里多镜都是"一次生成、内部硬切"**——300 条任务全部 `multi_shots: false`，靠正文里的 `HARD CUTS at 0.5s / 3.5s / 6.5s` 完成。
**失效表现：** 出现你没要的融合转场；剪辑点全在错的地方。
**做法：** 逐镜给：镜头时长、机位、t=0 谁在哪（开场状态）、走位、动作；然后写清剪切类型与**绝对秒数**。**默认只用** `HARD CUT / SMASH CUT / MATCH CUT / INSERT CUT / REVERSE CUT / WHIP CUT`；**不要** `fade / crossfade / dissolve / transition effect`。
**说：** `四个镜头，HARD CUTS 在 0.5s / 3.5s / 6.5s，全长约 9.5 秒。只用 HARD CUT。不要淡出、不要叠化、不要转场特效。`

### T-09-15 · 修补只改一节，其余逐字不动
**为什么：** 整条重写会丢掉已经成立的部分，把问题打散，下一次不知道是哪个改动起了作用。
**失效表现：** 第 5 版突然变好，但不知道为什么；第 6 版又变差。
**做法：** 工作台里把提示词存成分节的文件，只 patch 失败的节，末尾写一行 `All other sections preserved unchanged.`

### T-09-16 · 工作稿分三段写：意图 / 缺陷 / 补丁
**为什么：** 把"给人看的"和"给模型看的"分开，才不会把内部备注当指令发出去。
**失效表现：** 把"v2 defect：手上有血太早"发进提示词，模型真的生成了血。
**真实结构（可直接照抄）：**

```
WORKFLOW METADATA
User goal: <一句话本镜要什么>
Platform: <模型 + 参考模式>

FAILURE NOTES (internal, not for final prompt)
vN defect N: <症状>. Fix: <确切改法>.

PATCH LOG
<槽名>: <改了什么>
All other sections preserved unchanged.

FINAL PROMPT
<只发这一段>
```

### T-09-17 · 缺陷写成"症状 + 根因 + 确切改法"三件套
**为什么：** "再试一次"不是信息；"手上有血太早 → 血应在接触时转移 → 接触前手完全干净"才是可以复用的知识。
**失效表现：** 同一个错误在三个镜头里各修一遍。
**真实例（`cases/adiliada.md`）：** `v2 defect 1: driver's hand "blood-covered" BEFORE the grip. Fix: clean until contact; blood transfers at the grip.`（缺陷 1：司机的手在握住之前就已"沾满血"；改法：接触前保持干净，血在握住时转移。）

### T-09-18 · 发之前跑一遍审计
**为什么：** 四类错误能机械查出，且每类都直接导致废片。
**失效表现：** 开场状态塌了（t=0 的画面里没有人，或位置不对）；标签失效；地理不清；两句话互相矛盾。
**审计四问：**
1. **开场状态塌了吗？** t=0 该出现的人/物是否都在场在位？
2. **标签还活着吗？** 有没有重复、过期、指向已改的资产？
3. **地理还成立吗？** 谁在哪、朝哪、离什么多远，有没有一句相反？
4. **有互相矛盾的两句吗？** （"她站着"和"她坐着"同时存在）

### T-09-19 · 先过语言关，再过效果关
**为什么：** 模型对否定、嵌套、抽象词的抵抗力极低；这些是**机械可查**的，不需要生成就能改。
**失效表现：** 句子越长，执行越偏。
**快速体检：** 一句话超过两个从句 → 拆。含 `不 / 无 / 没有 / 除了` → 改写正面。含抽象名词（"氛围""情绪""质感"）→ 换成可量测证据。

### T-09-20 · 声音是唯一不能省的块
**为什么：** 在 300 条真实视频提示词里，`AUDIO` 出现率 **87%**，比 `SCENE CONTEXT`（83%）还高——它是语料里最普遍的块。省掉它，模型就自由发挥声场，而声场决定这一镜像不像电影。
**失效表现：** 画面对了但"像素材"；出现莫名其妙的配乐；口型和语气对不上。
**做法：** 每一条都写，最少给三件事：**有什么声 · 有没有配乐 · 人声怎么落在这个空间里**。
**说：** `声音：只用画内声——日光灯的电流声、椅子刮地一下、他近处的呼吸。无配乐。` `[译]`

### T-09-21 · 写一次，逐字粘贴，只改 10–20%
**为什么：** 模型无记忆，同一件事每一镜都要重说；但每次重说都换措辞，就等于每次让模型重新采样——一致性必崩。真实语料里，同一批描述块被复用 **20–162 次**。
**失效表现：** 相邻两镜的同一角色服装/发色/口音微妙地不同；观众说不清哪里怪，但觉得"不是同一部片"。
**做法：** 把以下内容做成**钉板常量**，存进项目文件，逐字复制：
- 角色描述符（资产原文）· 地点描述符 · 音色块 · 风格前缀 · 色法 · 光合同 · 材质/真实感块 · 常用锁句
**只改**：动作、时间轴、机位、视角、这一镜特有的锁。
**说：** `100%匹配参考`

### T-09-22 · 每条提示词都要挂资产图引用
**为什么：** 用户的实际工作流是**多参直接生成**：模型靠你挂上去的资产图（角色板、地点板、道具板）锚定身份与空间。不挂图，模型就自由发挥，每镜一个样——写再长的外貌描写也补不回来。
**失效表现：** 同一角色相邻两镜换了脸、发色；地点每镜不同；提示里写了一整段外观描写，出来还是不像。
**做法：** 参考图块里逐个列出本次生成要用的资产图。四条硬规矩：地点排第一（T-09-07）· 每个参考只出现一次、图片/视频/音频同一套 `{{ref N}}` 连号（T-09-04）· 数量在预算内（9 图 / 3 视频 / 3 音频，T-09-06）· **同一套资产库跨镜复用同一张图，不要每镜重新做图**。

### T-09-23 · 不写"从参考图/参考帧开始"这类话
**为什么：** 这类句子会把参考图的**构图**一起锚定：模型返回的是那张图的近似复制品，而不是新机位；它还会把参考图当成一个固定的起点画面，运镜被锁死。
**失效表现：** 每个镜头都像同一张图的轻微变体；想要推、摇、绕，结果镜头几乎不动。
**做法：** **直接不写。** 不要写成 `do not start from the reference image` 这种否定句——因为在否定句里，模型照样会读到 `reference frame` 这个词，并且更容易把参考图当关键帧处理。删除整句才干净。只保留一句职责声明：
**说：** `本参考图只控制身份与几何，不控制构图、裁切、机位高度或角度。`

### T-09-24 · 整条提示词只用一种语言
**为什么：** 用户用什么语言提要求，提示词就该用什么语言——他要和自己的团队、工作日志、平台界面同一个语言。而混排（一半 `LOCATION MAP` 一半 `场景背景`）会让模型把它当成两种不同的东西，等于给同一件事写了两份互相竞争的说明。
**失效表现：** 提示词里英文块名和中文块名交替出现；或者正文中文、术语全英文，读起来像机翻；或者中文提问却交了英文提示词，用户每次都要自己翻。
**做法：**
1. 先看**提问主体的语言**（不是看术语）→ 定提示词语言。
2. 块标签**全篇一套**：要么全英文（`SCENE CONTEXT`），要么全中文（`场景背景`），要么全【中文】（`【场景背景】`）。
3. `banks/` 里是**双语两栏**：英文请求取英文栏，中文请求取中文栏，中文栏是语料原文，比直译更贴。
4. **台词、生造语、歌词、方言保持原语言**，一个字都不翻——提示词语言与台词语言是两件独立的事。
**说：** `本参考图只控制身份与几何，不控制构图、裁切、机位高度或角度。`
**注：** 英文版里是同一句声明的英文原文，两版各写一句，绝不在同一条提示里同时出现。

## 速查：一次完整的组装

| 步 | 动作 | 产出一行 |
|---|---|---|
| 1 | 从镜卡取 Material + Direction | 情境与目标 |
| 2 | 排标签（地点第一），查重 | 参考图 |
| 3 | 写空间地图（从项目常量粘贴，不改） | 空间地理 |
| 4 | 写开场状态（t=0）的静态文字快照 | 开场状态（OPENING STATE） |
| 5 | 选视角 + 相机距离（`banks/A-optics-bank.md`） | 光学镜头 / 景别 |
| 6 | 写机位运动或"锁定" | 运镜 / 机位 |
| 7 | 数字时间轴 | 动作时间轴 |
| 8 | 表演任务（目标/障碍/战术）+ 眼睛 | 表演 / 活跃面孔 |
| 9 | 物理：重量、接触、惯性、跟随 | 物理 |
| 10 | 光合同（源/方向/明暗侧/曝光优先/禁止失效） | 光照 |
| 11 | 台词原文 + 冻结音色块 | 台词 |
| 12 | 本地锁 1–2 条 | 正向锁定 |
| 13 | 跑审计四问 → 跑 §6 闸门 | 发送 |

**注：开场状态是一个文字块。** 它写的是模型在 t=0 该看到什么——谁在哪、朝哪、手上有什么、什么已经在动；不需要产出任何图。

- [ ] 每个参考只出现一次、`{{ref N}}` 连续（图片/视频/音频同一套编号）、数量在参考预算内（9 图 / 3 视频 / 3 音频）？
- [ ] 资产图引用已挂齐，且跨镜复用同一张资产图，没有每镜重做图？
