# 编辑、局部修复与制作判断

## 选择修改层级

| 用户想改变什么 | 修改与执行 |
| --- | --- |
| 字幕出现时间，台词正文不变 | 按 UID 修改 dialogue_timings；建 finish 计划，仅 CPU 后期 |
| 要说的字、角色、动作、镜长 | 同时修改分镜语义与完整 prompt；建 render 计划 |
| 一镜重新尝试 | shot regenerate；查看实际 affected_uids，不忽略接续及角色参考依赖 |
| 画幅、质量方案 | 局部修改 settings；profile 是项目级，重新查看计划影响 |
| 插镜、排序、角色表 | 修改完整 story，保留旧 UID；新镜分配未占用 UID |

先读最新项目和 revision。CLI 可按 UID 更新；API 用 expected_revision + shots。完整 story 更新保留素材、锁定状态和不相关字段；不要直接改持久化文件。保存后重新读取，确认语义改动未使原 prompt 失效；需要时由当前 AI 补齐。

`dialogue_timings` 使用原镜头时间轴逐句 start/end。改实际台词却只换字幕不能修复旧音频。场景名称与 scene_id 相容，插镜后检查相邻的 use_previous_last_frame；首帧链可能扩展修改范围。

## 素材身份与构图

人物参考图的 character 对应本镜真实出场角色；场景、房间、道具不冒充人物。发现误标，先查看实际图片和元数据，不能仅凭名称下结论。

现有 API 可将原图重新上传为无人物标记的素材，再只替换受影响 UID 的绑定和 prompt；保留人物图身份。上传及采用参考图后重新读取 revision。不能为了让身份校验通过，把房间补进角色表或批量删除所有角色标记。

角色图、普通参考图、首帧、原声是不同约束。空镜不能为了复用成功模板变成人物镜；指定原声不能降级成“相近声音”。模式和素材关系见 [分镜契约](story-and-h3.md)。

## 缓存与试镜

保持 UID、seed_offset 或显式 seed 稳定有助于缓存；它们不保证复用。提示词、素材真实字节、模型、尺寸、采样参数与上一镜实际末帧变化都会影响结果。计划以候选／未知报告缓存，执行时核验；不能根据目录里仍有 MP4 宣称当前内容已生成。

对构图、人物或运动仍不确定的项目，可以先选代表性 UID 创建局部计划。局部执行不会自动拼出全片，范围外镜头保留且待验证。需要完整交付时再计划所有镜头或已就绪原片的后期。

保存已验收镜头样板使用 `POST /api/projects/{pid}/shots/{uid}/template`，请求 name；目标镜头用返回的 prompt_template_id。当前 AI仍需重写动作、台词和时间轴，并核对实际模式／素材；模板不是质量保证。

## 慢任务观察

使用 `sdf job get/watch/events` 精确跟踪，必要时 `factory_api.py diagnose --project PID` 读取阶段和历史采样数据。历史 recorded_seconds_per_frame 不是当前任务耗时；只有同机、同模式、同帧数和参考规模的记录才适合比较。

编码、采样、解码分阶段产出；暂时没有 MP4、日志不增长、低功耗单独都不能证明卡死。需要硬件调查时观察设备 UUID、显存、利用率和温度，失败记为未知。正常计算继续等待；确认错误、硬件异常或超出用户明确时间预算时，按授权停止原任务，再处理原因。

生成完成只证明管线结束。人物、动作、音画切口与台词还需实际查看／听音，见 [交付检查](delivery-checks.md)。
